# rus-transcriber 2.1 — расшифровка русской речи для Claude на Intel Core Ultra

Собрано под ноутбук с **Intel Core Ultra 5 125H** (Meteor Lake: 14 ядер, встроенная видеокарта Arc, NPU Intel AI Boost) и Windows 11.

| Задача | Модель | Где считается |
|---|---|---|
| Распознавание | GigaAM-v3 e2e RNN-T, с пунктуацией | **Видеокарта Arc** через OpenVINO; при сбое процессор |
| Разделение по спикерам | pyannote community-1 | Процессор |
| Эмоции | GigaAM-Emo | Процессор |

Распределение выбрано не случайно:
- **Видеокарта Arc** — лучшее место для распознавания: это самая тяжёлая часть, и на встроенной Intel-графике она идёт в разы быстрее процессора без потери точности.
- **NPU в Meteor Lake** — первое поколение (около 11 TOPS). Для GigaAM на NPU нужны фиксированные размеры входа, первая компиляция занимает минуты, а в известных сборках точность заметно падает. Поэтому NPU — только один из вариантов в тесте, а не основной путь. Если на вашем компьютере он окажется и быстрым, и точным, тест выберет его сам.
- **pyannote и эмоции** — лёгкие задачи, 14 ядер процессора справляются с ними хорошо. Так они не конкурируют с распознаванием за видеокарту.

Какой вариант реально быстрее именно на вашем ноутбуке, определяет **тест скорости** (`bench.py`). Он прогоняет отрывок вашей записи через все варианты, сравнивает точность с эталоном и записывает лучший в `config.json` папки данных.

## Установка (один раз, около 20 минут)

### 1. Драйверы Intel
Через **Intel Driver & Support Assistant** (https://www.intel.com/content/www/us/en/support/detect.html) обновите:
- **Intel Arc / Graphics** — нужен для работы на видеокарте;
- **Intel NPU** — нужен, только если хотите проверить NPU.

### 2. Токен Hugging Face
1. Зарегистрируйтесь на https://huggingface.co.
2. Откройте https://huggingface.co/pyannote/speaker-diarization-community-1 и примите условия использования.
3. Settings → Access Tokens → Create new token, тип **Read**. Скопируйте токен (`hf_...`).

### 3. Python и ffmpeg
Подходит Python **3.11, 3.12 или 3.13**. Если он уже установлен (например, в `C:\Program Files`), ничего делать не нужно: установщик сам его найдёт (через `py`, через PATH или в стандартных папках) и покажет, какой выбрал. Сам Python не меняется: все библиотеки ставятся в отдельное окружение внутри папки программы и не мешают другим вашим проектам.

Если подходящего Python нет:
```powershell
winget install Python.Python.3.12 --scope machine
```
`--scope machine` ставит Python в `C:\Program Files\Python312` (Windows попросит подтверждение администратора). Путь латинский, а файлы Python защищены от изменения обычными программами. Можно ставить рядом с уже имеющимися версиями, они не конфликтуют.

ffmpeg установщик поставит сам, если его нет (`winget install Gyan.FFmpeg`). После этого PowerShell нужно перезапустить.

### 4. Установка
Скачайте программу с GitHub одним из двух способов.

**Через git** (удобнее обновлять):
```powershell
git clone https://github.com/denII-sudo/rus-transcriber.git
cd rus-transcriber
```
**Без git:** на странице https://github.com/denII-sudo/rus-transcriber нажмите **Code → Download ZIP**, распакуйте архив (например, в «Загрузки») и откройте PowerShell в папке `rus-transcriber-main`.

Затем запустите установщик:
```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```
Установщик сам:
- скопирует программу в `%LOCALAPPDATA%\rus-transcriber`. Скачанную папку потом можно удалить, а клон git удобно оставить для обновлений;
- проверит, что в пути нет кириллицы, папка не лежит в OneDrive и на диске хватает места (около 8 ГБ);
- поставит окружение Python и библиотеки; все кэши (pip, модели, компиляция под видеокарту) окажутся внутри папки программы;
- покажет, какие устройства видит OpenVINO. Должно быть `['CPU', 'GPU', 'NPU']`; если `GPU` нет, вернитесь к шагу 1;
- спросит токен Hugging Face (ввод скрыт) и проверит, что он рабочий и что условия pyannote приняты;
- пропишет сервер в настройки Claude Desktop, предварительно сделав резервную копию файла настроек. Версия Claude из Microsoft Store хранит их в `%LOCALAPPDATA%\Claude-Data\claude_<id>\claude_desktop_config.json`, обычная — в `%APPDATA%\Claude\claude_desktop_config.json`; установщик пишет во все найденные места.

После этого полностью закройте Claude Desktop (значок в трее → Quit) и откройте снова.

**Если в имени пользователя Windows есть кириллица** (например, `C:\Users\Иван`), установщик остановится и предложит латинский путь:
```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Target C:\rus-transcriber
```
Так же можно поставить и на другой диск: `-Target D:\rus-transcriber`. Вне профиля установщик закрывает доступ к папке всем, кроме вас, SYSTEM и администраторов. Иначе Windows по умолчанию дала бы другим пользователям право менять файлы программы, которую Claude запускает от вашего имени.

Другие параметры:
- `-Token hf_...` — передать токен сразу, без вопроса;
- `-SkipClaudeConfig` — не трогать настройки Claude.

**Обновление:** в папке клона выполните `git pull` (или скачайте ZIP заново) и снова запустите `install.ps1`. Установщик найдёт прежнюю папку по настройкам Claude, не тронет данные (папка данных ниже) и токен.

**Удаление:**
```powershell
powershell -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\rus-transcriber\install.ps1" -Uninstall
```
Сервер убирается из настроек Claude, а папка программы удаляется вместе с моделями и кэшами (после подтверждения). Записи и расшифровки не затрагиваются.

### 5. Тест скорости (обязательно)
Попросите Claude: «запусти тест скорости на `C:\...\запись.mp3`». Или вручную:
```powershell
cd $env:LOCALAPPDATA\rus-transcriber
$env:HF_TOKEN = "hf_ваш_токен"
.\.venv\Scripts\python.exe bench.py "C:\путь\к\записи.mp3" --seconds 180
```
Тест занимает 5–30 минут: модели скачиваются, а под видеокарту и NPU первый раз компилируются. Отчёт — `<папка данных>\bench\bench_report.md`, лучший вариант — в `config.json` папки данных. Варианты, которые не запустились (например, NPU), просто помечаются как «не работает».

### 6. Проверка расшифровки
«Расшифруй `C:\...\короткая_запись.mp3`, там 2 участника». Рядом с аудио появятся `*.transcript.md` и `*.transcript.json`. В JSON, в блоке `timing`, видно, сколько ушло на каждый этап и на каком устройстве.

## Где что лежит
| Что | Где | Бэкап |
|---|---|---|
| Программа, окружение Python | `<папка>\` и `<папка>\.venv` | Не нужен, восстанавливается установщиком |
| Модели и кэши | `<папка>\cache\` (huggingface, gigaam, torch, openvino, pip) | Не нужен, скачается заново |
| Настройки и результат теста (только отличия от умолчаний) | `<папка данных>\config.json` | Желательно |
| Логи и статусы задач | `<папка данных>\jobs\` (можно чистить) | Не нужен |
| Словарь и голосовой профиль каждой группы | `<папка данных>\groups\<группа>\vocab.json, voices.json` | Желательно; профили — личные данные участников |
| Токен Hugging Face | Настройки Claude: `%LOCALAPPDATA%\Claude-Data\claude_<id>\claude_desktop_config.json` (версия из Store) или `%APPDATA%\Claude\…` | Резервные копии `*.bak-*` лежат рядом и тоже содержат токен |
| Записи и расшифровки | Там, где лежит исходное аудио | Да, это ваши данные |

`<папка>` — это `%LOCALAPPDATA%\rus-transcriber` или путь из `-Target`. Если переменная `HF_HOME` уже задана в системе, модели Hugging Face будут храниться там.

## Как пользоваться
«Расшифруй `C:\Записи\встреча.m4a`, там 3 участника, потом сделай конспект и поправь стиль».

Инструменты, которые вызываю я:
- `start_transcription` — запустить расшифровку в фоне; `whisper="all" | "doubt" | "off"` — третья модель
  на всей записи, только там, где две GigaAM расходятся, или без неё; `whisper_max_repeat` — сколько раз
  подряд Whisper может повторить фразу (по умолчанию 3, «субтитры» на тишине убираются всегда);
- `cancel_job` — отменить задачу (идущую или в очереди); одновременно идут не больше `max_heavy_jobs`
  тяжёлых задач (config.json, по умолчанию 2), остальные ждут в состоянии `queued`; `names="Анна, Вера, Борис, Глеб"` — участники
  известны: имена по голосу ищутся только среди них, голосов не меньше их числа и запас в один посторонний;
  точное число голосов — `num_speakers`;
- `start_benchmark` — тест скорости устройств;
- `transcription_status` — статус задачи. Вызов ждёт до `wait_sec` секунд (по умолчанию и не больше 50)
  и отвечает раньше, как только сменится этап или задача закончится, — частые проверки подряд не нужны.
  Для идущей задачи в ответе: `elapsed_sec` (с начала задачи), `stage_elapsed_sec` (с начала этапа),
  `since_update_sec` (давно ли обновлялся статус), `done` — счётчик внутри этапа (куски распознавания,
  окна голосов по словам), `download` — скачивание модели: файлов, МБ, скорость МБ/с;
- `read_transcript` — текст расшифровки или отчёт теста; по умолчанию только реплики (без сомнительных
  мест, исправлений и журнала правок — до половины объёма), `extra=True` — полностью. Слова нерешённых
  мест взяты в ⟦…⟧ (и в файле .md): распознаны или подписаны неуверенно; проверка цитат отмечает цитаты,
  задевающие такие места (`doubt`), а пометки в ответах и цитатах словами не считаются;
- `get_settings` — текущие настройки;
- `rename_speakers` — подписать или поправить имена («Спикер 4» → «Анна»), можно повторно; подтверждённые имена пополняют голосовые профили;
- `voice_profiles` — какие голосовые профили есть на этом компьютере;
- `review_items` — сомнительные места готовой расшифровки с контекстом;
- `apply_review` — применить решения по ним (журнал правок сохраняется);
- `check_quotes` — проверить цитаты конспекта по стенограмме;
- `list_jobs` — последние задачи.

## Как устроена обработка (pipeline = "words", по умолчанию)

1. **Разделение по голосам** (pyannote) — разметка, кто где говорит, и где говорят одновременно.
2. **Распознавание длинными кусками** 12–20 с по речи, разрезанными в паузах (в сплошной речи — в самом
   тихом месте, с нахлёстом 0,5 с), **независимо от границ голосов**. Из модели берутся слова со временами
   и уверенностью. Раньше звук резался по границам голосов на сотни коротких кусков, и на стыках терялись слова.
3. **Ещё две модели по тем же кускам и голосование «два из трёх»**: CTC-версия GigaAM (со временами слов) и
   Whisper large-v3-turbo (кодировщик — на видеокарте Arc напрямую через OpenVINO, fp16; декодер — процессор,
   int8; при сбое всё на процессоре, int8). Слово RNN-T
   принимается, если с ним согласна хотя бы одна из двух других моделей; если обе другие согласны против
   RNN-T — берётся их вариант; где разошлись все три — метка с вариантами CTC и Whisper.
   Файлы Whisper (≈2,5 ГБ: кодировщик fp16 и int8, декодер int8) скачиваются при первом запуске; первая
   сборка кодировщика под видеокарту занимает минуту-две, дальше берётся из cache\openvino\whisper. Настройки: `asr_third_model` (пусто — без
   Whisper), `asr_third_device` (`GPU`/`CPU`), `asr_third_quant` / `asr_third_quant_cpu`.
4. **Голос для каждого слова**: окна 1,5 с с шагом 0,25 с, сглаживание по пяти окнам, сравнение с голосовыми
   профилями участников (подсказка pyannote даёт поправку 0,05).
5. **Реплики собираются после**: подряд идущие слова одного голоса с паузой меньше 1,5 с. «Угу» поверх чужой
   речи записывается вставкой и реплику не рвёт.
6. **Метки сомнения**: модели распознали по-разному; модель не уверена в слове; голоса близки (20 % слов с
   самым малым отрывом); говорят одновременно; род глагола при «я» не совпадает с полом говорящего.
7. **Разбор Claude** (`review_items` → `apply_review`): по смыслу, только в помеченных местах и только выбором
   из имеющихся вариантов. Правки идут в журнал `edits`, слова модели сохраняются. Нерешённое — в раздел
   «Проверить человеку» с таймкодами и вариантами. Замена текста идёт по словам: меняются только
   отличающиеся слова, время остальных сохраняется (на него опираются ссылки конспекта); слово, уже
   исправленное другой правкой, не перезаписывается — такие случаи в ответе `conflicts`, а места,
   которых больше нет, — в `not_found`.

**Поддакивание и ответ.** Короткое «угу / да / ага» другого человека внутри чужой речи записывается вставкой
(поддержка, реплика не рвётся). Если перед ним вопрос («…правда? — Да»), это ответ со своим смыслом —
отдельная реплика со своим именем; любые другие слова другого голоса тоже идут отдельной репликой.

**Окно 1 с у смены говорящего** (`"word_win_near_change": 1.0` в config.json) — опыт, по умолчанию выключено:
на двух отрезках 06.11 точность не выросла (−0,3 пункта, в пределах шума), а этап голосов шёл вдвое дольше.

**Где лежат результаты.** Рядом с аудио создаётся подпапка `<имя записи>.rus-transcriber`, в ней
`<имя>.transcript.md` и `<имя>.transcript.json` (с меткой `tag` — `<имя>.<tag>.transcript.*`).

**Разбор голосом и карточками (локально и с телефона).** Claude по сомнительным местам формулирует вопрос,
2–4 варианта и рекомендацию и собирает пакет — `build_review_pack(job_id, items)`: в подпапке результатов
появляется `<имя>.review` с клипами мест (3,5 с до места и 1,5 с после, mp3 моно 64 кбит/с), `manifest.json` и `answers.json`.
В карточке — до 400 символов реплик до места и после него и до 700 символов внутри реплики с ⟦местом⟧.
Целиком запись никуда не уходит.
- Сейчас выключены (разбор — карточками в облаке; включить: `"review_local": true` в config.json и
  перезапуск Claude Desktop): `start_review_page`, `start_voice_review`, `speak`, `play_clip`, `listen_reply`.
- `start_review_page` — страница карточек на этом компьютере (http://127.0.0.1:8765/): клип, реплика с
  местом, варианты касанием, озвучка вопроса, ответ голосом с микрофона (распознаёт GigaAM).
- `start_voice_review` — разбор без экрана: голос Windows читает вопрос и варианты, играет клип, после
  сигнала записывает ответ. Понимает «первый/второй…», имя из варианта, «да» (рекомендация), «повтори»,
  «пропусти», «оставь человеку»; остальное сохраняется как свой ответ. Работает без Claude и интернета.
- `speak`, `play_clip`, `listen_reply` — те же действия по одному, если разбор ведёт Claude.
- Облако: Claude публикует ту же страницу карточек с клипами в приватный артефакт; ответы касанием и
  голосовые записи (файлом с диктофона) копятся в его базе. По команде «применяй ответы» Claude переносит
  их сюда — `import_answers` (голос распознаётся здесь же, GigaAM) — и удаляет клипы со страницы.
- `review_pack_cloud` — готовит карточки к публикации в облако (папка `cloud` пакета: страница и manifest с
  последними ответами); Claude публикует их приватной страницей и запоминает её адрес в пакете, чтобы
  обновлять ту же страницу из любой сессии. Карточки с ответом показывают последний записанный ответ
  (откуда и когда); после применения — отметку «применено», клипы со страницы убираются.
  Применённый ответ можно изменить («Изменить ответ») или отменить («Отменить ответ»): при следующем
  `apply_answers` прежняя правка места откатывается к тексту и говорящему модели и применяется новый ответ,
  а отменённое место снова открывается для разбора. Неизменённые ответы повторно не применяются.
- **Свой ответ текстом** — это правка того, что человек услышал в клипе (3,5 с до места и 1,5 с после), а не
  ответ на вопрос. Можно писать по репликам: «Борис: Ой, извините, не заметил даже. Анна: Ничего страшного…».
  Сервер режет ответ по меткам «Имя:», выравнивает его со словами стенограммы в окне клипа (с учётом вариантов
  других моделей) и правит по словам: меняет говорящего (реплика делится), заменяет слова, вставляет
  пропущенную речь, которой нет ни у одной модели. «…» — дальше без изменений. Опечатку («приколько»)
  исправляет по слову модели, смену окончания («заметила → заметил») принимает. Короткий ответ без имён
  («Пришли») — новый текст места. Ответ, покрывший место соседней карточки, закрывает его («решено
  человеком через rN»). Непонятый ответ уходит человеку с его текстом. В журнале правка подписана `human`.
  Порядок старшинства: человек > отпечаток голоса > распознавание > эвристики.
- **Пропущенная речь.** Где pyannote слышит голос дольше 1 с, а слов нет ни у одной модели, появляется
  место «пропущена речь»; ответ на его карточку вставляется в этот промежуток.
- `update_voice_profiles(job_id)` — пересчитать профили голосов по ответам человека: подписанные человеком
  отрезки — с весом ×3 (кроме наложений и отрезков короче 0,8 с), из подтверждённых расшифровок — только
  слова без пометок сомнения; вклад записи заменяется целиком (отменённое уходит само). Поправки «A → B»
  копятся как спутанные пары: на них сервер склоняется к подтверждённому и чаще ставит метку сомнения.
  Если профиль сильно изменился (сходство < 0,8), это видно в `voice_profiles` (warnings).
- `apply_answers` — применяет ответы через `apply_review`. На одно место из двух режимов побеждает более
  поздний ответ, расхождение уходит в «Проверить человеку». Ответы на прежнюю версию вопросов (пакет
  пересобран) не применяются. `review_pack_info` — состояние пакета.

**Проверка цитат конспекта** — `check_quotes(job_id, conspect_text | conspect_path)`: дословны ли «…» и тот ли
говорящий у цитат вида «Имя: «…»». [Поправки в квадратных скобках] — допустимое отличие.

Прежняя обработка по сегментам диаризации осталась: `"pipeline": "segments"` в `config.json`.
Вторая модель задаётся `"asr_second_model"` (по умолчанию `v3_e2e_ctc`; пустая строка — без второго прохода).

## Словарь группы и голосовые профили

**Защита от тёзок** (разные люди с одним именем): расшифровка помнит свою группу (`group`), и в профиль
другой группы она не идёт; вклад записи, непохожий на уже собранный голос этого имени (сходство < 0,70
или ближе к другому участнику), не добавляется, а ждёт решения в карантине (`voice_profiles` →
`quarantine`; `resolve_voice(name, recording, "same" | "different")`); если голоса записи почти не
похожи на группу — в шапке предупреждение «возможно, другая группа»; имена из `names`, которых нет в
словаре, отмечаются — их голоса в профиль не идут, пока их не добавят в `participants`.

**Словарь** — файл `rus-transcriber.vocab.json` (UTF-8, можно править в Блокноте). В нём участники
(имя, пол, роль), имена и названия (`terms`), явные замены (`replace`) и замены с условием (`replace_if`)
для слов, которые бывают и обычными: «весна» → «Весна» только после предлога (обычное слово не трогается),
«Борька» → «Борис» только с заглавной и не перед «богу». Слово из `replace_if` меняется только по условию —
похожесть на термин его не трогает. Подсказки словаря после ответов помечают обычные слова (`common`).
Пример группы — каталог `examples\group.example\` (будет добавлен).

Где сервер ищет словарь, по порядку:
1. путь, переданный явно (`vocab_path`);
2. папка записи и до двух папок выше. Удобно держать записи группы в одной папке и положить словарь туда:
   он ездит вместе с записями, его можно переслать отдельно, а у разных групп будут разные словари;
3. `<папка данных>\groups\<группа>\vocab.json` — словарь группы. Группа: параметр `group` в `start_transcription` (тогда её словарь сильнее словаря рядом с записью) → `default_group` в `config.json` → единственная группа в папке данных. Групп несколько и ни одна не выбрана — расшифровка не стартует с понятной ошибкой.

Что делает словарь:
- явные замены целого слова или фразы: «Борька» → «Борис», «Лисицина» → «Лисицын»;
- близкие по звучанию искажения имён и названий из `terms` («Гудзо» → «Гудзон», «вереском» → «Вереском»).
  Падежные формы («Никитой», «Эврики») не трогаются, обычные слова со строчной буквы — только при почти
  полном совпадении;
- пол участников нужен для проверки рода глаголов («я поняла» у мальчика).
Исходный текст реплики сохраняется в `.json` (поле `text_raw`), список замен — в конце `.md`.

**Голосовые профили** — `groups\<group>\voices.json` в папке данных, только на этом компьютере. Это отпечатки голосов
участников (биометрия), в словарь они не входят и вместе с ним не передаются. Профиль пополняется сам: перед
каждой расшифровкой сервер берёт из папки записи расшифровки с подтверждёнными именами (подписанные через
`rename_speakers`) и ещё не учтённые. Вклад каждой записи хранится отдельно; при расшифровке записи её
собственная прошлая расшифровка не используется, чтобы профиль не подсказывал сам себе.

Что делается по голосу:
1. **имена**: кластеры pyannote сопоставляются с профилями (порог сходства 0,40), «Спикер 3» сразу становится
   «Борис». Такие имена помечены как автоматические, пока их не подтвердят через `rename_speakers`;
2. **чужой голос внутри реплики**: длинные реплики (от 3 с) проверяются окнами по 1,5 с; если 2+ окна подряд
   явно ближе к другому участнику, реплика режется по ближайшей паузе и куски распознаются отдельно;
3. **каждая реплика от 1 с** сверяется с профилями: она переходит к другому участнику, если её голос ближе
   к его профилю, с поправкой 0,05 в пользу исходного кластера. Так находятся и участники, которых pyannote
   слил с другим голосом (у детей голоса близки);
4. **род глагола** при «я» против пола говорящего: реплика переходит к участнику нужного пола, только если
   голос не возражает. Иначе — в раздел «Проверить» (обычно это ошибка окончания при распознавании или
   пересказ чужих слов).

`voice_profiles` показывает, какие профили есть и из каких записей собраны. Удалить профиль — удалить его файл (или каталог группы целиком).
Отключить проверку голосов: `voices=false` в `start_transcription` или `"voices": false` в `config.json`.

## Проверка качества и тесты

- `python -m unittest discover -s tests` — быстрые тесты (без звука и моделей, секунды): голосование «два из трёх»,
  нарезка кусков, фильтры Whisper, словарь и замены с условиями, род глагола, разбор ответов человека, метки ⟦…⟧,
  проверка цитат, настройки и выбор группы, перенос данных, оценка качества. Данные в тестах выдуманные.
- `tools/eval_quality.py` — оценка по эталону на ваших записях: WER и точность подписи голосов с порогами.
  `init имя запись.mp3 эталон.txt --names "…"` один раз расшифровывает запись и записывает базовые значения и пороги
  (WER базы + 1 п.п., голоса базы − 1,5 п.п.); `run` повторяет прогон после любой правки и сообщает о нарушениях и
  росте времени больше чем на 30 %; `score расшифровка.json эталон.txt` оценивает готовую расшифровку.
  Случаи и история лежат в папке данных (`eval\`), не в репозитории. Эталон — строки `[мм:сс] Имя: текст`.
  Запускать питоном из `.venv` программы, с `HF_TOKEN` в окружении.

## Как устроена программа: ядро и слои управления

- **Ядро — `core.py`.** Запуск, статус, отмена и список задач, чтение стенограмм, настройки, группы и профили,
  выгрузка/загрузка/удаление данных. В нём нет ничего про MCP, Claude или другой клиент (проверяется тестом), ошибки —
  `CoreError` с понятным текстом. Тяжёлая работа идёт в отдельных процессах (`worker.py` и др.), ядро только их
  запускает и следит.
- **Слой MCP — `server.py`.** Тонкая обёртка: описывает инструменты для клиента и вызывает ядро.
- **Слой командной строки — `rt.py`.** Те же возможности без всякого клиента (`python rt.py --help`):
  `transcribe`, `status --wait`, `jobs`, `read`, `review`, `cancel`, `settings`, `profiles`, `export`, `import`,
  `delete-group`, `cleanup`, `migrate`, `audit`, `approve`. Вывод — JSON, коды возврата 0 / 1 (ошибка) /
  2 (отказ или нет терминала для подтверждения).
- Разбор сомнительных мест карточками, конспект и голосовой разбор пока живут в `server.py` (они опираются на клиента
  с моделью); из командной строки доступны `review` (список мест) и всё, что выше.

### Подтверждение опасных действий человеком

Выгрузка архива с голосами (`export_group`), загрузка (`import_group` с `apply=true`), удаление группы
(`delete_group`), очистка журналов (`cleanup_jobs` с `apply=true`) и перенос данных (`migrate_data` с
`dry_run=false`) не выполняются по одному слову модели: параметры вроде `confirm` или `apply` модель подставляет сама.
Согласие даёт человек каналом, к которому у модели нет доступа:

1. **Окно на экране (Windows).** Текст окна пишет программа: что именно будет сделано (группа, число файлов, режим,
   папка). Кнопка по умолчанию «Нет»; закрытие окна или тишина дольше `confirm_timeout_sec` (180 с) — отказ.
2. **Терминал**, если окна нет (другая система, нет экрана): сервер оставляет запрос, человек выполняет
   `python rt.py approve`, читает запрос и отвечает на клавиатуре (только в настоящем терминале). После этого тот же
   вызов, повторённый с теми же параметрами, выполняется один раз (разрешение живёт 5 минут и привязано к параметрам).

Отчёты без изменений (`import_group` без `apply`, `cleanup_jobs`/`migrate_data` в режиме подсчёта) подтверждения не
требуют. Все решения пишутся в `confirmations.log` в папке данных. Настройка — `confirm_mode` в `config.json`: `auto`
(по умолчанию), `dialog`, `terminal`, `off` (без подтверждения — для автоматических прогонов, на живой машине не
включать; неверное значение читается как `auto`). В `rt.py` те же действия спрашивают согласие в терминале, а удаление
группы — ввод её имени.

Границы: подтверждение защищает от действий модели через MCP. Тот, у кого есть оболочка на этом компьютере под вашей
учётной записью, и так может удалить файлы напрямую; окно подтверждения проверено только в Windows.

## Подключение к другим MCP-клиентам

Сервер — обычная программа с протоколом MCP по стандартному вводу-выводу, привязки к Claude в нём нет, но проверен он
только в Claude Desktop. Установщик прописывает сервер только в настройки Claude Desktop; в другом клиенте добавьте
запись вручную (формат у клиентов немного различается, суть одна):

```json
{
  "mcpServers": {
    "rus-transcriber": {
      "command": "C:\\Users\\<вы>\\AppData\\Local\\rus-transcriber\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\<вы>\\AppData\\Local\\rus-transcriber\\server.py"],
      "env": {"HF_TOKEN": "hf_…", "RUS_TRANSCRIBER_DATA": "C:\\Users\\<вы>\\AppData\\Roaming\\rus-transcriber-data"}
    }
  }
}
```

- **Рабочий процесс** сервер сообщает сам: поле `instructions` при подключении и три промпта — `transcribe_recording`,
  `review_doubts`, `make_conspect`. Клиент, который их показывает, подскажет порядок работы.
- **Ожидание.** `transcription_status(job_id, wait_sec=50)` держит вызов до 50 секунд. Если у клиента лимит на вызов
  короче, вызовы будут обрываться: уменьшите `wait_sec` (допустимо 0–50).
- **Нужна языковая модель.** Конспект, выбор между вариантами и разбор свободных ответов делает клиент с моделью;
  без неё доступны запуск, расшифровка, профили голосов и служебные инструменты.
- **Карточки разбора** показываются как страница в клиенте, который умеет публиковать веб-страницы (артефакты).
  Иначе включите локальный разбор: `"review_local": true` в `config.json` (страница на localhost, голосовой разбор).
- Расшифровку можно запустить и без клиента: `python worker.py запись.mp3 --names "Анна, Борис" --group example`
  (статусы и отмена — `python rt.py status|cancel`).

## Папка данных

Личные данные лежат отдельно от программы: `RUS_TRANSCRIBER_DATA`, иначе `C:\Users\<вы>\AppData\Roaming\rus-transcriber-data`
(внутри папки программы быть не может; путь строится от домашней папки, потому что `%APPDATA%` и `%LOCALAPPDATA%` в Claude из
Microsoft Store подменяются скрытой папкой внутри пакета Claude, которая пропадает вместе с ним; проверьте, что папка видна
в Проводнике по `%APPDATA%\rus-transcriber-data`, иначе задайте `RUS_TRANSCRIBER_DATA`). Данные из прежнего места переносятся сами. В ней `config.json` (только отличия от умолчаний в коде), `groups\<группа>\`
(`vocab.json`, `voices.json`), `jobs\`, `bench\`, `migration.log`. Папку программы можно удалить или
переустановить — данные останутся. `get_settings` показывает `data_dir`.

**Перенос со старой раскладки** (`profiles\`, `config.json`, `jobs\`, `bench_*` в папке программы) выполняется один раз
при первом запуске сервера (или `python migrate.py [--dry-run]`): копирование, проверка контрольных сумм, затем прежние
файлы уходят в `<папка данных>\_backup-<дата>\` (не удаляются; удалите сами, когда убедитесь, что всё работает).
Идёт расшифровка — перенос откладывается. Итог в `migration.log`.

### Перенос и обслуживание данных

- `export_group(group, dest_dir, with_jobs)` — zip с группой (словарь + голосовой профиль) и `manifest.json`
  (версия схемы, дата, группы, контрольные суммы). Абсолютные пути заменены именами файлов, карантин голосов
  не переносится. В архиве биометрия — храните как личные данные; в разговор архив не передаётся.
- `import_group(zip_path, mode, apply)` — `merge`: добавляются недостающие участники и словарь, при споре остаётся
  профиль с большим числом секунд речи (в отчёте `conflicts`); `replace`: группа заменяется, прежняя уходит в
  `_backup-import-<дата>`. Без `apply=true` только отчёт. Проверяются версия схемы, имена файлов, контрольные суммы.
  Записи, уже учтённые в профиле, после импорта на другом компьютере могут быть учтены повторно, если их
  расшифровки переучивать; для переноса достаточно импорта.
- `delete_group(group, confirm)` — `confirm` должен совпасть с именем группы; папка уходит в `_deleted` (можно вернуть),
  `permanent=true` — навсегда.
- `cleanup_jobs(days, apply)` — убирает статусы и логи задач старше N дней.
- То же из командной строки: `python rt.py export|import|delete-group|cleanup|audit` (`audit` ищет абсолютные пути);
  опасные действия спрашивают согласие в терминале (см. «Подтверждение опасных действий человеком»).
- Установщик: `-DataDir <путь>` задаёт папку данных (записывается в настройки сервера как `RUS_TRANSCRIBER_DATA`),
  повторная установка данные не трогает; `-Uninstall` отдельно спрашивает про программу (по умолчанию да) и про
  данные (по умолчанию нет). Пример словаря — `examples\group.example\`.
- Проверки: `python -m unittest discover -s tests` (на выдуманной группе).
  Тесты работают только во временной папке данных (каждый модуль задаёт её до первого импорта; `test_data_safety.py`
  проверяет это и то, что перенос из «прежних мест» не срабатывает при явно заданной папке данных).

## Настройки (`config.json`)
| Поле | Значения |
|---|---|
| `asr_backend` | `auto` (OpenVINO → DirectML → ONNX на CPU → PyTorch), `openvino`, `dml`, `onnx-cpu`, `torch` |
| `asr_device` | для OpenVINO: `GPU`, `NPU`, `CPU` |
| `pad_to_seconds` | `0`, `5` или `22`: дополнять куски тишиной до кратной длины, чтобы видеокарта или NPU не перекомпилировали модель под каждый размер |
| `asr_batch` | сколько реплик распознавать за раз (`1` — поштучно); подбирает тест скорости |
| `asr_model` | `v3_e2e_rnnt` (точнее) или `v3_e2e_ctc` (быстрее) |
| `emotions` | `true` / `false` |
| `diar_embeddings` | `auto` (OpenVINO на `diar_ov_device` → быстрый CPU → оригинал pyannote), `openvino`, `cpu`, `original` |
| `diar_ov_device` | `GPU` (Arc) или `NPU` — где считать отпечатки голосов |
| `diar_chunks_per_batch` | сколько 10-секундных кусков считать за раз (по умолчанию 16) |
| `diar_segmentation_batch` | размер пакета поиска речи; `0` — как в модели (32) |
| `torch_threads` | число потоков процессора для PyTorch; `0` — по умолчанию |
| `confirm_mode` | `auto` (окно, иначе терминал), `dialog`, `terminal`, `off` — подтверждение опасных действий человеком |
| `confirm_timeout_sec` | сколько секунд ждать ответа в окне подтверждения (по умолчанию 180); нет ответа — отказ |

Если выбранное устройство не запустилось, обработчик сам переходит к следующему варианту и пишет причину в `asr_fallbacks` в статусе задачи.

## Что ожидать
- Распознавание на Arc должно стать в разы быстрее, чем в первой версии на процессоре. Узким местом, скорее всего, станет разделение по спикерам. Точные цифры покажет тест.
- Если указать число участников, разделение по голосам заметно точнее.
- Эмоции: четыре класса (позитив, раздражение, грусть, нейтрально). В тексте помечаются только уверенные ненейтральные реплики.
- Если что-то сломалось, причина будет в `jobs\<id>.log`.
