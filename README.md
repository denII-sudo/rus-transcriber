# rus-transcriber — расшифровка русской речи для ИИ-агента (например, Claude Desktop)

Программа работает локально на обычном компьютере с Windows. Всё распознавание по умолчанию
считается на **процессоре**; видеокарта и NPU — необязательное ускорение, которое включает
только тест скорости после сверки текста с эталоном.

Для чего программа и какие документы считаются её результатом —
[`docs/product-goal-and-documents.md`](docs/product-goal-and-documents.md).

**Что нужно:**
- Windows 11, 64 бита (Windows 10 не проверялась); компьютеры на ARM не поддерживаются;
- процессор x86-64 (Intel или AMD) с поддержкой **AVX2** — практически все процессоры примерно с 2015 года:
  Intel Core 4-го поколения (Haswell) и новее, AMD Ryzen. Сама программа AVX2 не проверяет; это
  рекомендуемый минимум, на котором её зависимости работают и были проверены (подробнее — ниже);
- оперативная память: проверено на 16 ГБ; около 8 ГБ на диске.

| Задача | Модель | Где считается |
|---|---|---|
| Распознавание | GigaAM-v3 e2e RNN-T, с пунктуацией | **Процессор**; видеокарта — по желанию, если тест скорости подтвердит точность |
| Разделение по спикерам | pyannote community-1 | Процессор |
| Эмоции | GigaAM-Emo | Процессор |

**Ускорение по платформам:**
- **Любой процессор с AVX2** — основной и эталонный вариант: `onnx-cpu`, `torch-cpu`, `whisper-ct2`.
- **Intel со встроенной видеокартой Arc** (например, Core Ultra) — через OpenVINO (`ov-gpu*`, `whisper-gpu`).
  На проверенной машине Arc считала примерно вдвое быстрее процессора (около 57× против 28× реального времени),
  но иногда ошибалась в начале записи или возвращала пустой кусок, поэтому тест скорости оставил процессор.
  Вручную: `"asr_backend": "openvino"`, `"asr_device": "GPU"`; при сбое программа сама откатится на процессор.
- **NPU Intel** — только на поколениях с FP32 и только при совпадении текста с эталоном. На Meteor Lake
  (первое поколение, без FP32) для GigaAM он не тестируется: компилятор NPU неверно считает относительное
  позиционное кодирование во внимании, расхождение с процессором около 93% (проверено на OpenVINO 2025.4.1
  и 2026.4.1).
- **AMD Radeon и другие видеокарты** — варианты OpenVINO GPU/NPU здесь не работают (это плагины Intel);
  возможен DirectML (`dml-gpu`, `whisper-dml`), но только после замены пакета `onnxruntime-openvino` на
  `onnxruntime-directml` — их нельзя поставить одновременно. `dml-gpu` и `ctc-dml` в обычный тест скорости
  не входят (запуск — `bench.py --only dml-gpu,ctc-dml`); `whisper-dml` входит, но без DirectML пропускается.

Разделение по спикерам и эмоции всегда идут на процессоре, чтобы не конкурировать с распознаванием за
видеокарту. Модель эмоций не маленькая: файл её весов — около 0,5 ГБ, на проверенной установке он не
меньше файла весов основной модели GigaAM. Время этапа эмоций записывается
в `timing.emotions_sec` расшифровки.

**Проверенные машины:** Intel Core Ultra 5 125H (Meteor Lake, Arc, NPU) и AMD Ryzen 5 6600H (Zen 3+, AVX2
без AVX-512, Radeon), обе с Windows 11. Ориентиры скорости для AMD —
[`docs/research/amd-bench-baseline-2026-11.md`](docs/research/amd-bench-baseline-2026-11.md).

**Почему AVX2.** Это не формальный минимум каждой библиотеки, а надёжная общая база. У CTranslate2
(faster-whisper) заявленный минимум — SSE 4.1, нужный набор инструкций он выбирает сам. OpenVINO
оптимизирован под AVX2 и AVX-512. Для PyTorch и ONNX Runtime официального минимума для готовых пакетов
не нашлось; на процессорах без AVX/AVX2 сообщалось о сбоях. Процессоры без AVX2 не проверялись.

Какой вариант реально быстрее именно на вашем компьютере, определяет **тест скорости** (`bench.py`). Он идёт по порядку **процессор → видеокарта → NPU** (NPU только если он есть и поддерживает FP32), сравнивает точность с эталоном и записывает выбор в `config.json` этой машины. Порог совпадения задаётся переменной `bench_min_similarity` (по умолчанию 97%); для работы, где точность важнее скорости, его поднимают до 99%. Основной проход RNN-T, второй проход CTC и Whisper проверяются отдельно, поэтому у них могут получиться разные устройства.

### Диагностика фрагментов распознавания

В основном режиме `pipeline="words"` JSON стенограммы хранит `quality.asr_diagnostics`: для каждого
прохода и фрагмента — времена, длины и результаты попыток. Текст речи и звук в эти записи не
копируются. `empty_unknown` означает пустой результат с неизвестной причиной, а не доказанную тишину.
При технической ошибке или неверном формате ответа фрагмент повторяется один раз на том же бэкенде;
успешный пустой ответ повторно не запускается. Если повтор не помог, `quality.asr_incomplete_chunks`
и статус задачи показывают число оставшихся ошибок. Статус `done` при этом не гарантирует полноту
расшифровки. Автоматического переключения устройства для этих повторов нет. Повтор считается по
одному фрагменту: текст и времена совпадают с обычным прогоном, но уверенность слова может
пересчитаться, поэтому метки сомнения у восстановленного фрагмента иногда меняются.

Диагностика добавлена только для пословного конвейера; старый `pipeline="segments"` и отдельный
тест скорости используют прежний порядок обработки. Наличие провайдера или имя бэкенда не доказывает,
что все части модели вычислялись на одном и том же устройстве.

## Установка (один раз, около 20 минут)

### 1. Драйверы (только для Intel)
На компьютере с AMD этот шаг пропустите. Через **Intel Driver & Support Assistant** (https://www.intel.com/content/www/us/en/support/detect.html) обновите:
- **Intel Arc / Graphics** — нужен для работы на видеокарте;
- **Intel NPU** — для GigaAM не нужен (см. пояснение выше); можно не обновлять.

### 2. Токен Hugging Face
1. Зарегистрируйтесь на https://huggingface.co.
2. Откройте https://huggingface.co/pyannote/speaker-diarization-community-1 и примите условия использования.
3. Settings → Access Tokens → Create new token, тип **Read**. Скопируйте токен (`hf_...`).

### 3. Python и ffmpeg
Подходит Python **3.11, 3.12 или 3.13**. Если он уже установлен (например, в `C:\Program Files`), ничего делать не нужно: установщик сам его найдёт (через `py`, через PATH или в стандартных папках) и покажет, какой выбрал. Сам Python не меняется: все библиотеки ставятся в отдельное окружение внутри папки программы и не мешают другим вашим проектам.

Если подходящего Python нет:
```powershell
winget install Python.Python.3.12 --scope machine
```
`--scope machine` ставит Python в `C:\Program Files\Python312` (Windows попросит подтверждение администратора). Путь латинский, а файлы Python защищены от изменения обычными программами. Можно ставить рядом с уже имеющимися версиями, они не конфликтуют.

ffmpeg установщик поставит сам, если его нет (`winget install Gyan.FFmpeg`), и сразу подхватит его в текущем окне. Если Windows всё же попросит перезапустить PowerShell, после перезапуска вернитесь в папку с `install.ps1` — установщик напечатает готовую команду с полным путём.

### 4. Установка
Скачайте программу с GitHub одним из двух способов.

**Через git** (удобнее обновлять):
```powershell
git clone https://github.com/denII-sudo/rus-transcriber.git
cd rus-transcriber
```
**Без git:** на странице https://github.com/denII-sudo/rus-transcriber нажмите **Code → Download ZIP**, распакуйте архив (например, в «Загрузки») и откройте PowerShell в папке `rus-transcriber-main`.

Затем запустите установщик:
```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```
Если установщик попросит перезапустить PowerShell, новое окно откроется в другой папке: вернитесь в `rus-transcriber-main` командой `cd` (или скопируйте готовую команду с полным путём, которую напечатает установщик). `.\install.ps1` ищется в текущей папке, поэтому из другой папки он не запустится.
Установщик сам:
- скопирует программу в `%LOCALAPPDATA%\rus-transcriber`. Скачанную папку потом можно удалить, а клон git удобно оставить для обновлений;
- проверит, что в пути нет кириллицы, папка не лежит в OneDrive и на диске хватает места (около 8 ГБ);
- поставит окружение Python и библиотеки; все кэши (pip, модели, компиляция под видеокарту) окажутся внутри папки программы;
- покажет, какие устройства видит OpenVINO. Нужен хотя бы `CPU`; `GPU` (Arc) желателен для ускорения, `NPU` не обязателен — на Meteor Lake он для GigaAM не используется;
- подготовит базу записей `<папка данных>\state.sqlite3` (`rt.py db-init`): если её нет — создаст пустую, если есть — только проверит, что она открывается, и не изменит; в обоих случаях выберет хранение записей в базе. Если программа уже была переключена на базу, а базы нет, пустую не создаст: попросит восстановить базу из резерва (`rt.py db-restore`). Если база не открывается, её не удалось создать или `config.json` не читается, ничего не чинит и завершается с кодом 2; посмотреть, что сделал бы шаг, не меняя базу и настройки, — `rt.py db-init --check`;
- спросит токен Hugging Face (ввод скрыт) и проверит, что он рабочий и что условия pyannote приняты;
- пропишет сервер в настройки приложения ИИ-агента (например, Claude Desktop), предварительно сделав резервную копию файла настроек. Claude Desktop из Microsoft Store хранит их в `%LOCALAPPDATA%\Claude-Data\claude_<id>\claude_desktop_config.json`, обычная установка — в `%APPDATA%\Claude\claude_desktop_config.json`; установщик пишет во все найденные места.

Если `pip` останавливается на `CERTIFICATE_VERIFY_FAILED` или `certificate has expired`, установщик выведет ссылку на [`docs/model-download-certificate.md`](docs/model-download-certificate.md), раздел 6. Ручные команды из `download_hint.py` предназначены только для весов GigaAM; они не устанавливают PyTorch или пакеты из PyPI.

После этого полностью закройте приложение ИИ-агента (например, Claude Desktop: значок в трее → Quit) и откройте снова.

**Если в имени пользователя Windows есть кириллица** (например, `C:\Users\Иван`), установщик остановится и предложит латинский путь:
```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Target C:\rus-transcriber
```
Так же можно поставить и на другой диск: `-Target D:\rus-transcriber`. Вне профиля установщик закрывает доступ к папке всем, кроме вас, SYSTEM и администраторов. Иначе Windows по умолчанию дала бы другим пользователям право менять файлы программы, которую ИИ-агент запускает от вашего имени.

Другие параметры:
- `-Token hf_...` — передать токен сразу, без вопроса;
- `-KeepSavedToken` — не спрашивать токен и оставить сохранённый в настройках приложения ИИ-агента;
- `-SkipClaudeConfig` — не трогать настройки приложения ИИ-агента;
- `-AllowRunningServer` — обновлять, пока работает сервер программы (обработки записей при этом быть не должно; после обновления перезапустите приложение ИИ-агента);
- `-AllowUnreviewedSource` — ставить код, которого нет в `main` (и нет тега) или с незакоммиченными изменениями в клоне;
- `-DataDir <путь>` — папка данных (по умолчанию `%APPDATA%\rus-transcriber-data`); записывается в настройки
  приложения ИИ-агента как `RUS_TRANSCRIBER_DATA`, если их запись не отключена `-SkipClaudeConfig`;
- `-SkipSelfCheck` — не запускать самопроверку в конце;
- `-AcceptanceCopyOnly` — только для разработчиков: копирование комплекта в изолированную тестовую папку
  (нужны `-Target`, `-DataDir`, `-SkipClaudeConfig`; работает только в папке с меткой тестового прогона).

**Обновление:** в папке клона выполните `git pull` (или скачайте ZIP заново), перейдите в неё и снова запустите `install.ps1` из этой папки. Без `-Target` установщик найдёт прежние папки программы и данных по настройкам приложения ИИ-агента и не тронет данные (папка данных ниже) и токен. Если вы задаёте `-Target`, а папка данных не стандартная, укажите и `-DataDir`: иначе установщик возьмёт папку по умолчанию и запишет её в настройки приложения. Перед изменениями он:
- покажет версию в установке и ставящуюся версию, а для клона Git — ветку и коммит; если коммита нет в `origin/main` (по последнему `git fetch`) и на нём нет тега или в клоне есть незакоммиченные изменения, спросит, ставить ли такой код (без терминала — откажет без `-AllowUnreviewedSource`);
- проверит, что программа не занята: если идёт обработка записи или тест скорости, обновление не начнётся; если работает только сервер (его запускает приложение ИИ-агента), попросит закрыть приложение;
- сохранит список пакетов окружения в `cache\pip-freeze` (10 последних) и после установки библиотек покажет, что изменилось, с командой отката.

Уже установленные GigaAM и `onnxruntime-openvino` нужной версии он не переустанавливает. Токен спросит снова: достаточно нажать Enter — сохранённый токен останется (или запустите с `-KeepSavedToken`; без терминала вопрос не задаётся). Если в папках `tests`, `tools` или `examples` установленной копии есть файлы, которых нет в комплекте программы, установщик покажет их и спросит, удалять ли (Enter — удалить, `n` — оставить). В конце он запускает самопроверку (`selfcheck.py`: тесты в отдельной временной папке, проверка файлов, морфология) и печатает итог; если она нашла проблемы или не дала результата, установщик завершается с кодом 2. Повторить её можно просьбой к ИИ-агенту «проверь установку» (`self_check`) или командой `.\.venv\Scripts\python.exe selfcheck.py` в папке программы.

**Удаление:**
```powershell
powershell -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\rus-transcriber\install.ps1" -Uninstall
```
Перед удалением полностью закройте приложение ИИ-агента (например, Claude Desktop: значок в трее → Quit): пока программа работает, удаление не начнётся. Установщик сначала покажет, что будет удалено, и спросит по очереди:
1. удалить программу (код, окружение Python, модели, кэши) и убрать её из настроек приложения ИИ-агента — по Enter **да**;
2. удалить служебные данные программы в папке данных (голосовые профили и словари групп, настройки, журналы задач) — по Enter **нет**;
3. удалить резервные копии настроек приложения ИИ-агента (`*.bak-*`), в которых есть токен Hugging Face, — по Enter **нет**.

**Никогда не удаляются:** ваши аудиозаписи, стенограммы и конспекты — где бы они ни лежали, в том числе внутри папок программы и данных; база `state.sqlite3` (в ней стенограммы и конспекты), резервные копии и архивы выгрузки; папки `backup*` и `_backup*` внутри папки программы; Python и ffmpeg. В конце установщик перечислит, что удалено, какие ваши файлы сохранены и что удалить не удалось. Скрипт можно запускать прямо из папки программы: он продолжит работу из временной копии.

Без вопросов (например, когда удаление выполняет ИИ-агент): `-Yes` и `-RemoveData` или `-KeepData`, по желанию `-RemoveConfigBackups`. Без этих ключей при неинтерактивном запуске установщик ничего не меняет.

Записей в реестре Windows установщик не создаёт; Python и ffmpeg, поставленные через winget, — отдельные программы, их удаляют в «Параметры → Приложения».

### 5. Тест скорости (обязательно)
Попросите ИИ-агента (например, Claude Desktop): «запусти тест скорости на `C:\...\запись.mp3`». Или вручную:
```powershell
cd $env:LOCALAPPDATA\rus-transcriber
$env:HF_TOKEN = "hf_ваш_токен"
.\.venv\Scripts\python.exe bench.py "C:\путь\к\записи.mp3" --seconds 180
```
Тест занимает 5–30 минут: модели скачиваются, а под видеокарту первый раз компилируются. Отчёт — `<папка данных>\bench\bench_report.md`, лучший вариант — в `config.json` папки данных. Отчёт хранит только последний запуск; каждый запуск дополнительно оставляет свой файл в `<папка данных>\bench\runs\` — с условиями (питание, загрузка, версии программы и пакетов, драйверы) и контрольной суммой звука, без имени и пути записи. Термины — [`docs/bench-glossary.md`](docs/bench-glossary.md). Варианты, которые не запустились, просто помечаются как «не работает».

**Если при первом скачивании моделей появляется `CERTIFICATE_VERIFY_FAILED`**, в том числе «certificate has expired», это может быть проблема сертификата сервера, а не вашего компьютера. Проверка и разовая ручная загрузка с контролем md5: [`docs/model-download-certificate.md`](docs/model-download-certificate.md). Краткие команды для вашей установки печатает `.\.venv\Scripts\python.exe download_hint.py`.

Порог качества задаётся переменной `bench_min_similarity` в `config.json` (по умолчанию `0.97`) или ключом `--min-similarity`. Если важнее точность, а не скорость, поднимите порог:
```powershell
.\.venv\Scripts\python.exe bench.py "C:\путь\к\записи.mp3" --seconds 180 --min-similarity 0.99
```
Тогда в `config.json` запишется только вариант, который совпал с эталоном не хуже 99%. Ключ `--min-similarity` сохраняется в `config.json`: следующие запуски теста будут использовать этот порог.

В отчёте для каждого варианта теперь есть не только скорость и совпадение с эталоном, но и оценка времени на типичную 10-минутную запись с учётом загрузки модели, а также число слов и разбор расхождений: сколько слов потеряно, лишних и заменено. Раздел «Как выбрать» показывает три ориентира: самый точный вариант, самый быстрый в пределах порога и самый быстрый вообще.

Дополнительные наборы вариантов (в обычный тест не входят, запускаются ключом `--only`; модели скачиваются при первом запуске):
- `cpu-runtime` — GigaAM v3 на процессоре в разных средах исполнения: обычный ONNX Runtime, OpenVINO на процессоре и int8. Вариант OpenVINO может быть выбран и записан, как любой другой; int8 только показывается рядом и не записывается;

- `multilingual-gpu` — GigaAM Multilingual 600M на видеокарте (Arc через OpenVINO, DirectML) рядом с эталонами.

Замеры и ограничения этих наборов — [`docs/research/gigaam-multilingual-2026-11.md`](docs/research/gigaam-multilingual-2026-11.md).

## Как пользоваться
**Сохранённый процесс (режим SQLite):** нужна созданная база и выбранный режим

сохраняет процесс и запускает обработку без голосовых профилей; при `require_conspect=true` OpenCode автоматически вызывает
OpenAI `gpt-6-luna` без открытого чата, **только при явном согласии**: по умолчанию
`allow_cloud_model=false`, текст никуда не уходит. Согласие — `allow_cloud_model=true` в MCP,
`rt.py workflow-start --conspect --cloud-model` или отметка «нужен конспект» на локальном экране
(на экране заказ конспекта и есть согласие). В облако
уходят только текст слов, деление на реплики с условными метками говорящих («Участник 1»,
«Участник 2»…) и ограниченные поля задания, не подписи говорящих именами, аудио, пути, биометрия
или логи. Имена и сведения, произнесённые в записи или написанные в цели, уходят вместе с текстом. Запись длиннее 10 000 слов отправляется частями; к каждой части прилагается
изложение предыдущих, составленное моделью. Метки расшифровываются именами только на этом компьютере — в начале файла
конспекта; там же у каждого раздела стоит время его начала в записи. Цитаты в файле такой
свёртки идут «по одной»: чистая — в «», с автором, которого пишет программа; задевшая
неразобранное место — без кавычек с пометкой «по распознаванию, не проверено» и временем
(после разбора кавычки возвращаются при пересборке, без облака); не найденная в стенограмме —
без кавычек с пометкой «не найдено» (на локальном экране у такой свёртки — строка «Не найдено в
стенограмме цитат: N из M»; если таких цитат не меньше 3 и не меньше 20 %, а запрос разрешает
облако, человек может по кнопке или через `workflow_repair_quotes` попросить модель исправить их:
в облако уйдут только разделы с такими цитатами, один вызов на нажатие, ничего без согласия). Подробности и временные ограничения — в
`docs/2026-11-17-p4-opencode-openai-handoff.md`. Старые записи прежнего файлового режима в базу
не переносятся: инструмент переноса удалён (история —
[`docs/history/legacy-migration.md`](docs/history/legacy-migration.md)), старые файлы записи можно

Запрет облака у сохранённого запроса нельзя снять изменением его политики;
после отказа для облачной обработки создайте новый запрос с явным разрешением.

**Локальный экран без терминала:** `python rt.py screen` открывает в браузере

## Как устроена обработка (pipeline = "words", по умолчанию)

1. **Разделение по голосам** (pyannote) — разметка, кто где говорит, и где говорят одновременно.
2. **Распознавание длинными кусками** 12–20 с по речи, разрезанными в паузах (в сплошной речи — в самом
   тихом месте, с нахлёстом 0,5 с), **независимо от границ голосов**. Из модели берутся слова со временами
   и уверенностью. Раньше звук резался по границам голосов на сотни коротких кусков, и на стыках терялись слова.
   Известное ограничение: если в окне нет ни одной паузы (речь под музыкой или шумом, наложение), разрез может пройти
   внутри слова; тогда на стыке остаются и обрывок слова из первого куска, и слово целиком из второго. Обрывок
   обычно помечен сомнением распознавания (модели разошлись); на живых записях такого не наблюдалось.
3. **Ещё две модели по тем же кускам и голосование «два из трёх»**: CTC-версия GigaAM (со временами слов) и
   Whisper large-v3-turbo. У CTC свои `asr_second_device` / `asr_second_batch`, у Whisper — свои
   `asr_third_device` / `asr_third_quant`; по умолчанию всё на процессоре, тест скорости может развести их
   по разным устройствам. Whisper на видеокарте считает кодировщик напрямую через OpenVINO (fp16), декодер —
   на процессоре (int8); при сбое всё уходит на процессор. Слово RNN-T
   принимается, если с ним согласна хотя бы одна из двух других моделей; если обе другие согласны против
   RNN-T — берётся их вариант; где разошлись все три — метка с вариантами CTC и Whisper.
   Если кусок Whisper или CTC не распознан, голосование пропускается только на его отрезке (там сверяются
   RNN-T и CTC, в `quality` — `vote3_partial`); сбой основной модели отключает голосование для всей
   записи (`vote3_skipped`).
   Файлы Whisper (≈2,5 ГБ: кодировщик fp16 и int8, декодер int8) скачиваются при первом запуске; первая
   сборка кодировщика под видеокарту занимает минуту-две, дальше берётся из cache\openvino\whisper. Настройки: `asr_third_model` (пусто — без
   Whisper), `asr_third_device` (`CPU`/`GPU`), `asr_third_quant` / `asr_third_quant_cpu`.

   **Другие модели вторым и третьим номером.** CTC и Whisper — умолчания, а не требование: логика
   спрашивает возможности модели (`transcript.asr_model_caps`), а не её место. Вторая модель
   (`asr_second_model`) — любая модель со временами слов: GigaAM v3 CTC или RNN-T, GigaAM Multilingual
   (`multilingual_ctc`, `multilingual_large_ctc`). Whisper времён слов не даёт и вторым номером не
   считается: в журнале одна строка, в `quality` — `asr2_skipped`, сверки и голосования нет. Третья
   модель (`asr_third_model`) — любая: Whisper или модель GigaAM. Длинные куски до 28 с
   (`asr_third_long_chunks`), чистка «субтитров» и повторов (`asr_third_max_repeat`) и движки
   faster-whisper/OpenVINO Whisper — только для Whisper (faster-whisper — только для large-v3-turbo:
   для другого Whisper он пропускается, считают OpenVINO Whisper или `onnx-cpu` с выбранной моделью);
   другая третья модель считается кусками основного прохода на `onnx-cpu`, её текст не чистится.
   Вторая модель, совпадающая по имени с основной, не считается (`asr2_skipped`). Третья не
   считается (`asr3_skipped`), только если совпадает с основной или второй и по имени, и по
   фактической загрузке — движку, устройству и точности (`onnx-cpu` с `asr_third_quant_cpu` против
   движка, на котором та модель действительно загрузилась); с другой точностью или на другом движке
   она считается. Где голосование берёт слово второй модели, его время держится
   между соседними словами основной. В стенограмме варианты подписаны настоящими моделями
   (например «Multilingual large: «…»»); ключи данных прежние (`alt_ctc`, `alt_whisper`, проход
   `whisper`).
4. **Голос для каждого слова**: окна 1,5 с с шагом 0,25 с, сглаживание по пяти окнам, сравнение с голосовыми
   профилями участников (подсказка pyannote даёт поправку 0,05). Голос без профиля сравнивается с центром своего
   кластера pyannote, если у кластера есть реплики от 1,5 с и не меньше 3 с речи (сумма отрезков разметки, без пауз), а когда у участников есть голосовые профили — не меньше 10 с: иначе короткий неопознанный кусок речи участника (центр из этой же записи) уводил бы его слова от профиля. Без голосовых профилей слова голоса, у которого такой
   опоры нет (короткая реплика нового участника, короткое голосовое сообщение), остаются под меткой разметки
   pyannote («Спикер N») и не отдаются другому голосу; это назначение программы, без новых меток сомнения: отрыв у таких слов не измерялся и в порог сомнения не идёт (в наложении голосов такое слово всё же помечается — шаг 6)
   (журнал задачи: «голоса без опоры …»; в данных записи — `quality.voice_refs`). С профилями такие слова, как и раньше, получают голос по отпечатку — ближайшей опоры, с сомнением при малом отрыве (новый голос без профиля короче 10 с может так уйти участнику — известное ограничение). Слово метки, у которой все отрезки короче 0,3 с (часто ложный крошечный кластер), получает голос по отпечатку; отрезки одной метки с паузой меньше 1 с сначала склеиваются, поэтому метка из нескольких близких коротких отрезков сюда не попадает и без профилей остаётся «Спикер N». В голосовой профиль слова под «Спикер N» не попадают, пока человек не подтвердит имя.
5. **Реплики собираются после**: подряд идущие слова одного голоса с паузой меньше 1,5 с. «Угу» поверх чужой
   речи записывается вставкой и реплику не рвёт.
6. **Метки сомнения**: модели распознали по-разному; модель не уверена в слове; голоса близки (20 % слов с
   самым малым отрывом); говорят одновременно, а голоса близки или их отрыв не измерялся (одна опора на запись,
   голос по разметке); род глагола при «я» не совпадает с полом говорящего.
7. **Разбор ИИ-агентом** (`review_items` → `apply_review`): по смыслу, только в помеченных местах и только выбором
   из имеющихся вариантов. Правки идут в журнал `edits`, слова модели сохраняются. Нерешённое — в раздел
   «Проверить человеку» с таймкодами и вариантами. Замена текста идёт по словам: меняются только
   отличающиеся слова, время остальных сохраняется (на него опираются ссылки конспекта); слово, уже
   исправленное другой правкой, не перезаписывается — такие случаи в ответе `conflicts`, а места,
   которых больше нет, — в `not_found`.

**Поддакивание и ответ.** Короткое «угу / да / ага» другого человека внутри чужой речи записывается вставкой
(поддержка, реплика не рвётся). Если перед ним вопрос («…правда? — Да»), это ответ со своим смыслом —
отдельная реплика со своим именем; любые другие слова другого голоса тоже идут отдельной репликой.

**Окно 1 с у смены говорящего** (`"word_win_near_change": 1.0` в config.json) — опыт, по умолчанию выключено:
на двух отрезках 06.11 точность не выросла (−0,3 пункта, в пределах шума), а этап голосов шёл вдвое дольше.

**Где лежат результаты.** Рядом с аудио создаётся подпапка `<имя записи>.rus-transcriber`, в ней
`<имя>.transcript.md` и `<имя>.transcript.json` (с меткой `tag` — `<имя>.<tag>.transcript.*`).
Если хотя бы один из этих файлов уже существует, расшифровка не перезаписывает его:
для повторного запуска укажите другую метку `tag`. Если результат появится во время обработки,
задача завершится ошибкой вместо перезаписи; уже выполненные действия, например автоматическое
пополнение голосового профиля, этот отказ не отменяет.

### Горячие места разговора

При обработке записи (путь `words`) программа сохраняет слой признаков разговора: интервалы, где говорят
одновременно, реплики разделения по голосам с номером кластера, громкость и высоту голоса по окнам в 1 с.
В слое только числа, привязанные ко времени, — без текста, имён и отпечатков голоса; он хранится внутри
стенограммы (раздел `quality`, поле `interaction`) и в открытые документы записи не попадает.
Отключить расчёт — `"interaction": false` в `config.json`.

По запросу — инструмент `conversation_hotspots` или `rt.py hotspots ЗАДАЧА` — программа показывает
**горячие места**: отрезки, где говорящие часто сменяются, речь накладывается, голос громче или выше
обычного для того же говорящего в этой записи. Оценка считается в момент запроса по текущим словам
стенограммы, поэтому исправления «кто говорил» учитываются. Сама по себе в стенограмму и конспект она
не добавляется.

Горячее место — эвристика для навигации: подсказка, где развернуть стенограмму или послушать запись.
Это не оценка эмоций или поведения людей и не доказательство; пороги стартовые, на размеченных
разговорах не проверялись. Для записей, обработанных раньше, с выключенной настройкой или при ошибке
расчёта слоя ответ — «нет данных» с причиной; старые записи не пересчитываются.

Зачем это продукту и к чему оно должно прийти — раздел 6 в
[`docs/product-goal-and-documents.md`](docs/product-goal-and-documents.md). Из перечисленных там признаков
сейчас считаются смены говорящих, наложения, громкость и высота голоса относительно обычных для говорящего;
темп речи, паузы и оценка тона моделью по окнам пока не учитываются, пометки в конспект не передаются.
Модель эмоций (одна метка на реплику) работает по-прежнему и в оценку горячих мест не входит.

### Карточки без ИИ-агента и без MCP-клиента

В папке программы выполните в терминале (ЗАДАЧА — идентификатор готовой расшифровки):

```powershell
.\.venv\Scripts\python.exe rt.py review-build ЗАДАЧА
.\.venv\Scripts\python.exe rt.py review-page ЗАДАЧА
```

Откройте возвращённый `url` в обычном браузере на этом компьютере. Интернет и установленный
ИИ-агент не нужны: клипы и ответы остаются локально; шрифты из сети не загружаются.
Без модели создаются нейтральные карточки для открытых мест и мест, оставленных человеку:
можно оставить исходный вариант или написать свой ответ. Для собственных вопросов и вариантов
используйте `review-build ЗАДАЧА --items вопросы.json` (массив того же формата, что `build_review_pack`).
Для записи в базе повторная сборка дописывает порцию в открытый пакет: версия прежняя, ответы и «Применить»
прежних карточек сохраняются, место с карточкой пропускается («уже в пакете»), карточка с ответом, который
применить не удалось, получает новую редакцию; в пакете до 200 карточек. Полная пересборка — `rebuild=true`
(`rt.py review-build --rebuild`); в файловом режиме дописывания нет, только она.
Полная пересборка меняет версию пакета; прежние ответы архивируются. Для записи в базе пакет не
пересобирается, пока в нём есть ответы, ждущие «Применить»: отказ называет карточки. Сначала примените
сохранённые ответы (или подтвердите «Не отменять»), потом собирайте снова. После пересборки уже применённые
ответы со страницы не отменить; отчёт сборки называет их число (`undo_lost`) и ответы, которые применить
не удалось (`unapplicable`). Для записи в файлах пересборка прежняя, без этой проверки.

Сохранение ответа в браузере ещё не меняет стенограмму. Перед применением система проверяет,
не затрагивают ли разные ответы общие слова: такие карточки не применяются автоматически,
их нужно проверить человеку; независимые ответы могут быть применены. После проверки нажмите
«Применить сохранённые ответы» и изучите отчёт. Чтобы отменить применённый ответ,
нажмите «Подготовить отмену», затем снова примените сохранённые ответы. Отмена может
быть отклонена, если поздние правки изменили место или отсутствует снимок. Предпросмотр
свободного текста не записывает изменения; голосовой ответ сохраняется после подтверждения.
Вместо кнопки можно использовать команду:

```powershell
.\.venv\Scripts\python.exe rt.py review-apply ЗАДАЧА
```

Команда применяет ответы как человеческие и обновляет связанные цитаты; аудио не удаляет.
Голосовой ввод требует разрешения браузера и локальных моделей распознавания.
Страница доступна только на этом компьютере, закрывается после трёх часов без запросов;
её можно повторно запустить с сохранёнными ответами. В любом MCP-клиенте доступны
`build_review_pack` (без `items` — нейтральные вопросы), `start_review_page`, `apply_answers`.
Адрес содержит случайный секрет сеанса: не передавайте его посторонним и открывайте целиком, как вернула
команда. После перезапуска нужен новый адрес. Во время отладки архивы ответов и служебные файлы пакета
остаются доступны по этому адресу; доступ к файлам пользователя на компьютере он не защищает.
Облачный режим ИИ-агента (сейчас реализован артефактами Claude) остаётся необязательным отдельным режимом.

**Разбор голосом и карточками (локально и с телефона).** ИИ-агент (например, Claude Desktop) по сомнительным местам формулирует вопрос,
2–4 варианта и рекомендацию и собирает пакет — `build_review_pack(job_id, items)`: в подпапке результатов
появляется `<имя>.review` с клипами мест (3,5 с до места и 1,5 с после, mp3 моно 64 кбит/с), `manifest.json` и `answers.json`
(для записи в SQLite manifest хранится в базе, а не в файле).
В карточке — до 400 символов реплик до места и после него и до 700 символов внутри реплики с ⟦местом⟧.
Целиком запись никуда не уходит.
- По умолчанию выключены (включить: `"review_local": true` в config.json и перезапуск MCP-клиента):
  `start_voice_review`, `speak`, `play_clip`, `listen_reply`. Страница карточек `start_review_page` работает
  и без этой настройки.
- `start_review_page` — страница карточек на этом компьютере (http://127.0.0.1:8765/): клип, реплика с
  местом, варианты касанием, озвучка вопроса, ответ голосом с микрофона (распознаёт GigaAM).
- `start_voice_review` — разбор без экрана: голос Windows читает вопрос и варианты, играет клип, после
  сигнала записывает ответ. Понимает «первый/второй…» (и рядом с подтверждением: «верно, второй»), имя из
  варианта, «повтори», «пропусти», «оставь человеку»; остальное сохраняется как свой ответ. «Да», «верно»,
  «согласен» без номера голосом разбираются так же, как набранные (таблица коротких ответов ниже), и
  рекомендованную замену не выбирают; чтобы принять рекомендацию, назовите её номер. Работает без ИИ-агента и интернета.
- `speak`, `play_clip`, `listen_reply` — те же действия по одному, если разбор ведёт ИИ-агент.
- Облако: ИИ-агент (облачный режим сейчас — артефакты Claude) публикует ту же страницу карточек с клипами; ответы касанием и
  голосовые записи (файлом с диктофона) копятся в его базе. По команде «применяй ответы» ИИ-агент переносит
  их сюда — `import_answers` (голос распознаётся здесь же, GigaAM) — и удаляет клипы со страницы.
- `review_pack_cloud` — готовит карточки к публикации в облако (папка `cloud` пакета: страница и manifest с
  последними ответами); ИИ-агент публикует их приватной страницей и запоминает её адрес в пакете, чтобы
  обновлять ту же страницу из любой сессии. Карточки с ответом показывают последний записанный ответ
  (откуда и когда); после применения — отметку «применено», клипы со страницы убираются.
  Применённый ответ можно отменить («Подготовить отмену», затем `apply_answers`): правка места откатывается к тексту и говорящему модели, место снова открывается для разбора. Другим ответом применённый ответ не заменяется: новый ответ («Изменить ответ», другая кнопка, свой текст) сохраняется и ждёт, пока прежний не отменят; «Пропустить» и отрицание («неверно») применённый ответ не меняют. После `apply_answers` у каждого сохранённого ответа есть исход с причиной по-русски (`outcomes` в отчёте), и карточка показывает то же состояние. Неизменённые ответы повторно не применяются.
- **Свой ответ текстом** — это правка того, что человек услышал в клипе (3,5 с до места и 1,5 с после), а не
  ответ на вопрос. Можно писать по репликам: «Борис: Ой, извините, не заметил даже. Анна: Ничего страшного…».
  Сервер режет ответ по меткам «Имя:», выравнивает его со словами стенограммы в окне клипа (с учётом вариантов
  других моделей) и правит по словам: меняет говорящего (реплика делится), заменяет слова, вставляет
  пропущенную речь, которой нет ни у одной модели. «…» — дальше без изменений. Опечатку («приколько»)
  исправляет по слову модели, смену окончания («заметила → заметил») принимает. Короткий ответ без имён
  («Пришли») — новый текст места. Ответ, покрывший место соседней карточки, закрывает его («решено
  человеком через rN»). Непонятый ответ уходит человеку с его текстом. В журнале правка подписана `human`.
  Порядок старшинства: человек > отпечаток голоса > распознавание > эвристики.
- **Пропущенная речь.** Где pyannote слышит голос дольше 1 с, а слов нет ни у одной модели, появляется
  место «пропущена речь»; ответ на его карточку вставляется в этот промежуток. Пауза владеет только словами,
  начатыми внутри неё; соседнее слово в ответе узнаётся и не дублируется. Пока пустая пауза не решена, помечены
  ⟦…⟧ последнее слово до неё и первое после, и цитата с ними сомнительна; у паузы со словами помечены её
  собственные слова, соседи — нет. Если ответ совпал со словами, уже стоящими в открытой паузе, место
  закрывается как «как есть» человеком и эти слова подтверждаются (если место требует отдельного
  подтверждения прослушивания, ответ уходит человеку с причиной); у уже закрытого места ничего не меняется.
  Карточка пропуска даёт две кнопки: «Прослушал: слов нет» и «Прослушал: только междометия, не записывать»
  (в паузе есть начатые слова — ещё «Прослушал: слова в стенограмме верны»); «как есть» на паузе не
  показывается. «Слов нет» проверяется по словам, начатым в паузе: хвост слова до неё не мешает. Кнопка
  годна, пока не изменились слова её интервала (правка в другом месте записи её не портит). После
  «только междометия» в стенограмме стоит пометка «[междометия, не расшифровано] ЧЧ:ММ:СС–ЧЧ:ММ:СС» —
  перед первой репликой, начатой не раньше паузы; если такой нет (один говорящий до и после паузы —
  это одна реплика), пометка стоит после неё. Слово, вписанное потом в эту паузу, снова открывает место.
- **Короткие ответы.** Одна таблица `answer_phrases.tsv` для набранного текста и голоса. «Да», «так»,
  «ага», «угу», «нет»: на паузе — слово стенограммы; на месте с тем же словом — «как есть»; иначе —
  подсказка «напишите «Имя: да»». «Верно», «всё верно», «как есть»: на месте-слове — «как есть»
  человеком; на паузе — подсказка про кнопки; при «модели расходятся» — подсказка выбрать вариант
  карточки, который оставляет слова (подсказка называет его подпись), или вписать слова. Ответ вне таблицы, похожий на оценку («согласен», «рекомендую»), —
  подсказка. Подсказка повторяет ответ так, как он написан, ничего не меняет, место остаётся открытым
  (исход «не применён — см. подсказку»).
  Ответ с меткой «Имя: …» — всегда слова.
- `update_voice_profiles(job_id)` — пересчитать профили голосов по ответам человека: подписанные человеком
  отрезки — с весом ×3 (кроме наложений и отрезков короче 0,8 с), из подтверждённых расшифровок — только
  слова без пометок сомнения. Перед пересчётом показывается предварительный отбор и требуется подтверждение;
  существующий вклад заменяется только при получении подходящего нового. Отменённый вклад сам не удаляется:
  для него предусмотрен отдельный подтверждаемый `revoke_voice_profiles`. Поправки «A → B» копятся как
  спутанные пары: на них сервер склоняется к подтверждённому и чаще ставит метку сомнения.
  После фактической отмены или замены применённого ответа отчёт предупреждает, что прежний вклад записи
  мог остаться в профиле. Предупреждение не утверждает, что запись действительно использовалась для обучения.
  Если профиль сильно изменился (сходство < 0,8), это видно в `voice_profiles` (warnings).
- `apply_answers` — применяет ответы через `apply_review`. На одно место из двух режимов побеждает более
  поздний ответ, расхождение уходит в «Проверить человеку». Ответы на прежнюю версию вопросов (пакет
  пересобран) не применяются. `review_pack_info` — состояние пакета.
  Применённый более поздний ответ учитывается как применённый: его можно отменить. Карточка показывает
  «применён — проверьте: ответы ноутбука и облака расходились» и строку о расхождении. Кнопка «Ответ верен —
  оставить» (или тот же ответ, выбранный на ноутбуке) после «Применить» закрывает место подтверждением
  человека. Ответ человека на ноутбуке, который сохранён, снимает расхождение места; новое расхождение он не
  создаёт, если заменяет уже применённый ответ. Кнопка прослушивания, которая противоречит словам интервала,
  получает исход «не применён — ответ не совпадает со словами». Уточнения программы к исходу видны под
  карточкой и после перезагрузки страницы, в облачную страницу они не передаются; это только при хранении
  записей в базе, в файловом режиме карточка показывает уточнения, как раньше, лишь в отчёте «Применить».
  Программа может заменить одну карточку или дописать новые в уже открытый пакет (`review_pack.upsert_cards`): версия пакета прежняя, ответы на другие карточки остаются, растёт счётчик изменений пакета (`pack_rev`). Заменённая карточка получает следующий номер редакции (`rev`); прежний вопрос и ответ на него видны на карточке в истории, отменить прежний ответ после замены нельзя. Ответ со старой открытой страницы на прежнюю редакцию отклоняется («вопрос обновлён»), набранный текст остаётся в поле; локальная страница сама перечитывает карточки после действия или при возврате на вкладку. Без исходной записи новая карточка остаётся без звука.

**Проверка цитат конспекта** — `check_quotes(job_id, conspect_text | conspect_path)`: дословны ли «…» и тот ли
говорящий у цитат вида «Имя: «…»». Дословность означает совпадение нормализованных слов; неточности,
редакторские [поправки], составные цитаты и неоднозначные совпадения требуют проверки. Новые ссылки
конспектов используют ID слов; старые временные ссылки остаются непроверенными. Обновление цитат
не подтверждает актуальность выводов конспекта. MCP-инструмент `conspect_mark_reviewed` и команда
`rt.py conspect-confirm ЗАДАЧА --name НАЗВАНИЕ` фиксируют проверку смысла только после отдельного
подтверждения человеком и при неизменных файлах. Нельзя подтверждать проверку за человека.

Для неоднозначных цитат `conspect_candidates` или `rt.py conspect-candidates ЗАДАЧА ФАЙЛ.md` показывают
варианты с ID и ревизией. Выбор через MCP `conspect_link_selected` или CLI
`rt.py conspect-select ЗАДАЧА ФАЙЛ.md ВЫБОР.json --name НАЗВАНИЕ` создаёт **новый** конспект после
отдельного подтверждения человеком; существующий не перезаписывается. JSON выбора имеет вид
`{"1": {"recording_id": "...", "source_revision": 1, "word_ids": ["..."]}}` — значения берутся
из отчёта кандидатов. За один вызов можно выбрать до трёх цитат; все выбранные места показываются
человеку целиком. Слишком длинные или неразличимые в подтверждении варианты отклоняются.
Если после просмотра изменилась запись, выбор нужно получить и проверить заново.

Прежняя обработка по сегментам диаризации осталась: `"pipeline": "segments"` в `config.json`.
Вторая модель задаётся `"asr_second_model"` (по умолчанию `v3_e2e_ctc`; пустая строка — без второго прохода).

## Словарь группы и голосовые профили

Автопополнение голосов включено по умолчанию. Настройка `voice_auto_learn_default` задаёт начальное
значение для новых групп; при первом использовании оно сохраняется отдельно для группы. Далее на неё
влияет только её настройка. Управление: `python rt.py voice-auto-learn on|off [--group ИМЯ]` или MCP
`set_voice_auto_learn`; изменение требует подтверждения человека. Без `--group` меняется умолчание.
`voice_profiles` показывает настройку и приблизительную достаточность профилей.
В `weight_diagnostics` показаны численные веса и их доли по записям. Это относительные веса частей
в общем центроиде, не проценты точности и не фактическое влияние на узнавание. При обработке записи
её собственный вклад исключается, поэтому веса остальных записей там будут другими. Старый вес `sec`
может включать тройной коэффициент человеческого подтверждения и не равен длительности речи.
При некорректных или нулевых весах доли не вычисляются. Одинаковые имена файлов различаются номером
в отчёте, который не является устойчивым идентификатором записи.

Если у каждого известного участника группы накоплено не менее 90 секунд отобранной речи из трёх
записей, автоматическое пополнение группы останавливается. Запись засчитывается от 20 секунд,
не более 60 секунд на запись. В достаточность входят только вклады, прошедшие текущую версию отбора;
старые вклады сохраняются и показываются отдельно. Ранее выключенное автопополнение автоматически
не включается. Это эвристика, а не гарантия распознавания.
Старые данные без раздельной длительности не засчитываются. Диаризация, поиск новых голосов и применение
имеющихся профилей продолжаются. Новые голоса автоматически в остановленный профиль не добавляются.
Ответ, заменивший n слов на m, вносится m отдельными словами, время заменённого участка делится между ними
поровну (оценка). В «авто» материал голосов вставленные слова не идут; границы, по которым режутся
8-секундные отрезки «авто», у таких участков могут сдвинуться — профиль от самой правки не меняется,
меняется только то, что возьмёт следующее пополнение.
`python rt.py voice-preview ЗАДАЧА` или MCP `preview_voice_profiles` показывает существующие вклады и
кандидатов по временной разметке без изменения файлов. Это предварительная оценка, а не проверка
звука или окончательный результат модели. Причины отбора показаны по-русски; их счётчики относятся
к разным объектам (словам, окнам или расшифровкам) и не суммируются как одно число.
Просмотр показывает и секунды, подтверждённые человеком, «было → станет» для этой записи; если
замена вклада обнулит подтверждённое человеком, в окне подтверждения выводится предупреждение.
С 13.11.2026 подтверждением говорящего считается только пословная отметка `provenance.speaker`;
старое общее `by: human` (оно ставилось и при правке одного текста) не засчитывается — такие слова
показаны отдельной причиной. MCP `legacy_speaker_review` находит в старой стенограмме места,
где по истории правок видно решение человека о говорящем (смена говорящего или место, принятое как
есть; места, где человек правил только текст, тоже предлагаются — их говорящий подтверждается
отдельно; места короче 0,8 с в отпечаток не попадут и не предлагаются), и по `build_pack=true` собирает по ним карточки
«подтвердите говорящего». Подтверждает только человек на локальной странице разбора, затем
`apply_answers` ставит пословные отметки, и профиль обновляется обычным просмотром и подтверждением.
При пересборке карточек прежний `manifest.json` сохраняется рядом с архивом ответов, а звуковые
фрагменты прежних вопросов не удаляются. Старые подтверждения переносят до перевода записи в SQLite;
после перевода профили обучаются по записям в базе (обновление по `recording:<id>`, автопополнение).
`python rt.py voice-refresh-plan [--group ИМЯ]` или MCP `voice_refresh_plan` только читает профили и
стенограммы и показывает источники, у которых отличается отпечаток или остался старый отбор.
Строка `changed` означает, что нужен просмотр и подтверждённое обновление; сам план ничего не меняет.
Для источника хранится отпечаток: SHA-256 стенограммы и размер/mtime аудио. Поэтому правка карточек
обнаруживается даже при совпавшем времени файла и не приводит к молчаливому переобучению.
В ответе `transcript_changed` и `audio_changed` равны `true` или `false`, только когда соответствующее
сравнение доступно; `null` означает, что его выполнить нельзя. Это изменение контракта JSON для MCP и CLI.
`comparison_basis` показывает `fingerprint`, `legacy_mtime` или `unavailable`; для старого mtime поле
`legacy_mtime_changed` сообщает о несовпадении времени стенограммы, не доказывая изменение содержимого.
Аудио сравнивается по размеру и mtime, а не по хэшу: замена содержимого при прежних размере и mtime
может остаться незамеченной.
Старый источник, учтённый до появления отпечатков и не изменившийся по старому mtime стенограммы,
при следующем обучении принимается как исходный: вклад не пересчитывается, но появляется постоянный
отпечаток. Несовпадение mtime требует просмотра и не разрешает автоматический пересчёт.
`voice-update` / `update_voice_profiles` пересчитывает вклад,
а `voice-revoke` / `revoke_voice_profiles` отзывает вклады одной записи. Обе операции требуют отдельного
подтверждения; на момент подтверждения фиксируются хэши стенограммы, профиля и аудио. Перед изменением
сохраняется резерв профиля в `voice-backups` внутри группы — это биометрические данные. Автоматика
существующие вклады не заменяет. Отзыв после отмены не выполняется сам: до явной команды старый вклад
  может оставаться в профиле. Резервы не включены в экспорт группы и не удаляются автоматически.
`python rt.py voice-backup [--group ИМЯ]` или MCP `backup_voice_profiles` создаёт отдельную копию
профиля выбранной группы или всех групп, не заменяя прежние копии. Резерв не шифруется и содержит
биометрию: храните и удаляйте его по решению владельца. Массовая команда не удаляет старые копии.
`python rt.py voice-quality [--group ИМЯ]` или MCP `voice_quality` показывает политику и сохранённые
измерения записи: клиппинг, пик/RMS, долю тишины и приблизительную оценку SNR. По умолчанию политика
`warn`: программа только предупреждает и продолжает обучение. `reject_clipping` (MCP
`set_voice_quality_policy`, CLI `voice-quality-policy`) не учитывает источник с клиппингом; тихая речь
и SNR сами по себе не отбраковываются. Политика задаётся для группы или как умолчание новых групп;
в сводке видно, унаследовано значение или выбрано человеком. Измерения не заменяют проверку на слух
и не доказывают качество профиля.
Если существующий профиль повреждён, недоступен или имеет неподдерживаемую версию, программа его не
перезаписывает и сообщает об ошибке. Диаризация продолжает работать без использования этого профиля;
автоматическое преобразование старого профиля не выполняется. Просмотр, отзыв и обновление для такой
группы останавливаются до отдельного переноса, сводка профилей показывает ошибку вместо достаточности,
а импорт слиянием оставляет профиль без изменений. Заменить его можно только заменой группы: она сначала
создаёт резервную копию.
Перед импортом проверяются все голосовые профили в архиве: повреждённый или неподдерживаемой версии
останавливает импорт до изменения данных. Контрольная сумма сама по себе не подтверждает корректность профиля.
Настройка группы переносится с архивом. При слиянии сохраняется настройка существующей группы;
при замене восстанавливается настройка из архива. Для новой группы из старого архива без настройки
используется текущее глобальное умолчание; при замене старым архивом существующая настройка сохраняется.
Для импорта нового архива нужна версия программы, поддерживающая файл `voice-settings.json`.

**Защита от тёзок** (разные люди с одним именем): расшифровка помнит свою группу (`group`), и в профиль
другой группы она не идёт; вклад записи, непохожий на уже собранный голос этого имени (сходство < 0,70
или ближе к другому участнику), не добавляется, а ждёт решения в карантине (`voice_profiles` →
`quarantine`; `resolve_voice(name, recording, "same" | "different")`); если голоса записи почти не
похожи на группу — в шапке предупреждение «возможно, другая группа»; имена из `names`, которых нет в
словаре, отмечаются — их голоса в профиль не идут, пока их не добавят в `participants`.
Ответ `"different"` показывает, остался ли прежний вклад записи, и предупреждает, что штатный отзыв
удаляет вклады этой записи у всех участников, а не только у выбранного имени.

**Словарь** — файл `rus-transcriber.vocab.json` (UTF-8, можно править в Блокноте). В нём участники
(имя, пол, роль), имена и названия (`terms`), явные замены (`replace`) и замены с условием (`replace_if`)
для слов, которые бывают и обычными: «весна» → «Весна» только после предлога (обычное слово не трогается),
«Борька» → «Борис» только с заглавной и не перед «богу». Слово из `replace_if` меняется только по условию —
похожесть на термин его не трогает. Подсказки словаря после ответов помечают обычные слова (`common`).
Пример группы — каталог `examples\group.example\` (`README.md` и `vocab.json`).

Где сервер ищет словарь, по порядку:
1. путь, переданный явно (`vocab_path`);
2. папка записи и до двух папок выше. Удобно держать записи группы в одной папке и положить словарь туда:
   он ездит вместе с записями, его можно переслать отдельно, а у разных групп будут разные словари;
3. `<папка данных>\groups\<группа>\vocab.json` — словарь группы. Группа: параметр `group` в `start_transcription` (тогда её словарь сильнее словаря рядом с записью) → `default_group` в `config.json` → единственная группа в папке данных. Групп несколько и ни одна не выбрана — расшифровка не стартует с понятной ошибкой.

Что делает словарь:
- явные замены целого слова или фразы: «Борька» → «Борис», «Лисицина» → «Лисицын»;
- близкие по звучанию искажения имён и названий из `terms` («Гудзо» → «Гудзон», «вереском» → «Вереском»).
  Падежные формы («Никитой», «Эврики») не трогаются, обычные слова со строчной буквы — только при почти
  полном совпадении;
- пол участников нужен для проверки рода глаголов («я поняла» у мальчика).
Исходный текст реплики сохраняется в `.json` (поле `text_raw`), список замен — в конце `.md`.

**Голосовые профили** — `groups\<group>\voices.json` в папке данных, только на этом компьютере. Это отпечатки голосов
участников (биометрия), в словарь они не входят и вместе с ним не передаются. Пока автопополнение группы
включено, перед расшифровкой программа может использовать подходящие ранее подтверждённые расшифровки
из папки записи. Существующий вклад автоматически не заменяется. Вклад каждой записи хранится отдельно;
при распознавании её собственный вклад исключается, чтобы профиль не подсказывал сам себе.

Что делается по голосу:
1. **имена**: кластеры pyannote сопоставляются с профилями (порог сходства 0,50 и отрыв от второго 0,08), «Спикер 3» сразу становится
   «Борис». Такие имена помечены как автоматические, пока их не подтвердят через `rename_speakers`;
2. **чужой голос внутри реплики**: длинные реплики (от 3 с) проверяются окнами по 1,5 с; если 2+ окна подряд
   явно ближе к другому участнику, реплика режется по ближайшей паузе и куски распознаются отдельно;
3. **каждая реплика от 1 с** сверяется с профилями: она переходит к другому участнику, если её голос ближе
   к его профилю, с поправкой 0,05 в пользу исходного кластера. Так находятся и участники, которых pyannote
   слил с другим голосом (у детей голоса близки);
4. **род глагола** при «я» против пола говорящего: реплика переходит к участнику нужного пола, только если
   голос не возражает. Иначе — в раздел «Проверить» (обычно это ошибка окончания при распознавании или
   пересказ чужих слов).

`voice_profiles` показывает, какие профили есть и из каких записей собраны. Удалить профиль — удалить его файл (или каталог группы целиком).
Отключить проверку голосов: `voices=false` в `start_transcription` или `"voices": false` в `config.json`.

- `.\.venv\Scripts\python.exe -B -m unittest discover -s tests` — быстрые тесты (без звука и моделей, секунды): голосование «два из трёх»,
  нарезка кусков, фильтры Whisper, словарь и замены с условиями, род глагола, разбор ответов человека, метки ⟦…⟧,
  проверка цитат, настройки и выбор группы, перенос данных, оценка качества. Данные в тестах выдуманные.
  До запуска задайте `RUS_TRANSCRIBER_DATA`, `TEMP` и `TMP` в отдельном тестовом каталоге
  вне программы и настоящих данных, а также `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUTF8=1`
  и `PYTHONIOENCODING=utf-8`.
- `python -B tests/run_parallel.py` — тот же набор, поделённый на группы модулей (до 4 процессов, у каждой группы
  своя временная папка данных; три переменные выше задавать не нужно). Запуск сверяет с `discover` список модулей и
  число тестов, печатает полный вывод упавшей группы и итог в формате unittest; `--shuffle` случайно перемешивает
  порядок модулей внутри групп (состав групп задан таблицей длительностей и не меняется) и печатает seed (повтор: `--shuffle SEED`), `--sequential` — прежний прогон одним процессом.
  `--plan` показывает раскладку, не запуская тестов; `--table-from журнал.log` пересчитывает таблицу длительностей
  (`tests/parallel_durations.json`) из сохранённого вывода запуска с `--durations`, в том числе из журнала CI.
  Группа, вышедшая с ненулевым кодом, считается упавшей, даже если в её выводе «OK». Кэши моделей (`HF_HOME`,
  `TORCH_HOME`) у группы свои, в её песочнице. После успешного запуска песочницы убираются; после неудачного (или
  Ctrl-C, при котором группы убиваются) остаются, путь печатается последней строкой итога.
- `python selfcheck.py` (или просьба к ИИ-агенту «проверь установку») — те же тесты в отдельной временной папке данных,
  проверка файлов программы на личные данные и морфология. На домашней установке приватного списка запрещённых слов нет:
  проверка слов помечается как частичная (`partial: true`), а не как поломка; проверка путей всё равно выполняется.
  Тесты в самопроверке идут группами модулей в нескольких процессах (`tests/run_parallel.py`, до 4 по числу ядер; у каждой
  группы своя песочница), так что набор укладывается в несколько минут; в ответе `tests.mode` — `parallel`, число групп —
  `tests.groups`. Вернуть прежний путь (один процесс `unittest discover`) — `RT_SELFCHECK_JOBS=1` в окружении
  (`RT_SELFCHECK_JOBS=2` и больше — столько групп). Если параллельный запуск не дал итога (нет `tests/run_parallel.py`,
  не запустился, неверная раскладка), тесты сами идут одним процессом на оставшееся время, причина — в `tests.fallback`;
  упавшие тесты откатом не лечатся. У параллельного запуска нет списка самых медленных тестов (`slowest`).
- `tools/eval_quality.py` — оценка по эталону на ваших записях: WER и точность подписи голосов с порогами.
  `init имя запись.mp3 эталон.txt --names "…"` один раз расшифровывает запись и записывает базовые значения и пороги
  (WER базы + 1 п.п., голоса базы − 1,5 п.п.); `run` повторяет прогон после любой правки и сообщает о нарушениях и
  росте времени больше чем на 30 %; `score расшифровка.json эталон.txt` оценивает готовую расшифровку.
  Случаи и история лежат в папке данных (`eval\`), не в репозитории. Каждый прогон идёт в своей временной
  папке: копия аудио, словари групп, `config.json` и новая база записей; рабочая база, голосовой профиль и папка
  с настоящим аудио не меняются. Голосовые профили не копируются, поэтому прогон идёт без голосов: точность голосов
  не измеряется, её порог не проверяется. Папка удаляется после прогона, и неудачного тоже; `--keep-temp` оставляет её
  для разбора. `score` читает и выгрузку записи базы, и прежний файл. Эталон — строки `[мм:сс] Имя: текст`.
  Запускать питоном из `.venv` программы, с `HF_TOKEN` в окружении.

### Проверка окружения (`pip check`)

`pip check` может выдать одно замечание:

```
gigaam 0.2.0 requires onnxruntime, which is not installed
```

Это не поломка. Установщик ставит сборку `onnxruntime-openvino`: она даёт тот же модуль
`onnxruntime` (1.24.1) с ускорителями OpenVINO и CPU, и распознавание работает. Пакет `gigaam`
в своих метаданных по-прежнему просит пакет со старым именем, поэтому проверка формально ругается.
Если модуль импортируется и расшифровка идёт, делать ничего не нужно.

## Как устроена программа: ядро и слои управления

- **Ядро — `core.py`.** Запуск, статус, отмена и список задач, чтение стенограмм, настройки, группы и профили,
  выгрузка/загрузка/удаление данных. В нём нет ничего про MCP, Claude или другой клиент (проверяется тестом), ошибки —
  `CoreError` с понятным текстом. Тяжёлая работа идёт в отдельных процессах (`worker.py` и др.), ядро только их
  запускает и следит.
- **Слой MCP — `server.py`.** Тонкая обёртка: описывает инструменты для клиента и вызывает ядро.
- **Слой командной строки — `rt.py`.** Те же возможности без всякого клиента (`python rt.py --help`; подсказка
  по команде — `python rt.py <команда> --help`). Вывод — JSON, коды возврата 0 / 1 (ошибка) / 2 (отказ или нет
  терминала для подтверждения). Команды:
  - задачи и расшифровки: `transcribe`, `status --wait`, `jobs`, `read`, `cancel`, `settings`, `self-check`;
  - разбор и правки: `review` (список мест), `review-build`, `review-page`, `review-apply`, `edit-span` (обязателен `--by human|claude`), `reopen`;
  - конспект: `conspect-confirm`, `conspect-candidates`, `conspect-select`;
  - голоса: `profiles`, `voice-preview`, `voice-update`, `voice-revoke`, `voice-refresh-plan`, `voice-quality`,
    `voice-quality-policy`, `voice-auto-learn`, `voice-backup` (изменяющие команды спрашивают согласие в терминале);
  - сохранённый процесс и локальный экран: `workflow-start`, `workflow-status`, `workflow-list`, `workflow-questions`,
    `workflow-policy`, `workflow-confirm`, `workflow-abandon`, `workflow-task`, `workflow-part`, `workflow-part-result`,
    `workflow-result`, `workflow-execute`, `screen [--port 8766] [--hours 6]`, `db-init [--check]`, `db-backup`, `db-restore`;
  - данные: `export`, `import`, `delete-group`, `cleanup`, `audit`, `approve`.
- Разбор сомнительных мест и конспект: логика — в `core.py`; формулировку вопросов, выбор между вариантами и
  текст конспекта делает клиент с моделью, а из командной строки доступны сборка и страница карточек, применение
  ответов и подтверждение цитат. Голосовой разбор (`start_voice_review` и др.) — только через MCP.

### SQLite workflow и проверка файлов

SQLite workflow по пакетам П3–П5 интегрирован через `core.py`, CLI `rt.py`,
MCP и локальный экран. Он использует явно созданную БД схемы v4 и режим
`recording_backend = "sqlite"`; обычное открытие не мигрирует прежние схемы или
файловые данные. Переноса старых записей больше нет: инструмент П7 удалён
([`docs/history/legacy-migration.md`](docs/history/legacy-migration.md)), записи, перенесённые
им раньше, остаются в базе.
Контракты и ограничения: [`docs/2026-11-17-p3-workflow-handoff.md`](docs/2026-11-17-p3-workflow-handoff.md),
[`docs/2026-11-17-p5-screen-handoff.md`](docs/2026-11-17-p5-screen-handoff.md)
и [`docs/development-boundaries.md`](docs/development-boundaries.md).

Если правка записи (сохранение, ответы на карточки, возврат ревизии) не доходит до файла, программа называет исход
словами одинаково в `rt.py`, у ИИ-агента (MCP) и на страницах: «Не записано: файл изменён вне программы…» (в базе
ничего нового, файл не тронут; решите конфликт на экране `rt.py screen`) или «Записано в базу, но файл обновится
позже / его изменили во время записи…» (запись сохранена, файл допишет повтор или решение конфликта). Файл больше
8 МиБ, оказавшийся в конфликте, программа не копирует; когда он снова равен версии программы, конфликт закрывается на
экране кнопкой, сам файл не меняется.

Для зарегистрированного корня SQLite-документов разработчик может получить
read-only JSON-отчёт о расхождениях файлов с реестром и сохранёнными версиями,
включая архивы:

```powershell
python -m tools.verify_document_files --db <путь-к-БД> --root-id <UUID-корня> --root <путь-к-корню>
```

Команда открывает SQLite только для чтения, не чинит файлы и проверяет только
указанные БД и зарегистрированный корень. Код возврата: `0` — файлы согласованы,
`1` — найдены расхождения, `2` — ошибка проверки. Сверку запускайте при простое
materializer и внешних редакторов: файловая система не блокируется. Она не является
миграцией, backup или автоматическим восстановлением. Детали контракта —
[`docs/storage-contract-v1.md`](docs/storage-contract-v1.md); исторические
передачи П1/П2 находятся в
[`docs/history/development-legacy/README.md`](docs/history/development-legacy/README.md).

### Подтверждение опасных действий человеком

Выгрузка архива с голосами (`export_group`), загрузка (`import_group` с `apply=true`), удаление группы
(`delete_group`) и очистка журналов (`cleanup_jobs` с `apply=true`) не выполняются по одному слову модели: параметры вроде `confirm` или `apply` модель подставляет сама.
Так же подтверждаются действия от имени человека и с биометрией: подтверждение имён (`rename_speakers`),
обновление, отзыв и резерв голосовых профилей и их настроек (`update_voice_profiles`, `revoke_voice_profiles`,
`backup_voice_profiles`, `set_voice_auto_learn`, `set_voice_quality_policy`), отметка проверки конспекта и выбор
цитат (`conspect_mark_reviewed`, `conspect_link_selected`), проверка цитат по файлу вне папки данных
(`check_quotes`), а в режиме SQLite — резерв и возврат ревизии (`backup_state`, `restore_recording_revision`),
замена файла при конфликте внешней правки (`resolve_document_conflict`, `resolve_conspect_conflict`;
правка человека из файла пропадает, её копия остаётся в базе), подтверждение
проверки ответов (`request_review_answer_verification`), отметка проверки и отказ от запроса процесса
(`workflow_mark_reviewed`, `workflow_abandon_request`).
Согласие даёт человек каналом, к которому у модели нет доступа:

1. **Окно на экране (Windows).** Текст окна пишет программа: что именно будет сделано (группа, число файлов, режим,
   папка). Кнопка по умолчанию «Нет»; закрытие окна или тишина дольше `confirm_timeout_sec` (180 с) — отказ.
2. **Терминал**, если окна нет (другая система, нет экрана): сервер оставляет запрос, человек выполняет
   `python rt.py approve`, читает запрос и отвечает на клавиатуре (только в настоящем терминале). После этого тот же
   вызов, повторённый с теми же параметрами, выполняется один раз (разрешение живёт 5 минут и привязано к параметрам).

Отчёты без изменений (`import_group` без `apply`, `cleanup_jobs` в режиме подсчёта) подтверждения не
требуют. Все решения пишутся в `confirmations.log` в папке данных. Настройка — `confirm_mode` в `config.json`: `auto`
(по умолчанию), `dialog`, `terminal`, `off` (только для автоматических тестов, на живой машине не включать;
неверное значение читается как `auto`). `off` не разрешает действия, которые должен подтвердить человек: все
перечисленные выше, кроме `cleanup_jobs`, при `off` отказывают. В `rt.py` те же действия спрашивают согласие в терминале, а удаление
группы — ввод её имени.

Границы: подтверждение защищает от действий модели через MCP. Тот, у кого есть оболочка на этом компьютере под вашей
учётной записью, и так может удалить файлы напрямую; окно подтверждения проверено только в Windows.

## Подключение к другим MCP-клиентам

Сервер — обычная программа с протоколом MCP по стандартному вводу-выводу, привязки к конкретному приложению ИИ-агента в нём нет, но проверен он пока
только в Claude Desktop. Установщик прописывает сервер в настройки приложения ИИ-агента (сейчас — Claude Desktop); в другом клиенте добавьте
запись вручную (формат у клиентов немного различается, суть одна):

```json
{
  "mcpServers": {
    "rus-transcriber": {
      "command": "C:\\Users\\<вы>\\AppData\\Local\\rus-transcriber\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\<вы>\\AppData\\Local\\rus-transcriber\\server.py"],
      "env": {"HF_TOKEN": "hf_…", "RUS_TRANSCRIBER_DATA": "C:\\Users\\<вы>\\AppData\\Roaming\\rus-transcriber-data"}
    }
  }
}
```

- **Рабочий процесс** сервер сообщает сам: поле `instructions` при подключении и три промпта — `transcribe_recording`,
  `review_doubts`, `make_conspect`. Клиент, который их показывает, подскажет порядок работы.
- **Ожидание.** `transcription_status(job_id, wait_sec=50)` держит вызов до 50 секунд. Если у клиента лимит на вызов
  короче, вызовы будут обрываться: уменьшите `wait_sec` (допустимо 0–50).
- **Нужна языковая модель.** Конспект, выбор между вариантами и разбор свободных ответов делает клиент с моделью;
  без неё доступны запуск, расшифровка, профили голосов и служебные инструменты.
- **Карточки разбора** показываются как страница в клиенте, который умеет публиковать веб-страницы (артефакты).
   Локальные карточки доступны всегда через `start_review_page`; для голосового разбора включите `"review_local": true`.
- Расшифровку можно запустить и без клиента: `python rt.py transcribe запись.mp3 --names "Анна, Борис" --group example`
  (статусы и отмена — `python rt.py status|cancel`). Прямой запуск `worker.py` — для отладки: без `--status` задача
  не видна `rt.py status`/`cancel`, автор записи берётся из базы, `HF_TOKEN` должен быть в окружении. Новая запись
  сохраняется только в базу записей: без базы и `worker.py`, и `rt.py transcribe` отказывают (`rt.py db-init`).

## Папка данных

Личные данные лежат отдельно от программы: `RUS_TRANSCRIBER_DATA`, иначе `C:\Users\<вы>\AppData\Roaming\rus-transcriber-data`
(внутри папки программы быть не может; путь строится от домашней папки, потому что `%APPDATA%` и `%LOCALAPPDATA%` в некоторых ИИ-приложениях (например, Claude Desktop из
Microsoft Store) подменяются скрытой папкой внутри пакета, которая пропадает вместе с приложением; проверьте, что папка видна
в Проводнике по `%APPDATA%\rus-transcriber-data`, иначе задайте `RUS_TRANSCRIBER_DATA`). В ней `config.json` (отличия от умолчаний в коде и ключи, уже записанные в файл), `groups\<группа>\`
(`vocab.json`, `voices.json`, `voice-settings.json`, `voice-backups\`), `jobs\`, `bench\`, `eval\`, `state.sqlite3` (база записей в режиме SQLite),
`confirmations.log`; полный список — в таблице «Где что лежит». Папку программы можно удалить или
переустановить — данные останутся. `get_settings` показывает `data_dir`.

**Старая раскладка** (`profiles\`, `config.json`, `jobs\`, `bench_*` в папке программы, установки до 09.11.2026)
больше не переносится: команда переноса `migrate_data` / `migrate.py` удалена. Оставшиеся от прежнего переноса
`migration.log`, `.migrated.json` и `_backup-<дата>\` в папке данных программа не читает и не удаляет.

### Перенос и обслуживание данных

- `export_group(group, dest_dir, with_jobs)` — zip с группой (словарь + голосовой профиль) и `manifest.json`
  (версия схемы, дата, группы, контрольные суммы). Абсолютные пути заменены именами файлов, карантин голосов
  не переносится. В архиве биометрия — храните как личные данные; в разговор архив не передаётся.
- `import_group(zip_path, mode, apply)` — `merge`: добавляются недостающие участники и словарь, при споре остаётся
  профиль с большим числом секунд речи (в отчёте `conflicts`); `replace`: группа заменяется, прежняя уходит в
  `_backup-import-<дата>`. Без `apply=true` только отчёт. Проверяются версия схемы, имена файлов, контрольные суммы.
  Записи, уже учтённые в профиле, после импорта на другом компьютере могут быть учтены повторно, если их
  расшифровки переучивать; для переноса достаточно импорта.
- `delete_group(group, confirm)` — `confirm` должен совпасть с именем группы; папка уходит в `_deleted` (можно вернуть),
  `permanent=true` — навсегда.
- `cleanup_jobs(days, apply)` — убирает статусы и логи задач старше N дней.
- `cleanup_hypotheses(recording_id, unit_id, older_than_days, apply)` — удаляет сохранённые гипотезы моделей (настройка `save_hypotheses`; с Г-1 — в базе записей, частью записи): все, одной записи, одного звука или старше N дней; без `apply` — подсчёт, `apply=true` — после подтверждения человеком. Окно подтверждения и отчёт называют записи названием (иначе именем файла аудио без папки) и датой записи или обработки, номер — в конце (`recordings`, `recordings_text`). Объём — поле `hypotheses` в `get_settings`.
- То же из командной строки: `python rt.py export|import|delete-group|cleanup|audit` (`audit` ищет абсолютные пути);
  опасные действия спрашивают согласие в терминале (см. «Подтверждение опасных действий человеком»).
- Установщик: `-DataDir <путь>` задаёт папку данных (записывается в настройки сервера как `RUS_TRANSCRIBER_DATA`,
  если запись настроек не отключена `-SkipClaudeConfig`), повторная установка данные не трогает (только создаёт базу записей, если её нет, и выбирает её); `-Uninstall` отдельно спрашивает про программу (по умолчанию да) и про
  данные (по умолчанию нет). Пример словаря — `examples\group.example\`.
- Проверки: `python -B -m unittest discover -s tests` в изолированной папке (см. «Проверка качества и тесты»).
  Тесты работают только во временной папке данных (каждый модуль задаёт её до первого импорта; `test_data_safety.py`
  проверяет это и то, что перенос из «прежних мест» не срабатывает при явно заданной папке данных).

**Какой Whisper выбрать?** Если после проверки тихой речи, пауз и спорных
фрагментов качество близко, можно предпочесть `whisper-ct2` (faster-whisper),
если его скорость на вашем компьютере приемлема. ONNX может оказаться быстрее;
при сбое загрузки CT2 программа пробует ONNX на CPU. Оба варианта могут
пропускать речь или выдумывать слова на тишине; совпадение с другой моделью
не заменяет прослушивание. Замеры, версии и ограничения —
в [исследовании третьего прохода](docs/research/research-third-whisper-2026-11.md).

Устройство задаётся **отдельно для каждой группы**, а не одной настройкой на всё:

- **основной проход GigaAM RNN-T** — `asr_backend` и `asr_device`;
- **второй проход GigaAM CTC** — свои `asr_second_backend`, `asr_second_device`, `asr_second_batch`; он может считаться на видеокарте, пока RNN-T считает на процессоре, и наоборот;
- **Whisper** — своё `asr_third_device`; он тоже может считаться отдельно от GigaAM;
- **разделение по спикерам** — своё `diar_ov_device`.

Эмоции (GigaAM-Emo) всегда считаются на процессоре — настройки устройства для них нет: так они не отнимают видеокарту у распознавания. Время этого этапа записывается в `timing.emotions_sec` (если эмоции включены).

Тест скорости проверяет RNN-T, CTC и Whisper **по отдельности** и записывает лучшие настройки каждой группы. Ничего не «привязывается» к устройству основной модели: если для GigaAM быстрее процессор, а для Whisper — видеокарта, так и будет записано.

### Два слоя настроек: общие и для этой машины

- **Общие умолчания** — в `settings.py`. Они уходят в Git и одинаковы для всех: чистая установка везде считает на процессоре.
- **Настройки этой машины** — `config.json` в папке данных (`%APPDATA%\rus-transcriber-data`). Туда тест скорости пишет только отличия от умолчаний; ключ, уже записанный в файл, остаётся в нём, даже если совпадает с умолчанием. Этот файл не в Git, поэтому у каждого компьютера свои процессор/видеокарта/NPU.

Если перенести папку данных на другой компьютер, его `config.json` переедет вместе с ней; после смены железа достаточно снова запустить тест скорости.

Если выбранное устройство не запустилось, обработчик сам переходит к следующему варианту и пишет причину в `asr_fallbacks` в статусе задачи.

## Что ожидать
- По умолчанию на процессоре идут и GigaAM, и CTC, и Whisper. Тест скорости может перевести любую из групп на видеокарту — но только если текст совпадёт с эталоном не хуже 97%. На проверенной машине с Intel Core Ultra 5 125H для GigaAM совпадение на видеокарте оказалось ниже (около 90–96%: часть кусков возвращалась пустой), поэтому остаётся процессор.
- Для ориентира на той же машине с Intel Core Ultra 5 125H (запись 300 с, куски до 20 с): процессор — около **27×** реального времени с пакетами по 16 (совпадение 98,1%) и около **17×** поштучно (100%); видеокарта Arc с фиксированными 22-секундными кусками — около **53×**, но с потерей слов; NPU дал бы около 97×, но с неверным текстом, поэтому он отключён. На ней выбран поштучный режим: точность важнее, порог поднят до 99%.
- Если указать число участников, разделение по голосам заметно точнее.
- Эмоции: четыре класса (позитив, раздражение, грусть, нейтрально). Это оценка модели, а не факт: одна метка на реплику от 2 с, по первым 15 с реплики. В тексте помечаются только уверенные ненейтральные реплики; в режиме SQLite в открытые документы метки не попадают. Для чего эмоции нужны продукту — раздел 6 в [`docs/product-goal-and-documents.md`](docs/product-goal-and-documents.md).
- Если что-то сломалось, причина будет в `jobs\<id>.log`.
