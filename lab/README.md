# Лаборатория опытов: прогон моделей по имеющимся записям

Первый рабочий вариант лаборатории из направления РАР-4
([rar-roadmap.md](../docs/rar-roadmap.md), раздел «РАР-4»). Задача опыта — собрать данные для
вопроса «какие модели нужны для сведения и насколько меньше станет мест для разбора
человеком»: скорость этапов, итоги голосования, места для разбора по причинам и гипотезы
каждой модели. Анализ собранного — отдельный шаг (по формату ниже).

Папку `lab/` установщик (`install.ps1`) не ставит. Лаборатория запускается обычной командой
Python, без ИИ-агента и без MCP-сервера.

## Как запустить

Интерпретатор — из установленной программы (только в нём есть пакеты), код — из этого клона:

```powershell
$py = "$env:LOCALAPPDATA\rus-transcriber\.venv\Scripts\python.exe"
cd <папка клона>

# 1. Песочница: новая пустая папка вне папки данных, программы, клона и папок с аудио
& $py -B lab\experiment.py prepare --sandbox D:\lab\models-1 --voice-profiles copy

# 2. План и оценка времени, без счёта
& $py -B lab\experiment.py run --sandbox D:\lab\models-1 --dry-run

# 3. Прогон (можно прерывать Ctrl+C и запускать снова — посчитанное пропускается)
& $py -B lab\experiment.py run --sandbox D:\lab\models-1
& $py -B lab\experiment.py run --sandbox D:\lab\models-1 --configs c-no-third,f-whisper-doubt --limit 4

# 4. Пересобрать обезличенную сводку (прогон делает это сам в конце)
& $py -B lab\experiment.py summary --sandbox D:\lab\models-1

# 5. Анализ: отчёт, примеры и обезличенные числа (раздел «Анализ» ниже)
& $py -B lab\experiment.py analyze --sandbox D:\lab\models-1 [--baseline a-current]
```

Ключи `run`: `--experiment` — файл опыта (по умолчанию
`lab/experiments/models-arbitration.json`); `--configs` — конфигурации через запятую (id или
начало id); `--units` — единицы через запятую (начало `unit_id`, его показывает `--dry-run`);
`--limit N` — не больше N пар за запуск; `--dry-run` — только план; `--program-dir` — папка
установленной программы, если не та, что при подготовке.

Перед прогоном: закрыть программу и не запускать расшифровки (лаборатория не занимает место в
очереди тяжёлых задач программы, а только отмечает в паспорте, была ли занята очередь),
питание от сети. Переменная `HF_TOKEN` не нужна: модели берутся из кэша без сети.

`prepare` по умолчанию берёт ту же папку данных, что программа (`RUS_TRANSCRIBER_DATA` или
`%APPDATA%\rus-transcriber-data`); другая — ключом `--source-data`. Папка программы — ключ
`--program-dir` (по умолчанию `%LOCALAPPDATA%\rus-transcriber`). Ключи `--audio`, `--group`,
`--only-audio` у `prepare` и действие `add-audio` — для файлов вне базы записей (раздел
«Пробный запуск на отрывке»).

## Безопасность и что копируется

Песочница — обязательный параметр. Работа не начинается, если папка песочницы совпадает с
настоящей папкой данных, папкой установленной программы, клоном репозитория или папкой с
исходными записями, лежит внутри одной из них или содержит её (ссылки и junction
раскрываются, регистр в Windows не учитывается). Для новой подготовки нужна новая пустая папка.

| Что | Откуда | Куда в песочнице | Зачем |
|---|---|---|---|
| База записей `state.sqlite3` | папка данных | `source/state.sqlite3` | список записей, группы, прежние времена, решения человека — для анализа |
| `config.json` | папка данных | `data/config.json` | выбор моделей и устройств этой машины — основа конфигураций |
| Словари групп `vocab.json` | `groups/<группа>/` | `data/groups/<группа>/` | словарь и участники, как в обычной обработке |
| Голосовые профили `voices.json`, `voice-settings.json` — **биометрия** | `groups/<группа>/` | `data/groups/<группа>/` | только при `--voice-profiles copy`: имена говорящих и метки «голос» как в обычной обработке |
| Аудиофайл вне базы записей | указанный путь | `audio/<то же имя>` | только при `--audio` / `add-audio`: считается копия; удаляется вместе с песочницей |
| Соль стенда `bench/testbed.json` | папка данных | `data/bench/` | тот же обезличенный идентификатор стенда, что в тесте скорости |

База копируется штатной резервной копией программы (`Store.backup`), двумя путями:

- **Обычный случай — программа закрыта**, рядом с базой нет `-wal` и `-shm`: база открывается
  штатно `storage.open_store_readonly`, которая в этом случае открывает её неизменяемой
  (`immutable=1`) и рядом ничего не создаёт. Если за время копирования база изменилась или
  появились служебные файлы (программа начала писать), копия выбрасывается и делается вторым
  путём. В выводе `prepare` и в `LAB-SANDBOX.json` (`copied[].method`) — `readonly`.
- **Программа работает или осталась после сбоя** (`-wal` и/или `-shm` есть): штатное чтение
  в этом случае видит данные из `-wal`, но меняет `-shm` — обновляет его содержимое, а если
  рядом лежит только `-wal`, создаёт новый `-shm`. Поэтому база и `-wal` читаются побайтно во
  временную папку песочницы (если файлы меняются во время чтения — повтор; при постоянных
  изменениях — отказ с просьбой закрыть программу), из этой копии делается резервная копия,
  временная копия удаляется. Метод — `bytes`.

Папка данных не меняется ни в одном из случаев — это проверяет тест (содержимое и время
изменения каждого файла, новых файлов нет): закрытая база, живой писатель с непустым `-wal`,
оставшийся `-wal` без `-shm`. Резервная копия неактивна (заблокирована до явной перепривязки), поэтому
программа по ней не пишет документы рядом с аудио. Копия лежит в `source/`, а не в `data/`:
у конвейера в песочнице нет рабочей базы записей.

Аудиофайлы только читаются (контрольная сумма при подготовке и перед прогоном; изменившийся
файл не обрабатывается). В настоящую папку данных лаборатория не пишет ничего; она лишь
проверяет в паспорте, заняты ли места очереди `jobs/slots` (проба блокировки без записи).
Из папки программы читаются только модели кэша `cache/` и интерпретатор; компиляция OpenVINO
идёт в `cache/openvino` песочницы. Всё работает без сети: `HF_HUB_OFFLINE=1`, откат на
PyTorch (он может скачивать модели) запрещён, эмоции выключены. Ничего не уходит за
пределы компьютера; выгрузка сводки — отдельное решение человека.

Неизменность источника закреплена тестом `tests/test_lab_experiment.py` (содержимое и время
изменения каждого файла папки данных и папки с аудио до и после подготовки и прогона).

## Устройство прогона

- **Единица опыта** — звук: записи базы с одинаковой контрольной суммой файла (варианты одной
  записи) считаются одним звуком. Группа берётся из стенограммы записи
  (`quality.runtime.group`); имена участников (`names`) не передаются — голос ищется среди
  всех участников словаря группы.
- **Общие этапы на звук** выполняются один раз и общие для всех его конфигураций в этом
  запуске: чтение звука (`worker.load_audio`), словарь (`worker.resolve_vocab_details`),
  разделение говорящих (`worker.diarize`), голоса. Голоса готовятся теми же функциями, что в
  `worker.main` для пословного конвейера, но профиль только читается
  (`worker.load_group_profile_for_recognition`): автопополнение выключено, чтобы прогон
  не зависел от порядка и ничего не менял. Эти ~40 строк повторяют порядок вызовов из
  `worker.main` (там они не выделены в функцию) — это единственное место, где лаборатория
  повторяет шаги, а не вызывает готовую функцию.
- **Каждая конфигурация** — вызов рабочего `worker.run_words` с настройками конфигурации:
  проходы моделей, сведение гипотез (`words.combine_hypotheses`: `vote3`, частичное исключение
  сбойных отрезков или `mark_alt`), словарь, голос каждого слова, места
  для разбора, слой признаков разговора — тот же код, что в обычной расшифровке.
- **Гипотезы** перехватываются на время вызова, без правки конвейера: `words.transcribe`
  (слова основного и второго прохода до голосования), `words.clean_whisper` (текст третьей
  модели по кускам до и после чистки), `words.vote3` / `words.mark_alt` (какое сведение и
  с каким списком слов третьей модели; при частичном исключении после `vote3` вне сбойных
  отрезков идёт `mark_alt` на каждом отрезке — записывается `vote3`, а число таких отрезков —
  в `mark_alt_spans`), `backends.make_asr` (что запрошено и что получилось, откаты).
- **Результат** пишется в отдельную базу результатов `results/lab.sqlite3`, а не новой
  ревизией в копию базы записей: ревизия в базе записей регистрирует файлы стенограммы рядом с
  аудио (при открытии копии программой они могли бы появиться рядом с настоящими записями),
  сталкивается с уже зарегистрированными путями и смешивает опыт с работой человека.
  Сопоставление конфигураций на одной записи — по `unit_id`; связь с записями и решениями
  человека в копии базы — через `recording_ids` в `units.json`.
- **Возобновление.** Пара «единица × конфигурация» считается посчитанной, если в базе есть
  строка `state='done'` с тем же `config_sha256`. Сумма меняется при правке ролей или
  настроек конфигурации и при другом `config.json` песочницы — тогда пара считается заново
  (прежняя строка остаётся). Пары с ошибкой повторяются при следующем запуске.
- **Скорость** отдельно не меряется: записываются времена этапов, которые считает конвейер
  (`timing`), и условия запуска из `runinfo` (паспорт прогона; условия до и после каждой пары
  и проверка готовности `runinfo.preflight`).

## Конфигурации готового опыта

Файл `lab/experiments/models-arbitration.json`. Не заданные в ролях среды исполнения и
устройства берутся из `config.json` песочницы.

| id | Основная | Вторая | Третья | Зачем |
|---|---|---|---|---|
| `a-current` | GigaAM v3 RNN-T | GigaAM v3 CTC | faster-whisper (`whisper-ct2`), вся запись | как сейчас, опорная |
| `b-ml3` | RNN-T | CTC | GigaAM Multilingual large CTC, fp32, процессор | другая третья модель |
| `c-no-third` | RNN-T | CTC | — | нужен ли третий проход |
| `d-ml2-whisper3` | RNN-T | Multilingual large CTC | faster-whisper | вторая — независимая модель |
| `e-ml2-no-third` | RNN-T | Multilingual large CTC | — | независимая вторая без третьей |
| `f-whisper-doubt` | RNN-T | CTC | faster-whisper только в кусках расхождения RNN-T и CTC | дешёвая третья |

Особенности: Multilingual третьей считается кусками GigaAM (до 22 с), а не длинными кусками
Whisper (`long_chunks: false`; длинные куски конвейер даёт только Whisper); её текст строчный
и без пунктуации, как и в тесте скорости, и не чистится `clean_whisper` (чистка — только для
Whisper). Multilingual второй сохраняет времена слов; там, где голосование берёт вариант второй
модели, в стенограмму попадают её слова без пунктуации, а время слова держится между соседними
словами основной модели (`words._fit_times`). В диагностике конвейера ключ третьей модели
называется `whisper` при любой модели.

Невозможно без правки `worker.py` (и потому нет в опыте): четыре и больше модели в одном
голосовании; основная модель без времён слов; голосование по другому правилу; Multilingual
третьей на видеокарте (для третьей модели на GPU конвейер пробует путь Whisper для
видеокарты). Пересвести сохранённые гипотезы любого набора моделей можно при анализе:
слова RNN-T, CTC и Multilingual со временами и тексты Whisper и Multilingual по кускам
сохраняются, штатную `words.combine_hypotheses` можно вызвать на них вместе с диагностикой
кусков пары.

## Формат файла опыта

```json
{"schema": "lab-experiment-1", "name": "...", "description": "...",
 "allow_torch_fallback": false,
 "estimate_sec_per_audio_hour": {"third:multilingual_large_ctc:all": 900},
 "configurations": [
   {"id": "a-current", "label": "...", "note": "...",
    "roles": {"primary": {"model": "v3_e2e_rnnt", "backend": "onnx-cpu", "device": "CPU", "batch": 1, "quant": null},
              "second": {"model": "v3_e2e_ctc", "backend": "auto", "device": "CPU", "batch": 1},
              "third": {"engine": "whisper-ct2", "mode": "all"}},
    "settings": {"review_missed": true}}]}
```

- `id` — латиница в нижнем регистре, цифры, `-`, `_`, до 40 знаков; уникален.
- `primary`: `model` обязательно → `asr_model`; `backend` → `asr_backend`, `device` →
  `asr_device`, `batch` → `asr_batch`, `quant` → `asr_quant` и `asr_quant_cpu` (действует и на
  второй проход — так устроен конвейер; `null` — fp32).
- `second`: `null` — без второй модели (`asr_second_model: ""`); иначе `model` →
  `asr_second_model`, `backend`, `device`, `batch` → `asr_second_*`. Модель не может
  совпадать с основной и должна давать времена слов (Whisper вторым номером — ошибка файла опыта).
- `third`: `null` — без третьей (`asr_third_mode: "off"`); требует второй модели. `engine`:
  `whisper-ct2` (faster-whisper; при сбое конвейер сам откатывается на ONNX-Whisper),
  `whisper-onnx` (ONNX-Whisper; `device` CPU или GPU, `quant`), `onnx` (любая модель onnx-asr
  по имени `model`, только CPU, `quant` → `asr_third_quant_cpu`, `null` — fp32). Общие поля:
  `mode` (`all` или `doubt`) → `asr_third_mode`, `max_repeat` → `asr_third_max_repeat`
  (действует только на Whisper), `long_chunks` → `asr_third_long_chunks` (только для Whisper).
  Ошибка — явная `model` у `engine: onnx`, совпадающая с основной или второй, у которой явно
  `backend: onnx-cpu` и та же точность (`quant` основной роли; вторая наследует его): конвейер такую
  третью пропускает. С другой точностью или движком она считается; если движок или точность
  берутся из `config.json` песочницы, решает конвейер при запуске (`asr3_skipped`).
- `settings` — прочие настройки `settings.py` (опечатка в имени — ошибка). Нельзя менять
  настройки общих этапов и заданные лабораторией: `diar_*`, `torch_threads`, `voices`,
  `voices_debug`, `default_group`, `pipeline`, `recording_backend`, `emotions`,
  `max_heavy_jobs`, `word_win_near_change`.
- Лаборатория всегда ставит `emotions: false`, `pipeline: "words"`.
- `estimate_sec_per_audio_hour` — свои оценки секунд счёта на час звука по ключам
  `primary:<модель>`, `second:<модель>`, `third:<модель или whisper-ct2>:<режим>`,
  `diarization`, `voices`, `word_voice`.

## Формат результатов

Песочница:

```
<песочница>/
  LAB-SANDBOX.json        метка песочницы: источник, папка программы, что скопировано
  units.json              единицы опыта (локально: в нём пути к аудио)
  audio/                  копии внешних аудиофайлов (prepare --audio, add-audio); считаются они
  source/state.sqlite3    неактивная резервная копия базы записей (нет при --only-audio)
  data/                   папка данных конвейера в песочнице (config.json, groups/, bench/, jobs/)
  results/lab.sqlite3     база результатов (тексты и гипотезы — только здесь)
  results/report.md       отчёт анализа (без текстов слов)
  results/examples.md     примеры анализа со словами (только этот компьютер)
  export/summary.json     обезличенная сводка
  export/analysis.json    обезличенные числа анализа
  tmp/, cache/openvino/   временные файлы и кэш компиляции
```

### `units.json` (схема `lab-units-1`)

`{"schema", "units": [...], "missing_audio_recordings": [recording_id, ...]}`. Единица:
`unit_id` (первые 16 знаков `audio_sha256`), `audio_sha256`, `location` (путь к аудио),
`size_bytes`, `group`, `group_conflict` (варианты с разными группами), `no_profile`,
`duration_sec` (из стенограммы), `recordings` — варианты: `recording_id`, `location`,
`group`, `no_profile`, `tag`, `duration_sec`, `timing` (прежние времена обработки этой записи:
`asr_sec`, `asr2_sec`, `asr3_sec`, `diarization_sec`, `voices_sec`, `word_voice_sec`, … и
названия `asr_model`, `asr2_model`, `asr3_model`, `asr3_device`, `asr3_mode`).

Единица из внешнего файла (раздел «Пробный запуск на отрывке»): `origin: "audio_file"`,
`location` — путь копии в `audio/` песочницы (с неё и считается), `source_location` — откуда
файл скопирован (только для справки, только в этом локальном файле), `group` — из `--group`
или `null`, `duration_sec` — по самому звуку (`ffprobe`, для WAV — и без него),
`recordings: []`. У единиц из базы поля `origin` нет. В сводке у каждой единицы есть
`origin` — `audio_file` или `database`; путей и имён файлов в сводке и `analysis.json` нет.

### `results/lab.sqlite3` (схема `lab-results-1`, в таблице `meta`)

Строки только добавляются (кроме отметок окончания запуска и звука).

- `runs` — запуск: `run_id`, `started_utc`, `finished_utc`, `state` (`running`, `finished`,
  `interrupted`), `experiment_name`, `experiment_sha256` (сумма текста файла опыта),
  `experiment_json`, `passport_json`, `args_json`.
- `configs` — конфигурация в версии: `config_id`, `config_sha256`, `label`, `roles_json`,
  `settings_json` (поле `settings` конфигурации), `effective_json` (все настройки, с которыми
  вызван конвейер), `first_run_id`.
- `unit_runs` — общий этап звука в запуске: `run_id`, `unit_id`, `state` (`running`, `done`,
  `error`), `error_kind`, `error` (хвост трассировки), `shared_json`: `duration_sec`,
  `diarization_sha256`, `diarization_segments` (`[начало, конец, метка pyannote]`),
  `diarization_info`, `turns`, `label_name` (метка → имя), `voices` (`voice_profile`,
  `profile_names`, `match`, `unmatched`, `voices_error`, `voices_off`), `timing`
  (`diarization_sec`, `voices_sec`, `embeddings_sec`). Векторов голосов нет.
- `pairs` — пара: `pair_id`, `run_id`, `unit_id`, `config_id`, `config_sha256`, `state`
  (`done` или `error`), `started_utc`, `finished_utc`, `error_kind`, `error`,
  `diarization_sha256` (у пар одного звука из разных запусков можно проверить, что разделение
  говорящих одинаково), `conditions_json` (`before`, `after` — `runinfo.conditions`;
  `preflight` — `runinfo.preflight`), `metrics_json` (ниже), `result_json`, `hypotheses_json`.

`result_json` — данные расшифровки, которые вернул `worker.run_words`, дополненные так же,
как в `worker.main`: `segments` (слова с `w`, `s`, `e`, `c`, `flags`, `alt`, `alt_whisper`,
`voted`, `model`, …), `review` (места для разбора: `reasons`, `t1`, `t2`, `text`, `alt_ctc`,
`alt_whisper`, `asr_problem`, …), `quality` (`vote`, `vote3_skipped`, `vote3_partial`, `asr_votes`,
`asr_diagnostics`, `asr_run`, `asr_incomplete_chunks`, `asr2_error`, `asr3_errors`,
`missed_speech`, `missed_speech_diagnostics`, `interaction`, `words`, `flagged_words`, …),
`speakers`, `speaker_names`, `file`, `duration`, `group` и `timing`.

`timing` пары: времена конвейера (`asr_sec` — основной проход без загрузки модели,
`asr_chunks`, `asr_backend`, `asr_model`; `asr2_sec` — второй вместе с загрузкой, `asr2_model`;
`asr3_sec`, `asr3_load_sec`, `asr3_model`, `asr3_device` — `движок:устройство:точность`,
`asr3_name`, `asr3_mode`, `asr3_pieces` — `посчитано/всего` кусков, `asr3_removed_words`,
`asr3_fallbacks`, `asr3_compile_sec`; `word_voice_sec`, `word_windows`, `interaction_sec`) и
лаборатории: `diarization_sec`, `voices_sec`, `diarization` (шаги pyannote) — общие для звука;
`embeddings_sec` — общий этап плюс эта пара; `pair_sec` — время вызова `run_words`;
`total_sec` = общие этапы + `pair_sec` (сколько заняла бы обычная обработка с этой
конфигурацией, без эмоций); `realtime_factor` = длительность / `total_sec`;
`asr_fallbacks` — откаты основного прохода.

`hypotheses_json` (схема `lab-hyp-1`):

```
{"schema": "lab-hyp-1",
 "combine_rule": "vote3_partial" | "whole_record",
 "primary": {"model", "backend", "chunks": [{"a", "b", "own": [с, по]}], "words": [{"w", "s", "e", "c"}]},
 "second":  тот же вид или null,
 "third":   {"model", "backend", "name", "mode", "pieces",
             "chunks": [{"chunk_index", "audio_span", "own_span", "state", "raw_text", "text", "removed_words"}]} или null,
 "vote":    {"function": "vote3" | "mark_alt", "third_words": [слова, поданные в vote3] | null,
            "mark_alt_spans": число исключённых отрезков (только при частичном исключении)} или null}
```

`combine_rule` — правило сведения версии `words.py`, с которой посчитана пара
(`lab_run.combine_rule`): `vote3_partial` — сбойный кусок второй или третьей модели исключает
из голосования только свой отрезок; `whole_record` — прежнее правило (любой сбойный кусок
отключал голосование на всей записи). В базах, записанных до появления отметки, её нет.

Слова — до голосования и словаря; `c` — уверенность слова; времена в секундах от начала
записи. Слово попадает в проход, только если начинается в своей части куска (`own`), как в
конвейере. У третьей модели `raw_text` — ответ модели, `text` — после `clean_whisper` (у модели
не из семейства Whisper — без чистки: `junk=False`, без предела повторов);
в режиме `doubt` кусков меньше, а в `vote.third_words` на месте непосчитанных кусков стоят
слова RNN-T (так конвейер подаёт их в голосование). `state` куска — из диагностики
(`ok`, `empty_unknown`, `error`). У кусков основной и второй моделей поля `state` в гипотезах
нет: состояние их кусков — только в `result_json` → `quality.asr_diagnostics`.

`asr_problem_items`), `review_per_hour`, `vote` (`agree3`, `agree2`, `replaced`, `inserted`,
`disputed`), `vote3_skipped`, `vote3_partial` (`reason`, `spans`, `seconds`), `asr_votes`,
`asr_incomplete_chunks`, `asr_diagnostics`
(по ролям `primary`, `second`, `whisper`: `backend`, `chunks`, `states` — число кусков по

`missed_speech`, `voice_doubt_threshold`, `overlaps_sec`, `timing` (числовые поля выше и

`export/summary.json` (схема `lab-summary-1`) — пригодная для выгрузки сводка: `runs`
(паспорт `runinfo`: окружение, железо, обезличенный `testbed_id`, кэш моделей, работа без

`roles`), `units` (`unit_id`, `audio_sha256`, `duration_sec`, `variants`), `pairs` (`run_id`,
`unit_id`, `config_id`, `config_sha256`, `state`, времена, `error_kind`, `conditions`,

это на синтетических данных. Выгрузка — только по решению человека.

## Анализ

Команда `analyze` (модуль `lab_analyze.py`) отвечает на вопрос опыта: насколько меньше мест
для разбора уходит человеку при каждом наборе моделей, какие модели для этого нужны, какой
ценой во времени машины. Она читает только песочницу и пишет только в неё:

| Файл | Что | Куда можно |
|---|---|---|
| `results/report.md` | отчёт с таблицами и короткими выводами, без текстов слов | только этот компьютер |
| `results/examples.md` | примеры решений человека со словами всех моделей | только этот компьютер |
| `export/analysis.json` | схема `lab-analysis-1`, `version` 2: только числа, `config_id`, `unit_id`, названия моделей и коды причин | выгрузка — решение человека |

Аудио, модели и настоящая папка данных не нужны. База результатов и копия базы записей
открываются только на чтение: копия базы записей — штатно `storage.open_store_readonly` (с
проверкой схемы), база результатов — тем же правилом своим кодом (у неё другая схема); без
служебных файлов рядом обе открываются неизменяемыми и ничего рядом не создают.
Названия показателей — из [bench-glossary.md](../docs/bench-glossary.md), раздел «Время
человека и сведение моделей».

### Какие пары учитываются

Только пары `state='done'` последней версии каждой конфигурации (`config_sha256` последней
посчитанной пары); на единицу — последняя такая пара. Пары с ошибкой и старых версий только
считаются в разделе «Данные». Чего нет, выводится как «не измерено» с причиной, а не нулём.

### 1. Конфигурации

- **Места для разбора на час звука** — сумма мест по единицам, делённая на сумму часов
  (`micro_average`, а не среднее процентов); у каждой единицы — свои числа. Час звука —
  `duration_sec` пары. По причинам (`by_reason`) место с несколькими причинами считается
  в каждой из них.
- **Виды мест спора моделей** (каждое место — в одном виде): `asr_only` — единственная причина
  `asr` («только спор моделей»); `asr_mixed` — `asr` и ещё причина; `asr_incomplete` —
  место из-за неполного прохода (`asr_problem` с состоянием `error`, `empty_unknown`,
  `filtered`), а не из-за спора; `no_asr` — без причины `asr`.
- **Итоги голосования** — счётчики `vote3` конвейера (`agree3`, `agree2`, `replaced`,
  `inserted`, `disputed`), доли — от числа слов основной модели (сумма по единицам). Где
  голосовала `mark_alt` (нет третьей или голосование отключилось), согласие двух моделей
  пересчитано по сохранённым гипотезам (`source: recomputed`); у записи прежним правилом
  (раздел 3, «Сверка») счётчики — пересчётом нынешним правилом. При частичном исключении
  счётчики `vote3` — только по словам вне исключённых отрезков.
- **Отметки сведения** — нынешним правилом: пересчётом, если он есть (итог сверки `ok` или
  `old_rule`), иначе как записал конвейер. `vote3_skipped` — в скольких единицах голосование
  отключилось на всей записи и почему (`whisper_incomplete`, `asr_incomplete`): сбой куска
  основной модели или вне сбойных отрезков нет слов. `vote3_partial` — в скольких единицах
  сбойные куски второй или третьей модели исключены из голосования только на своих отрезках:
  число единиц, сумма отрезков и секунд, причины. `revote_check` — число пар по итогам сверки.
- **Состояния кусков** по ролям конвейера (`primary`, `second`, `whisper` — третья модель
  любого движка): `ok`, `empty_unknown` (пустой ответ), `error`, `filtered` (весь текст третьей
  модели убран фильтром ложных фраз).
- **Время машины на час звука** по этапам `timing` пары (поля — в «Формате результатов»);
  этап, измеренный не у всех единиц конфигурации, — «не измерено».
- **Сравнение с базовой** (`--baseline`, по умолчанию `a-current`) — только на единицах, где
  посчитаны обе пары: разность сумм мест (всего и спор моделей), число единиц «лучше / хуже /
  равно» и вывод по [bench-database-spec.md](../docs/bench-database-spec.md), раздел 8.6:
  «тенденция», если в одну сторону не меньше 2/3 единиц и суммарно не меньше 10 % и 10 мест;
  «мало данных» — меньше 4 единиц; иначе «различия нет». По полному времени — медианное
  отношение `total_sec` (не меньше 10 %); полоса шума не измерена (повторов нет).
- Всё это дано дважды: по всем парам и без пар с признаками сбоя (раздел 5).

### 2. Попарное согласие моделей

Источник гипотез единицы — «роль:модель» (`primary:v3_e2e_rnnt`, `second:v3_e2e_ctc`,
`second:multilingual_large_ctc`, `third:whisper-ct2`, `third:multilingual_large_ctc`,
`third:whisper-ct2:doubt`). Один и тот же источник есть в нескольких конфигурациях; берётся
пара базовой конфигурации, затем по порядку, остальные сверяются с ней (`sources_consistency`:
одинаковы ли слова и разделение говорящих).

- **Согласие A с B** — доля слов A, для которых `words._ops(A, B)` (то же выравнивание, что
  в `vote3` и `mark_alt`: склейки и пары `SAME` — не расхождение) даёт «согласна»; сумма по
  единицам. **Места расхождения** — число несовпадающих участков выравнивания, на час звука.
- **Похожие ошибки** (гипотеза РАР-4) — для второй модели X и судьи R (другая модель):
  среди слов основной, с которыми R не согласен, доля тех, где X согласна с основной. Если
  у CTC (то же семейство) доля выше, чем у независимой Multilingual, CTC чаще повторяет
  основную там, где третья видит иное. Это согласие моделей, а не точность; с решениями
  человека то же сравнивается в разделе 4 («тот же текст, что основная»).

### 3. Пересведение

Для каждой единицы по сохранённым гипотезам считаются все сочетания «основная + вторая» и
«основная + вторая + третья» — штатной `words.combine_hypotheses`, той же функцией, что в
`worker.run_words`; своей копии правила в лаборатории нет. Функции подаются гипотезы и
диагностика кусков (`result_json` → `quality.asr_diagnostics`) тех пар, откуда взяты
источники, в той роли, в которой источник участвует в сочетании. Правило (PR №76): сбойный кусок
(`error`, `empty_unknown`, у третьей — и `filtered`) второй или третьей модели исключает из
голосования трёх только свой отрезок — там сверяются две модели (`mark_alt`), на остальной
записи идёт `vote3` (`vote3_partial`); сбой куска основной модели или пустой остаток вне
отрезков — `mark_alt` по всей записи (`vote3_skipped`). У пары без сохранённой диагностики
сочетание не сводится (`no_diagnostics`); состояние куска «ok» не подставляется.
**Спорных слов** — слова с «несогласием» после сведения: они ушли бы человеку с причиной
`asr`. **Мест (оценка)** — эти слова, сведённые в места правилом `words.review_items`
(согласных слов между спорными не больше одного), но без деления на реплики и без других
причин; поэтому оценка может расходиться с числом мест конвейера (обе цифры есть в «Сверке»).

Какие сочетания сводятся и почему:

- Гипотезы разных конфигураций одной единицы сочетаются, если у пар одинаковы разделение
  говорящих (`diarization_sha256`) и слова основной модели: тогда одинаковы и куски
  основной и второй моделей (они режутся по разделению говорящих), а текст третьей модели
  в режиме `all` от второй не зависит — берутся его куски по порядку, как в конвейере.
  Иначе — «не сводится» (`diarization_differs`, `primary_differs`).
- Третья модель в режиме `doubt` (`f-whisper-doubt`) сводится только со своей второй
  моделью (теми же словами): она считала лишь куски расхождения основной со своей второй, а на
  остальных в `vote3` поданы слова основной (`vote.third_words`). С другой второй набор кусков
  был бы другим (`doubt_needs_own_second`). Если голосование в этой паре отключилось,
  `third_words` не сохранены, а нарезка непосчитанных кусков — тоже: такое сочетание не
  восстановить (`doubt_not_reconstructible`).
- Вторая модель без времён слов (текст третьей модели на месте второй) сводится `mark_alt`,
  но в конвейере невозможна: вторая обязана давать времена слов — помечено «только
  пересведением». Диагностика кусков в такое сведение не подаётся: без третьей модели
  итог от сбойных кусков не зависит, а исключить отрезки по времени у текста нельзя.
- Модель со временами слов на месте третьей (например, CTC или Multilingual второй роли)
  подаётся текстом по своим кускам через `words.third_text` — тем же правилом, что в конвейере
  (чистка только для Whisper). Это приближение: сам конвейер дал бы такой модели куски целиком,
  с нахлёстом, а не слова «своих» частей; помечено «приближённо».
- Четыре модели в одном голосовании и другое правило голосования не считаются: штатных
  функций для этого нет (РАР-4, этап 4.2).

**Сверка.** Исходный набор каждой пары пересводится нынешним правилом по её собственным
гипотезам и диагностике кусков и сравнивается с тем, что записал конвейер: функция сведения
(`vote.function`), отметки `vote3_skipped` и `vote3_partial`, счётчики `vote3`, слова третьей
модели, собранные из кусков, против `vote.third_words`, и пометка `asr` у каждого слова
стенограммы (слово ищется по началу и нормализованному тексту до словаря; поддакивания,
ушедшие во вставки, не находятся и считаются отдельно). Итоги (`revote_check.state`):

- `ok` — «совпало».
- `mismatch` — «НЕ совпало»: пересведение этой единицы недостоверно (`mismatch` — что разошлось).
- `old_rule` — «запись конвейера сделана прежним правилом сведения»: не ошибка данных, а смена
  правила. Так бывает в базе, записанной до PR №76: там у записи со сбойным куском третьей или
  второй модели стоит `vote3_skipped` и `mark_alt` по всей записи, а нынешнее правило даёт
  `vote3_partial`. Различение: если в гипотезах есть отметка `combine_rule` нынешнего правила,
  любое расхождение — `mismatch`. Без отметки (или с `whole_record`) пара признаётся записанной
  прежним правилом, только если запись в точности такая, какой её дало бы прежнее правило:
  нынешнее правило частично исключает отрезки, а записаны `mark_alt` с `vote3_skipped` той же
  причины, без итогов голосования и без `vote3_partial`, и пометки `asr` у всех слов совпали
  с `words.mark_alt` по всей записи. Иначе — `mismatch`. В такой паре отметки и итоги сведения
  в анализе — нынешним правилом, а места для разбора конвейера (разделы 1 и 5) — прежним:
  оценка нынешним — «мест спора (оценка)» в «Сверке». В `recorded` — что записал конвейер;
  `pipeline_program` — версия программы из `quality.asr_run` (для справки, в решении не
  участвует: номер версии на ветке разработки не гарантирует правила).
- `no_diagnostics` — у пары нет пригодной диагностики кусков (`detail`: нет
  `asr_diagnostics`, нет прохода, у куска нет `state` или у сбойного — `own_span`): пара не
  пересчитана и за совпадение не выдаётся; её отметки — как записал конвейер.
- `not_reconstructible` — в режиме `doubt` слова третьей модели не сохранены (конвейер не
  голосовал), а нынешнее правило голосовало бы; если не голосовало бы, итог (`mark_alt`) от
  них не зависит и считается.
- `no_hypotheses` — гипотез нет.

Закреплено тестами `tests/test_lab_analyze.py` на настоящем `worker.run_words` с
подменёнными моделями: частичное исключение отрезка, полное отключение при сбое основной
модели, пара без диагностики, кусок без `state` и синтетическая база прежнего правила (с
отметкой нынешнего правила то же расхождение — `mismatch`).

### 4. Кто был прав: решения человека

У единиц из внешних файлов решений человека нет: они перечислены в
`human.units_not_measured` («не измерено: решений человека нет…»), а если посчитаны только
такие единицы, весь раздел — `human.not_measured` с той же причиной. Ошибкой это не считается.

Решения берутся из копии базы записей (`source/state.sqlite3`) по `recording_ids` единицы:
текущая ревизия стенограммы (`recordings.source_revision`) и разбора (`review_revision`) каждого
варианта записи. Решение человека — только с автором «человек»:

- слова с `provenance.text.by = "human"` — по месту (`provenance.text.edit`); слова с
  `by = "human"` и `edited` — по месту `edited`; слова с `by = "human"` без своей метки
  текста, стоящие рядом с решением, — к нему (так `apply_review` помечает неизменённые слова
  исправленного места); прочие такие слова — подряд идущими группами (старые записи);
  слова, у которых человек менял только говорящего (`provenance.speaker` без `text`), не
  считаются;
- вид: `changed` — у места есть правка человека в журнале `edits` (`by = "human"`),
  иначе `confirmed` (подтверждено как есть); `deleted` — правка человека, удалившая все
  слова; `listened` — ответ человека после прослушивания (`listening.by = "human"`);
- правки ИИ-агента (`by = "claude"`), модели и отменённые (`reverted`) не учитываются
  (`agent_edits` — сколько их было);
- одно место, решённое в двух вариантах записи одинаково, считается один раз; по-разному —
  в сопоставление не идёт (`conflicting_between_variants`).

Слова каждого источника (и итоговые слова каждой конфигурации) выравниваются с итоговой
стенограммой варианта целиком (`difflib.SequenceMatcher`, нормализация `norm_word`, как
в конвейере); месту решения соответствуют выровненные слова (при замене равной длины — слово
к слову, иначе участок замены целиком). **Угадала** — текст места после нормализации
совпал с решением (или они — пара `SAME`). Для каждой конфигурации место:

- **показано** — у выровненных слов есть любая пометка или на место приходится место без
  слов (пропуск, неполный проход); «из них спором моделей» — пометка `asr`;
- **снято верно** — пометки нет и итог совпал с решением: человеку не пришлось бы смотреть;
- **ошибка без пометки** — пометки нет, а итог не совпал с решением.

Решений мало, и они сделаны по старым вариантам записей (другие версии моделей и
разделения говорящих): выводятся абсолютные числа с предупреждением, без процентов.

### 5. Пригодность

Пара помечается (`fitness`), если: у роли есть куски `error`; кусок пуст, а у соседней
GigaAM-модели на том же куске не меньше 5 слов, или кусок третьей модели пуст при 10+ словах
основной на его участке; у модели меньше половины слов соседа (при 20+ словах у соседа);
`make_asr` сообщил откат или ошибку; запрошено GPU/NPU, а модель считалась иначе; у третьей
модели были ошибки или откаты; запрошен faster-whisper, а третья посчитана другим движком;
ошибка второго прохода. Пороги — из правил пригодности теста скорости
([bench-database-spec.md](../docs/bench-database-spec.md), раздел 8.3) и выбраны
рассуждением. Итоги разделов 1 и 3 даны с такими парами и без них; в сравнении с базовой
без них исключается вся единица.

## Пробный запуск на отрывке

Чтобы до большого прогона проверить, что куда пишется и как всё работает, весь сценарий можно
выполнить на одном файле, которого нет в базе записей, — например, на отрывке настоящей
записи минуты на три.

**Как устроено.** Файл указывается при подготовке (`prepare --audio`, можно несколько раз) или
добавляется в готовую песочницу (`add-audio`). Лаборатория копирует его в подпапку `audio/`
песочницы под тем же именем и дальше работает только с копией; исходный файл лишь читается.
Если в `audio/` уже есть файл с тем же именем и той же контрольной суммой — он используется и
заново не копируется; с другой суммой — отказ, чужой файл не перезаписывается. Перед счётом
контрольная сумма копии сверяется с `units.json`. Копия удаляется вместе с папкой песочницы.
Проверка «песочница не пересекается с папкой аудио» к папке исходного файла не применяется
(он только источник копии), а для записей из базы действует по-прежнему.

С ключом `--only-audio` база записей не копируется вовсе: в песочнице только указанные файлы,
а из папки данных — настройки, словари и (по выбору) голосовые профили. Остальные записи при
этом не считаются; в смешанной песочнице того же добиваются ключом `run --units`.

**Группа.** Без `--group` словарь и голосовой профиль выбираются так же, как при обычной
расшифровке нового файла: словарь рядом с файлом (для копии — в `audio/`, песочнице и её
родительской папке), иначе `default_group` из `config.json`, иначе единственная группа;
групп несколько и `default_group` нет — программа откажет, как и при обычной расшифровке
(`prepare` об этом предупредит). `--group <имя>` задаёт группу явно, как `group` у
`start_transcription`. Решений человека для такой единицы нет: в анализе раздел «Кто был прав»
для неё — «не измерено».

**Команды по шагам** (`$py` — как в разделе «Как запустить»; путь к отрывку может содержать
пробелы и кириллицу):

```powershell
$s = "D:\lab\trial-1"
& $py -B lab\experiment.py prepare --sandbox $s --voice-profiles copy --only-audio --audio "D:\Отрывки\совещание 3 мин.m4a" --group <группа>
& $py -B lab\experiment.py run --sandbox $s --dry-run
& $py -B lab\experiment.py run --sandbox $s
& $py -B lab\experiment.py summary --sandbox $s
& $py -B lab\experiment.py analyze --sandbox $s
```

Начать можно и с одной дешёвой конфигурацией: `run --sandbox $s --configs c-no-third`.
Добавить отрывок в уже готовую песочницу: `add-audio --sandbox <песочница> --audio <файл>`;
команда напечатает `unit_id`, затем `run --units <unit_id>`.

**Что смотреть после запуска** (всё в папке песочницы):

| Где | Что проверить |
|---|---|
| `audio/` | копия отрывка того же размера; исходный файл не изменился |
| `units.json` | одна единица, `origin: "audio_file"`, `location` — путь копии, `duration_sec` около 180 |
| `data/` | `config.json`, `groups/<группа>/vocab.json`, при `copy` — `voices.json`; `state.sqlite3` здесь нет и быть не должно |
| `results/lab.sqlite3` | таблицы `runs`, `configs`, `unit_runs`, `pairs`; по строке `pairs` на каждую конфигурацию, `state='done'`; в `unit_runs.shared_json` — разделение говорящих |
| вывод `run` | время каждой пары и число мест для разбора; второй запуск `run` пишет «Все пары уже посчитаны» |
| `export/summary.json` | числа без текстов, имён и путей; у единицы `origin: "audio_file"` |
| `results/report.md`, `results/examples.md`, `export/analysis.json` | отчёт анализа; в разделе «Кто был прав» — «не измерено: решений человека нет» |
| `tmp/`, `cache/openvino/` | временные файлы и кэш компиляции (можно не смотреть) |

Ожидаемый размер для отрывка около 3 минут: копия звука — размер самого файла; `data/` —
килобайты (больше при скопированных профилях); `results/lab.sqlite3` — порядка 1–3 МБ на
шесть конфигураций (стенограмма, места для разбора и гипотезы каждой пары); сводка и анализ —
десятки килобайт; `cache/openvino/` — пусто или десятки мегабайт, если что-то считается
через OpenVINO. Время счёта на процессоре — порядка 5–15 минут на все шесть конфигураций,
точнее покажет `--dry-run`.

## Оценка времени

`--dry-run` показывает план и оценку по каждой паре. Оценка берётся по порядку: медиана
посчитанных пар этой песочницы; прежние времена обработки из копии базы (для моделей, которые
уже стояли в обработке); `estimate_sec_per_audio_hour` файла опыта; грубые значения по
умолчанию (помечаются «грубо»). Для набора около 1,75 ч звука и шести конфигураций грубая
оценка — 4–6 часов счёта на процессоре, из них больше половины — faster-whisper в
конфигурациях `a` и `d`; разделение говорящих считается один раз на звук. Уточнённое число
даст `--dry-run` по истории обработки.

## Что не умеет и упрощения относительно РАР-4

- Нет «границы этапов» 4.2: гипотезы получаются перехватом вызовов, а не штатной функцией
  «проход → гипотеза»; формат гипотез лаборатории свой (`lab-hyp-1`).
- Пересведение сохранённых гипотез и попарное согласие моделей делает команда `analyze`
  (раздел «Анализ»); досчёта недостающих проходов нет.
- База результатов своя (`lab.sqlite3`), не база прогонов из
  [bench-database-spec.md](../docs/bench-database-spec.md): нет стенда и окружения отдельными
  сущностями, повторов замера, полосы шума и правила «один вариант — один процесс». Все
  конфигурации одного звука считаются в одном процессе подряд, поэтому холодный старт модели
  (загрузка) у первой пары и у следующих может отличаться.
- Разделение говорящих общее только внутри одного запуска: если прогон прерван посреди звука,
  следующий запуск разделит этот звук заново (несколько минут); совпадение проверяется по
  `diarization_sha256`.
- Эмоции не считаются. Автопополнение голосовых профилей выключено. Имена участников записи
  (`names`) не передаются.
- Эталонов нет: точность слов (WER) не считается; решения человека — в копии базы.
- Названия этапов в журнале прогона — строки рабочего `worker.py`: при третьей модели
  Multilingual этап называется «третья модель: загрузка Whisper (CPU)» и «третья модель
  (Whisper, CPU)», хотя считается Multilingual. Это только надпись: что считалось на самом
  деле, видно по `timing.asr3_model`, `asr3_device` и `hypotheses.third.model`.
- Проверено на синтетических данных с подменой моделей и пробным запуском владельца на
  отрывке настоящей записи; полный прогон — отдельное решение владельца.
