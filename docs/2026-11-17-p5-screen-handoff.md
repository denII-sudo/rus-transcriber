# П5: понятный локальный экран и эксплуатация

Это пакет П5 из плана разработки (приватный репозиторий, архив:
`rus-transcriber-ops/reports/archive/2026-11/2026-11-15-architecture-development-plan.md`, §16 «П5»).
Зависимость П0 → П1 → П2 → П3 выполнена; П4 (облачный исполнитель) уже принят. Приёмка П5 — на
синтетике (17.11.2026). Старые записи экран видит только после переноса П7
([`legacy-migration.md`](legacy-migration.md)), который на каждой установке согласуется отдельно.

## Что сделано

- **Локальный экран** `workflow_page.py` + `workflow.html`: локальный HTTP-сервер на `127.0.0.1`
  с секретным адресом на каждый запуск (по образцу `review_page.py`), автозакрытие после
  `--hours` часов простоя (по умолчанию 6). Запуск: `python rt.py screen [--port 8766]` или
  `python workflow_page.py`. Порт занимается монопольно: если он занят (например, прежним
  экраном), берётся следующий свободный из 20 (PR №43). Экран позволяет без терминала:
  - выбрать файл записи в окне Windows («Выбрать файл…», `api/pick`) или ввести путь;
  - запустить обработку (`core.start_workflow`): отметка «нужен конспект» означает и согласие
    отправить текст стенограммы облачной модели (`allow_cloud_model`), плюс число уточнений;
  - видеть состояние запроса (`workflow_status`): состояние, готовность, препятствия, лимиты,
    ошибку модельного шага — без чтения логов и traceback;
  - открыть стенограмму и конспекты: текст из SQLite-снимка и явные пути к MD/JSON/manifest
    (файлы читаются без приложения);
  - добровольные сгруппированные уточнения (`workflow_questions`): экран показывает места,
    но не выбирает ответы — они остаются человеческим действием в карточках или MCP;
  - история ревизий текста и разбора (`recording_revisions`, `read_recording_revision`) с
    просмотром старой версии и «вернуть как текущую»; возврат использует совместимую
    пару ревизий текста и разбора, а не предполагает совпадение их номеров;
  - конфликты документа и конспекта, общий список всей базы с решёнными (`list_all_conflicts`,
    раздел наверху страницы, не зависит от запроса): скачать копию правки целиком
    (`conflict_copy`), сравнение с последней версией программы (`preview_conflict`), явная замена
    файла этой версией (`replace_conflict_file`) и повтор записи (`retry_conflict_file`).
    «Сохранить внешнюю правку» больше нет: правка в стенограмму не переносится, файл заменяется,
    копия остаётся в базе;
  - резерв состояния (`backup_store`): новый неактивный файл БД + отчёт проверки копии.
- **Подтверждения человека**: возврат ревизии и подтверждение проверки стенограммы привязаны
  к снимку (prepare → confirm с полным снимком, как в MCP-слое); замена файла при
  конфликте — двухшаговая: сравнение со снимком (его видел человек), затем подтверждение
  элементом страницы; без действующего снимка (конфликт решён, версия программы или файл-цель
  изменились) сервер отказывает до записи решения. Экран — доверенный локальный канал
  человека; контекст автора — `human` через `recordings.operation_context`.
- **MCP-инструменты** (`server.py`, в приёмке — версия `2026.11.17.5`): `workflow_list`,
  `recording_history`, `read_recording_revision`, `restore_recording_revision`
  (с подтверждением человека), `backup_state` (через confirm-диалог).
- **Команды** (`rt.py`): `screen`, `workflow-list`, `db-backup НОВЫЙ-ФАЙЛ`,
  `db-restore РЕЗЕРВ [--dest ПУТЬ] [--root ID=ПУТЬ]` — интерактивный мастер восстановления
  (`core.inspect_backup`, `core.restore_from_backup`): проверка резерва, новые корни
  и установка, формирование документов в новых корнях, публикация с сохранением прежней
  базы рядом; только в настоящем терминале, с подтверждением на клавиатуре.
- **Установка**: новые runtime-файлы `workflow_page.py`, `workflow.html` и документ
  включены в `install.ps1`.

## Проверки

Синтетическая приёмка `tests/test_p5_screen.py`: история ревизий с происхождением и хэш-проверкой,
просмотр старой ревизии, полный цикл возврата ревизии (новая пара 3/3 с `restored_from`,
файлы согласованы по `verify_files`), отказ при устаревшем снимке, предпросмотр конфликта
с сохранёнными байтами и отказ при несовпадении записи, создание и проверка неактивной
резервной копии, HTTP-эндпоинты экрана (страница, список, запуск с заглушкой, резерв,
ошибки без traceback). Замена файла при конфликте — `tests/test_conflict_replace.py`. Итог полного набора — см. отчёт приёмки в приватном репозитории.

## Известные ограничения

- Восстановление выполняет мастер `python rt.py db-restore РЕЗЕРВ.sqlite3 [--dest ПУТЬ]
  [--root ID=ПУТЬ]` (`core.restore_from_backup`): проверка резерва, новые корни и новая
  установка (`rebind_restored_copy`), формирование документов в новых корнях из сохранённых
  bytes, повторная проверка и публикация с сохранением прежней базы рядом. Восстановление
  «на те же пути» отклоняется по конструкции (пересечение со старыми корнями). Мастер
  интерактивный и работает только в настоящем терминале.
- Копия правки в базе — до 8 МиБ. У файла крупнее и у архивной копии прежней версии замены
  нет; пока такой конфликт открыт, программа может отклонять новые правки записи, и выхода
  из этого экран не даёт (нужна отдельная задача в хранилище).
- Замена файла необратима; копия остаётся в базе. Между проверкой файла и его заменой есть
  короткое окно (миллисекунды): сохранённое в нём другой программой может пропасть без копии.
  Закрыть его можно только в `documents.py`, `recordings.py`, `conspect.py`.
- Сравнение построчное и не учитывает порядок строк; показано не более 200 строк по 500 знаков,
  об остальном говорит `shown_all=false`. Это не замена скачанной копии. Предпросмотр копии —
  первые 20 000 знаков.
- Итог замены сообщается по самому файлу (заменён / изменился, сохранена новая копия / не записан).
  Одно подтверждение может заново записать и другие файлы той же записи по прежнему решению
  (`also_replaces`); их итог смотрите в списке.
- Правка файла конспекта без новой версии конспекта конфликтом не становится: программа
  замечает правку, лишь когда сама записывает файл заново. Пустой список не доказывает,
  что файлы не правили.
- Окно подтверждения MCP строк различий не показывает; сравнение даёт только экран.
- В режиме `legacy_files` конфликты внешней правки не обнаруживаются и не ведутся: этот раздел для них
  ничего не показывает (если база есть, виден её список; если нет — раздел говорит об этом).
- Скачанную копию браузер кладёт в папку загрузок; программа её не удаляет. Экран — доверенный
  локальный канал: окно программы не защищает от агента, который сам нажимает кнопки страницы.
- Экран не заменяет карточки разбора: ответы на уточнения и свободный ввод выполняются
  существующими интерфейсами; экран не выбирает ответы за человека.
- Перенос старых данных (П7) и выбор SQLite на установке — отдельные согласованные действия;
  умолчание `recording_backend` по-прежнему `legacy_files`.
