# Источник 05. Шифрование в домашней сети и мобильное приложение

Отчёт поискового субагента (модель Sonnet), 22.11.2026. Приведён как получен; не перепроверен,
кроме оговорённого в [README.md](../README.md). Обращения «вы», «твой» — к заказчику поиска.

ОТЧЁТ: доступ с телефона к локальному веб-интерфейсу по Wi-Fi (на 22.11.2026)

Метки: [Д] — подтверждено первоисточником или документацией; [Ф] — по форумам, баг-трекерам и пересказам; [?] — мой вывод или не проверено, нужен пробный прогон на реальных телефонах. Прямых испытаний на устройствах я не делал.

1. Способы получить HTTPS

а) Самоподписанный сертификат. Нужно нажать «всё равно открыть» на каждом телефоне. Для камеры, микрофона и service worker браузеру нужен «безопасный контекст». Обычный http на адресе 192.168.x.x таковым не считается [Д, MDN]. С исключением по предупреждению картина плохая [Ф]:
- Chrome Android не регистрирует service worker при ошибке сертификата: «SSL certificate error occurred when fetching the script». Firefox Android в одной ветке регистрировал.
- В Chrome при невалидном сертификате установка PWA сводится к обычному ярлыку.
- iOS Safari по одним источникам даёт временно принять сертификат, по другим отвергает; WebSocket (wss) с таким сертификатом не работает.
- Поведение getUserMedia при принятом исключении я не нашёл ни в одном источнике [?].
Вывод: ненадёжно, пользователю не показывать.

б) Собственный локальный центр сертификации (ЦС), установленный на телефон.
- iOS [Д, Apple 102390]: получить файл (AirDrop, письмо или страница в Safari), затем «Профиль загружен» → «Установить» → «Настройки → Основные → Об этом устройстве → Доверие сертификатов» → включить полное доверие. Примерно 6–8 нажатий. Для AirDrop есть жалобы, что корень не появляется в списке доверия [Ф]; надёжнее скачать файл со страницы в Safari. Для iOS 17/18/26 я не нашёл различий, это [?]. Ограничение в 398 дней действует только для предустановленных корней, на пользовательские ЦС не распространяется [Д, Apple 102028].
- Android: «Настройки» → поиск «CA certificate» → «Установить всё равно» → PIN [Ф, AdGuard]. Остаётся постоянное предупреждение о возможном наблюдении за сетью. Конкретные экраны Android 14–16 я не подтвердил [?]. Chrome Android учитывает локально добавленное доверие по TCP [Д, Chromium FAQ]. Для Firefox Android нужна скрытая настройка (в 138–140 были регрессии) [Ф]. Обычные приложения с Android 7 по умолчанию пользовательским ЦС не доверяют [Ф], но для браузера Chrome это не важно.
- Ограничение через name constraints: Apple поддерживает критичные name constraints с iOS 9 [Ф, рассылка CA/B Forum]. Chromium проверяет name constraints сам [Ф, комментарий в коде]. Для Android и Conscrypt подтверждения нет [?]. Ключ ЦС надо хранить как секрет: mkcert прямо предупреждает, что rootCA-key.pem даёт полную власть над перехватом [Д].
- Плюс: работает без интернета; все функции доступны, если на телефоне действительно принят ЦС. Минус: сложная установка для неспециалиста.

в) Публичный сертификат на домен, указывающий на частный адрес.
- Сертификаты Let's Encrypt на IP-адреса доступны с 15.01.2026, живут 160 часов; подтверждение только http-01 или tls-alpn-01, DNS-01 для IP нельзя [Д]. Значит, нужен публично досягаемый адрес; к 192.168.x.x это неприменимо [?, вывод].
- Остаётся схема «свой купленный домен + A-запись на 192.168.x.x + DNS-01 + Let's Encrypt (90 дней)» [?, общеизвестная схема]. Нужны домен, интернет при выпуске и продлении, API DNS-провайдера. Имя попадает в публичные журналы Certificate Transparency [Д, Tailscale]. Многие роутеры блокируют такие ответы DNS как «DNS rebinding» [Ф, Plex].
- Plex делает так же с 2015 года: DigiCert-сертификат на *.HASH.plex.direct, ключ выдаётся серверу; клиенты обязаны связываться с plex.tv [Д, Filippo Valsorda]. Для нас это значит строить собственный сервис. Без интернета не работает, если телефон не может разрешить имя.
- Плюс: на телефоне ничего не ставится, всё работает полноценно. Минус: внешние сервисы и платёж за домен.

г) Tailscale: serve с сертификатом Let's Encrypt, нужны MagicDNS, учётная запись и координатор Tailscale; имя машины попадает в Certificate Transparency [Д по поиску; страница kb не загрузилась напрямую]. Headscale (свой координатор): поддержка tailscale serve с HTTPS по состоянию на заявку #1921 отсутствует, актуальный статус не проверен [Ф]. Без интернета и внешних сервисов не подходит; через частную сеть можно ходить и из-за дома, но это отдельная цель.

2. Что работает (по первоисточникам)
Service worker и getUserMedia требуют безопасного контекста [Д]. Достоверно полноценно — только в вариантах б) и в) (доверенный сертификат). Воспроизведение аудио с Range — это поведение сервера и браузера, к сертификату не привязано, но на ненадёжном соединении Safari и Chrome ведут себя нестабильно [?]. Установка PWA: Safari — «На экран Домой» (без service worker допустимо) [?]; Chrome Android — установка требует безопасного источника [Ф]. Микрофон в iOS 26.x имеет открытые баги WebKit (311451, 319706): разрешение дано, но звука нет [Д, баг-трекер].

3. Как делают другие
- Home Assistant: с версии 2025.11 приложение требует выбрать уровень безопасности для http и рекомендует HTTPS с валидными сертификатами [Д]; пользователи с самоподписанными и своими ЦС сообщают о проблемах [Ф]. Удалённый доступ — платный внешний сервис Nabu Casa.
- Jellyfin: на форуме говорят, что клиенты не годятся для самоподписанных сертификатов; советуют публичный [Ф].
- Immich: переключатель «разрешить самоподписанные» частично не работает (Flutter, загрузки) [Ф].
- Nextcloud: отдельные приложения принимают самоподписанный, другие нет; на Android 13+ жалобы на cert4android [Ф].
- LocalSend: в браузерном режиме использует обычный http, потому что браузеры отвергают самоподписанные [Д, протокол]; в приложениях — отпечаток сертификата SHA-256.
- KDE Connect: самоподписанные сертификаты и закрепление при первом сопряжении (TOFU) [Ф, рассылка 2016] — ровно та модель, что нужна нативной оболочке.
- Syncthing: не проверял.

4. Нативная оболочка
- iOS: WKWebView позволяет принять самоподписанный сертификат в делегате вызовов (проверять надо отпечаток из QR-кода) [Ф, форум Apple]. Ограничения: WebSocket этим не покрывается (слова Apple DTS) [Ф]; есть сообщение о поломке на iOS 26.4 для локального сервера внутри приложения [Ф]. Безопасный ли контекст у такой страницы для микрофона и service worker — [?], проверять прототипом.
- App Transport Security к IP-адресам не применяется [Ф, цитата из документации Apple]; но нужны NSLocalNetworkUsageDescription и согласие пользователя на доступ к локальной сети [Д по форуму].
- Android: Capacitor на Android разрешает переопределить onReceivedSslError [Ф, форум Ionic]; сверка отпечатка делается в нескольких строках. Этот приём запрещён в Google Play, но для установки APK вручную не страшен [?].
- Цена iOS: бесплатный Apple ID — профиль на 7 дней, до 3 устройств; платная программа $99/год — год подписи, TestFlight (сборка живёт 90 дней) [Ф, Expo/Apple]. Нужен Mac с Xcode (для Tauri подтверждено; для Capacitor и Flutter из общих знаний [?]); можно использовать облачные Mac-раннеры.
- Android: Google (блог 19.03.2026) вводит проверку разработчиков; бесплатные «ограниченные аккаунты» для личного круга до 20 устройств без удостоверения и платы; расширенный режим установки с ожиданием 1 день и биометрией; доступность обещана «в августе» до введения требований в сентябре 2026 [Д]. Выполнено ли это — не проверено; F-Droid в письме от 24.02.2026 сомневался [Ф]. Перед выбором проверить.
- Обернуть готовый интерфейс без переписывания можно (Capacitor или WebView), но доверие по отпечатку — отдельный нативный код.

5. Итог (от простого к надёжному)
1) Сразу, без установок: только чтение и аудио по http в локальной сети; для голоса — запасной путь через выбор файла с записью (input type=file accept=audio) [?, проверить на iOS]. Минус: микрофон и PWA недоступны, трафик открыт для всех в Wi-Fi.
2) Рекомендую: собственный ЦС с name constraints, мастер установки в программе (страница со скачиванием профиля, QR-код, инструкции с картинками для iOS и Android), Chrome на Android и Safari на iPhone, Firefox Android не обещать. Минусы: 6–8 шагов, постоянное предупреждение на Android, ответственность за ключ ЦС (после выпуска сертификата сервера ключ ЦС лучше не хранить).
3) Долгосрочно: тонкая оболочка (Android APK через ограниченный аккаунт, iOS — по необходимости $99 и Mac), доверие по отпечатку из QR. Минусы: деньги, обслуживание, неподтверждённый безопасный контекст в WebView.
Вариант «домен + DNS-01» — только для продвинутых по желанию.

Что сделать сразу, чтобы не переделывать: поднимать только HTTPS; сертификат сервера выдавать от отдельного ЦС; в SAN — стабильное имя и IP (на роутере закрепить адрес); сопряжение — QR с адресом, одноразовым кодом и SHA-256 отпечатком (пригодится и мастеру, и будущей оболочке); интерфейс не должен зависеть от service worker; запись голоса через MediaRecorder с резервной загрузкой файла; Range для аудио; процедура смены сертификата и отзыва телефона.
