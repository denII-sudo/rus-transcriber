# Исследование замены третьей модели: faster-whisper и whisper.cpp

Исследование начато 14.11.2026 и дополнено замерами 14–15.11.2026.
**Актуальное резюме:** проект поддерживает ONNX Whisper и faster-whisper
(CTranslate2); faster-whisper — необязательная альтернатива, а выбор движка
записывается настройкой машины после теста скорости. Сбой faster-whisper
возвращает обработку к ONNX. Это не означает, что faster-whisper является
общим умолчанием или что один тест доказывает его качество для всех записей.
Подробности поведения см. в текущих `README.md`, `backends.py`, `bench.py`
и `worker.py`.

Исходный план для AMD-машины сохранён в архиве:
`research/archive/amd-optimization-plan-2026-11.md`. Дальнейшие разделы —
хронология исследования и ограниченные замеры, а не актуальные инструкции
по настройке или установке.

Версии и воспроизводимость: для замера faster-whisper 14.11 указаны
`faster-whisper 1.2.1`, `ctranslate2 4.9.0`, `onnxruntime-openvino 1.24.1`;
для whisper.cpp — nightly `b5454`. Сборки проекта менялись в ходе исследования:
интеграция CT2 — коммит `e6eb4e1`, исправление метрики bench — `89ea97e`,
описание двухминутного прогона — `ca74ea5`. Версии `onnx-asr`, остальных
пакетов и точные ревизии весов для всех исторических замеров в этом отчёте
не зафиксированы; текущая установка не доказывает их прежние версии.
Численные результаты относятся к указанным записям и настройкам, а не являются
гарантией точности или скорости на другом оборудовании.

## Контекст первоначального исследования (14.11.2026)

На момент первоначального исследования третья модель использовала ONNX-путь.
Впоследствии добавлена опциональная интеграция faster-whisper; исторические
замеры ниже относятся только к указанным машинам, записям и настройкам.

## Вариант 1: faster-whisper (CTranslate2, CPU int8)

Что это: переимплементация Whisper на CTranslate2; на CPU декодер пакета
не требует CUDA — `pip install faster-whisper` достаточно (CPU-колёса есть).
Модель подтягивается с Hugging Face в формате CT2 (у turbo есть готовые
репозитории; имена проверять при установке).

- Официальный бенчмарк (i7-12700K, 8 потоков): small int8 с батчем 8 —
  51 с на 13 мин записи (~15×). На нашей машине (6 ядер, без VNNI, модель
  крупнее) ожидание консервативное: **3–6×**, то есть в 1.5–2.5 раза быстрее
  текущих 2.7×. Это оценка, не измерение.
- RAM: int8 turbo ~1.5–2 ГБ — укладывается в 16 ГБ при `max_heavy_jobs: 1`.
- Интеграция: новый класс-обёртка в `backends.py` по образцу существующих
  (интерфейс `transcribe_texts(pieces, progress=...)`, на вход — float32
  16 кГц куски ≤28 с; у faster-whisper `transcribe` принимает numpy-массив),
  подключение в `worker.py` третьей моделью и в `bench.py` как вариант
  `whisper-ct2`. Правки умеренные, всё в Python.
- Новые зависимости: `faster-whisper` (тянет `ctranslate2`, `tokenizers`,
  `av`). Не конфликтуют с `onnxruntime`-пакетами. Нужна запись в
  `install.ps1`/requirements — как договоримся.
- Риски: int8 без VNNI может дать меньший выигрыш, чем ожидаешь; возможны
  отличия в разбиении текста (нужно сверить эталоном — обязательное условие
  плана). На Windows CTranslate2 CPU-инференс стабилен (основной сценарий
  библиотеки).

## Вариант 2: whisper.cpp с Vulkan (Radeon)

Что это: C/C++ реализация Whisper, кросс-вендорный Vulkan-бэкенд — единственный
реалистичный путь задействовать встроенную Radeon для Whisper (см. выше,
OpenVINO/DirectML не работают). Модели в ggml-формате есть, включая
large-v3-turbo.

- Качество на Vulkan/Amd: исторически встречались расхождения fp16-пути на
  разных GPU; наш опыт с DirectML fp16 (текст ломался) показывает, что проверка
  эталоном обязательна и может закончиться отрицательно.
- Интеграция заметно тяжелее, чем у faster-whisper:
  - сборка нативного exe: CMake + MSVC Build Tools + Vulkan SDK
    (`-DGGML_VULKAN=1`), либо готовый exe с релизов;
  - либо Python-биндинги (`pywhispercpp` и т.п. — сторонние, меньше поддержки);
  - exe нужно поставлять установщиком (новый runtime-файл в `install.ps1`);
  - модель ggml (~1.6–3 ГБ) — новый артефакт для скачивания.
- Ожидание по скорости: на RDNA2 iGPU для turbo неопределённое; энкодер
  получит выгоду GPU, декодер остаётся узким местом. Может оказаться и
  медленнее CPU int8 — только измерение покажет.

## Оценка и порядок действий

1. **faster-whisper — приоритет для проверки**: интеграция проще, возможен
   выигрыш скорости; сохранность качества необходимо проверять, она не гарантирована.
2. **whisper.cpp + Vulkan — запасной вариант**: брать только если
   faster-whisper не даст нужного выигрыша; выше интеграционная цена и риск
   неверного текста.

## Что не проверено (требует согласия)

- Реальные замеры: установка `faster-whisper` в окружение установленной копии
  (установка зависимостей — по отдельному разрешению), скачивание CT2-модели
  (~1.5 ГБ), прогон на том же аудио с сверкой эталона.
- Скорость whisper.cpp на Vulkan на этой машине (нужна сборка; не начиналась).
- Интеграционные правки `backends.py`/`worker.py`/`bench.py` — отдельная
  задача после выбора варианта.

## whisper.cpp (замер 15.11, по согласию)

Проверен CPU-путь на готовых бинарниках (nightly b5454, AVX2, без установки
тулчейна): `whisper-cli -t 6`, аудио те же 180 с, `ggml-large-v3-turbo`:

- f16-модель (1.51 ГБ): **1.28×**;
- Q5_0-квант (574 МБ): **1.72×**, качество на уровне остальных (сходство с
  faster-whisper 0.546 — тот же разброс, что fw-vs-onnx 0.54; даже часть слов
  точнее, например «издевательство» вместо «изгибательство» у f16).

Итог: whisper.cpp на CPU **в 2–3 раза медленнее faster-whisper** (3.53×) и
медленнее даже текущего onnx-whisper (2.86×). Vulkan-путь: готового бинарника
для Windows нет, нужна установка VS Build Tools + CMake + Vulkan SDK; в ggml
int8-оптимизации Vulkan сейчас только для RDNA3/RDNA4, наша RDNA2 iGPU идёт
по общему f16/f32-пути — ожидаемый выигрыш не окупает стоимость установки.
**Решение: whisper.cpp отклонён; единственный кандидат на замену третьей
модели — faster-whisper** (см. замер выше).

Файлы эксперимента: `Temp\opencode\whisper-cpp` (бинарник, две модели 2.1 ГБ,
wav, выводы) — удалить по разрешению.

## Замер faster-whisper (14.11.2026, по согласию)

Установка: `faster-whisper` 1.2.1, `ctranslate2` 4.9.0 (CPU), модель
`mobiuslabsgmbh/faster-whisper-large-v3-turbo` (алиас `large-v3-turbo`;
позже HF переименовал репозиторий в `dropbox-dash/faster-whisper-large-v3-turbo`,
redirect сохраняется) int8 (кэш HF в `hf-cache` установленной
копии). Замечание 15.11: в прежней редакции здесь стояло
`Systran/faster-whisper-large-v3-turbo` — такого репозитория нет, HF отвечает
анонимному запросу 401. **Важно:** faster-whisper тянет обычный `onnxruntime` — пакет
взаимно исключаем с `onnxruntime-openvino`; onnxruntime ему нужен только для
встроенного VAD, поэтому ставится корректно с `--no-deps` + ручные
ctranslate2/tokenizers/av, после чего `onnxruntime-openvino==1.24.1`
восстанавливается. Методика: те же куски ≤28 с (`split_at_pauses`), прогрев,
6 потоков CPU, beam=1; эталон — GigaAM RNN-T CPU b1 на тех же кусках.

Результаты (аудио 180 с):

| Вариант | rtfx | Загрузка | На 10 мин записи | Замечания |
|---|---|---|---|---|
| faster-whisper int8, beam=1 | **3.53×** | 4 с | ~174 с | слов 283 |
| onnx whisper int8 (на момент замера) | 2.86× | ~92 с | ~234 с | слов 343, **галлюцинация: «бабушка» ×142** |
| faster-whisper int8, beam=5 | 2.84× | — | — | качество как у beam=1 — beam=1 предпочтителен |

Качество: у faster-whisper цикла-галлюцинации нет, хвост текста почти дословно
совпадает с эталоном GigaAM; у onnx-whisper на этом аудио развивался
цикл (в bench это проявлялось и 06.11 — «извините» ×N в `bench_texts.json`).
Итог: **faster-whisper быстрее (~20–25% с учётом загрузки) и надёжнее** —
кандидат на замену третьей модели. whisper.cpp/Vulkan не проверялся — после
такого замера и низкой интеграционной цены faster-whisper стал очевидным
приоритетом.

**Статус на 14.11.2026 (устарел):** полная интеграция тогда ещё не была
выполнена. Она добавлена 15.11; см. следующий раздел. Эти строки оставлены
только как хронология исследования, не как список незавершённых работ.

## Интеграция и bench-выбор (15.11.2026, по согласию)

Интеграция выполнена: класс `WhisperCT2` в `backends.py` (int8, beam=1, CPU,
диагностика в формате `_observed_recognize`), ключ `asr_third_backend` в
`worker.py` (пусто — старое поведение; `whisper-ct2` — faster-whisper первой
попыткой с откатом на onnx-cpu), вариант `whisper-ct2` в `bench.py`,
установка `faster-whisper==1.2.1 --no-deps` + `ctranslate2==4.9.0
tokenizers av` в `install.ps1` (без обычного `onnxruntime`). Запись в конфиг
сделана доступной и при прогоне только Whisper-вариантов (раньше требовался
победитель основного прохода); `asr_allow_npu` при таком прогоне не пишется.

Bench `--only whisper-cpu,whisper-ct2` (180 с, та же запись): onnx 2.7–2.8×,
faster-whisper 4.3–4.4× (2.5 мин на 10 мин записи после кэширования модели,
первый прогон включал скачивание ~1.6 ГБ — 4.9 мин). Но bench выбрал onnx:
«совпадение 54%» — это артефакт эталона. Внутри семейства Whisper bench
сравнивает текст с первым CPU-кандидатом (onnx), поэтому расхождение движков
считает плохим качеством faster-whisper. Против независимого эталона GigaAM
картина обратная:

| Сравнение | Совпадение |
|---|---|
| faster-whisper vs onnx (метрика bench) | 54.0% |
| onnx vs эталон GigaAM | 44.9% |
| faster-whisper vs эталон GigaAM | **74.1%** |

Текст onnx на 50% длиннее оригинала (2464 против 1642 символов) — раздув от
циклов-повторов. Итог: **выбор движка по метрике bench внутри семейства
недостоверен при разных движках**; ограничение зафиксировано, переработку
метрики (сравнение с эталоном основной модели) можно сделать отдельно.
По независимым данным качество выше у faster-whisper — записано вручную:
`asr_third_backend: "whisper-ct2"` (конфиг этой машины; остальное —
умолчания: CPU, int8). Ограничение bench отражено и в
`research/archive/amd-optimization-plan-2026-11.md`.

Не проверено на тот момент: поведение воркера при сбое faster-whisper (откат на
onnx). Случай пустой строки `asr_third_backend` проверен 15.11 в полном прогоне
воркера (см. раздел «Полный прогон воркера на 2-минутном фрагменте»).
Контрольный полный прогон выполнен 15.11 — итоги в
`research/archive/amd-optimization-plan-2026-11.md`
(12:34 на 18.4 мин, Whisper-этап 6.7 мин против 8 мин у onnx, пик ОЗУ
снизился с 5.7 до 2.4 ГБ).

### Исправление метрики bench (15.11.2026)

Метрика внутри семейства заменена: Whisper сверяется с текстом основного
прохода (RNN-T, а если он измерялся — с PyTorch-эталоном), а не с первым
CPU-вариантом Whisper. Порог `bench_min_similarity` к Whisper не применяется:
у другого движка своя шкала, иначе не прошёл бы ни один исправный вариант,
а зацикленный выигрывал бы по скорости. Выбирается максимальное совпадение,
скорость — только при равенстве. Если основной проход не тестировался
(`--only whisper-*`), действует прежнее правило, а в отчёте появляется
предупреждение о недостоверности такой оценки.

Повод — измерения 15.11 на записи 06.11. У onnx-Whisper (int8) кусок в 140
слов повторяется 3 раза (≈280 лишних слов из 344): именно зацикливание,
известное по прежним прогонам. Сравнение с таким текстом занижало
faster-whisper до 54%. На фрагменте 2 мин (5:00–7:00) повторов не было,
но onnx-Whisper потерял 64 слова из 252 (совпадение с RNN-T 71.7%),
у faster-whisper — 246 слов и 83.3%. Регрессионные тесты:
`tests/test_bench_devices.py` (`FamilyRefTests`, `WhisperChoiceTests`).

Не проверено: поведение метрики на машине с видеокартой Arc — там другой
набор вариантов (Whisper OpenVINO GPU, DirectML) и другой эталон.

Контрольный прогон на новом фрагменте (600–720 с, `--no-write`) подтвердил
исправление: RNN-T 22.7×, Whisper onnx зациклился (60.1% против RNN-T,
повтор блока из 97 слов, длина текста ×1.46), faster-whisper — 88.5% без
повторов, и bench выбрал именно его. PyTorch-эталон снова не измерился из-за
ошибки сертификата при скачивании, поэтому сверка шла с RNN-T.

### Полный прогон воркера на 2-минутном фрагменте (15.11.2026)

Цель — проверить оба движка третьей модели не на текстовом стенде `bench.py`,
а в обычном пути программы: конвертация, диаризация, RNN-T, CTC, Whisper на
всей записи (`--whisper all`), слова и голосование по спорным словам.

Условия:

- фрагмент 13:00–15:00 записи 06.11 (120 с, 16 кГц моно), ранее не использовался;
- два изолированных прогона `worker.py` с разными папками данных:
  A — `asr_third_backend: "whisper-ct2"`, B — пустое значение (Whisper через
  `onnx-cpu` int8);
- песочница `%LOCALAPPDATA%\Temp\opencode\rt-full-20261115-170022`: логи,
  `status.json`, `*.transcript.json` и скрипты анализа. Настоящая папка данных
  не использовалась, `config.json` этой машины прогоны не меняли.

| Показатель | A (faster-whisper) | B (Whisper onnx) |
|---|---|---|
| Код возврата | 0 | 0 |
| Время прогона | ~1 мин 48 с | ~1 мин 48 с |
| Сегментов / спикеров | 15 / 2 | 15 / 2 |
| Слов в итоговом тексте | 231 | 230 |
| Повторы (лишние 5-словные) | 0 | 0 |
| Совпадение итоговых текстов | 99.8% | — |
| Этап Whisper | 40 с, 6/6 кусков | 45 с, 6/6 кусков |
| Откаты третьей модели | нет | нет |
| Слов в собственном тексте Whisper | 221 | 169 |
| Очищено повторов (`removed_words`) | 0 | 0 |
| Замен слов голосованием | 0 | 1 |

Выводы:

1. В реальном воркере зацикливания не обнаружено ни у одного движка на этом
   фрагменте. Куски до 20 с (в bench до 28 с) и защита
   `clean_whisper` с `asr_third_max_repeat` (по умолчанию 3), покрытая тестом
   в `tests/test_core.py`, снижают риск; третья модель не переписывает текст, а участвует
   в голосовании только по спорным словам.
2. Собственный текст onnx-Whisper на этом фрагменте короче на 24% (169 слов
   против 221); само по себе число слов не доказывает пропуски речи. Итоговые
   тексты почти совпали, но это не доказывает равного качества третьих голосов.
3. Пустое значение `asr_third_backend` проверено в реальном прогоне: ошибок
   и откатов нет, третий проход идёт через `onnx-cpu` int8. Ранее этот случай
   был в списке непроверенных.
4. Эмоции отключились в обоих прогонах: скачивание `emo.ckpt` падает на
   проверке сертификата — та же ошибка, что у PyTorch-эталона в bench. Это
   ограничение окружения, а не следствие выбора движка.

Изменения кода по итогам этого прогона не требуются. Полный путь запускается
существующим CLI (`worker.py --whisper all`), а диагностика уже пишет по кускам
`raw_words`, `cleaned_words`, `removed_words` — по этим числам видно
зацикливание. Возможное необязательное улучшение — показывать те же числа
в отчёте `bench.py`, чтобы цикл был виден прямо в таблице; на выбор модели это
не влияет, поэтому не делалось.

Не проверено: один фрагмент и один прогон на вариант (разница в пределах
10–15% может быть шумом); эмоции и PyTorch-эталон недоступны из-за сертификата;
текст самой третьей модели в диагностику не сохраняется (только счётчики слов),
поэтому оценить её дословно можно лишь через `bench.py`.

## Сравнение рисков и выбор (обзор 15.11.2026)

Оба пути используют Whisper large-v3-turbo, но разные реализации и форматы.
Третий проход — дополнительная гипотеза для голосования, а не независимый
эталон. Совпадение с RNN-T или прежней стенограммой не равно точности по аудио.
Если качество близко, сначала проверяют тихую речь, паузы, пропуски и повторы;
затем учитывают время, память и устойчивость на конкретном компьютере.
На проверенных материалах faster-whisper — разумный предпочтительный вариант,
onnx-cpu остаётся резервом; это не универсальная гарантия для всех записей.

- Whisper может выдумывать и повторять текст на тишине: пример 2026 года —
  [обсуждение OpenAI #2856](https://github.com/openai/whisper/discussions/2856).
  Фильтрация уменьшает последствия, но не гарантирует устранения всех ошибок.
- В [faster-whisper #1179](https://github.com/SYSTRAN/faster-whisper/issues/1179)
  описаны пропуски в пакетном режиме; обсуждение старое, закрыто в 2026 году,
  доказательство универсального исправления не установлено. Проект вызывает
