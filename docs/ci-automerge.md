# Автослияние PR (`automerge.yml`)

Для разработчиков репозитория; установщик этот файл не копирует.

- Защита `main` требует успешную проверку `tests` (Windows) и актуальность ветки PR, а также
  одобрение владельца кода (`.github/CODEOWNERS`) для PR, которые меняют закреплённые за ним файлы
  (`*.py`, `*.ps1`, `.github/`, `AGENTS.md` и др.; `README.md` и `docs/` не закреплены). Общего
  числа обязательных одобрений нет. На деле (по PR №36 и №41–№45): PR другого участника с такими
  файлами ждёт одобрения владельца; PR, созданный от имени самого владельца (в том числе его
  агентами), и PR только с документами сливаются после успешных `tests` без ревью. Что автор —
  единственный владелец кода и потому одобрение не требуется, установлено по поведению GitHub, а не
  по его документации.
- После успешных Tests на PR `automerge.yml` включает слияние squash. Черновики не трогает.
  Задание следит за поставленным в очередь PR до 60 минут (`WATCH_MINUTES`, всего не дольше 120).
- Если PR отстал от `main`, автослияние вызывает `gh pr update-branch`. Коммит обновления делает
  `github-actions[bot]`, и Tests на нём ждёт одобрения запуска. Для веток этого репозитория
  автослияние само одобряет этот запуск через API и включает слияние: PR сольётся только после
  успешных `tests` на обновлённом коммите. PR из форков одобряет владелец.
- Одобренный так запуск по завершении не вызывает автослияние снова, поэтому задание само
  дожидается его; если `main` за это время ушёл вперёд, обновление и одобрение повторяются (до 5 раз).
- Ветку PR из форка автослияние тоже обновляет, но если в `main` менялись файлы `.github/workflows`,
  GitHub не даёт токену Actions это сделать: автослияние один раз пишет в PR комментарий с просьбой
  к автору влить свежий `main` и продолжает работу с другими PR.
- Если одобрить не удалось, в журнале задания будет «approve it in the Actions tab»: одобрите
  запуск во вкладке Actions или отправьте в ветку PR новый коммит.
- Запуск Tests через `workflow_dispatch` не засчитывается GitHub как проверка PR, поэтому не
  используется.
