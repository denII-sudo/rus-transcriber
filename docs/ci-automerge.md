# Автослияние PR (`automerge.yml`)

Для разработчиков репозитория; установщик этот файл не копирует.

- Защита `main` требует успешную проверку `tests` (Windows) и актуальность ветки PR, а также
  одобрение владельца кода (`.github/CODEOWNERS`) для PR, которые меняют закреплённые за ним файлы
  (`*.py`, `*.ps1`, `.github/`, `AGENTS.md` и др.; `README.md` и `docs/` не закреплены). Общего
  числа обязательных одобрений нет. На деле (по PR №36 и №41–№45): PR другого участника с такими
  файлами ждёт одобрения владельца; PR, созданный от имени самого владельца (в том числе его
  агентами), и PR только с документами сливаются после успешных `tests` без ревью. Что автор —
  единственный владелец кода и потому одобрение не требуется, установлено по поведению GitHub, а не
  по его документации.
- После успешных Tests на PR `automerge.yml` включает слияние squash. Черновики не трогает.
- Снятие черновика Tests не повторяет: `automerge.yml` запускается по этому событию сам и берёт
  результат Tests того же коммита. Проверка ещё идёт — PR встанет в очередь по её завершении;
  упала или её нет — перезапустите Tests или отправьте исправление. У этого задания есть права
  записи и для PR из форков, поэтому код PR оно не скачивает и не запускает.
- Полный набор идёт один раз на коммит PR. Новый коммит отменяет идущую проверку предыдущего.
- Контроль `main` — полный набор последовательно, одним процессом: он ловит скрытую зависимость между модулями, которую параллельный прогон PR не видит. Он идёт раз в сутки по расписанию (01:41 UTC), вручную (Actions → Tests → Run workflow, ветка `main`) и после слияния, выполненного от имени человека. `automerge.yml` сам вызывает `gh pr merge --auto` токеном Actions для каждого нечернового PR с зелёными Tests, даже если автослияние уже включил человек; тогда PR может слить `github-actions[bot]`, а такое слияние прогона на `main` не запускает: события от токена Actions не запускают workflows. Поэтому на прогон после слияния не рассчитывайте.
- Если PR меняет только `docs/**/*.md` и `README.md`, из тестов идёт только `test_text_hygiene`
  (остальные от этих файлов не зависят); самопроверка без тестов и проверка запрещённых слов
  остаются. Новый тест, который читает документы, добавьте в этот шаг `tests.yml`.
- Проверка запрещённых слов (последний шаг Tests, секрет `RUS_FORBIDDEN_WORDS`) в PR идёт скриптом `tools/check_repo.py`
  из базового коммита (`HEAD^1` merge-коммита) поверх файлов PR (`--root .`): автор PR не может подменить сам скрипт.
  Если базовый скрипт прочитать не удалось, шаг падает, а не пропускается. Защита частичная: для события
  `pull_request` GitHub берёт и `tests.yml` из самого PR, поэтому правкой этого файла секрет можно вывести; такие
  правки закрывает ревью код-владельца (`.github/` в `CODEOWNERS`), но CI на PR идёт до ревью. Поэтому писать в ветки
  репозитория могут только владелец и его агенты, а запуск Tests у новых участников ждёт одобрения. На `main` (push,
  расписание, вручную) шаг запускает скрипт из дерева, как раньше. PR из форков секрет не получают: шаг пропускается.
- `automerge.yml` работает по одному заданию на PR за раз (`concurrency` по номеру PR, `cancel-in-progress: false`):
  идущее задание не обрывается, потому что оно может стоять между обновлением ветки и одобрением запуска Tests. Следующее
  ждёт; ожидающее задание, которое успело стать устаревшим, заменяется новым. У PR из форков номера в событии нет —
  для них очереди нет, как раньше.
- Пакеты для Tests берутся из кэша с ключом по хэшу `tests.yml`. Кэш, видимый всем PR, создаёт запуск на `main`: при изменении `tests.yml` и по расписанию раз в сутки.
  Задание следит за поставленным в очередь PR до 60 минут (`WATCH_MINUTES`, всего не дольше 120).
- Если PR отстал от `main`, автослияние вызывает `gh pr update-branch`. Коммит обновления делает
  `github-actions[bot]`, и Tests на нём ждёт одобрения запуска. Для веток этого репозитория
  автослияние само одобряет этот запуск через API и включает слияние: PR сольётся только после
  успешных `tests` на обновлённом коммите. PR из форков одобряет владелец.
- Одобренный так запуск по завершении не вызывает автослияние снова, поэтому задание само
  дожидается его; если `main` за это время ушёл вперёд, обновление и одобрение повторяются (до 5 раз).
- Ветку PR из форка автослияние тоже обновляет, но если в `main` менялись файлы `.github/workflows`,
  GitHub не даёт токену Actions это сделать: автослияние один раз пишет в PR комментарий с просьбой
  к автору влить свежий `main` и продолжает работу с другими PR.
- Если одобрить не удалось, в журнале задания будет «approve it in the Actions tab»: одобрите
  запуск во вкладке Actions или отправьте в ветку PR новый коммит.
- Запуск Tests через `workflow_dispatch` не засчитывается GitHub как проверка PR, поэтому для PR не используется; на `main` это ручной контроль.
- Ветку слитого PR GitHub сам не удаляет, если PR слил бот Actions (так сливает `automerge.yml`).
  Такие ветки убирает `cleanup-branches.yml` дважды в сутки (06:17 и 18:17 UTC): только ветки слитых
  PR этого репозитория, если ветка указывает ровно на слитый коммит и открытого PR с ней нет; ветки
  форков и ветки с новыми коммитами не трогает. Вручную: `gh workflow run cleanup-branches.yml`
  (по умолчанию только показывает, что удалил бы; удалить — `-f dry_run=false`).
