# План №1 оптимизации rus-transcriber на платформе AMD

Дата: 2026-11-14. Статус: **план, прогоны не выполнялись** (тяжёлые операции — только
по отдельному разрешению человека, см. `AGENTS.md`). Дополнение к разделу
«Эта копия: форк; поведение по платформам» в `AGENTS.md` (AMD-пункт).

## Целевая машина

- AMD Ryzen 5 6600H (Zen 3+, 6 ядер / 12 потоков, AVX2, без AVX-512 и VNNI);
- встроенная графика AMD Radeon (RDNA2), драйвер 32.0.21045.16010;
- 16 ГБ ОЗУ, Windows 11 Pro, мини-ПК UM660;
- рабочее окружение программы — установленная копия `%LOCALAPPDATA%\rus-transcriber`,
  в копии репозитория `.venv` нет.

## Выводы анализа (2026-11-14)

1. OpenVINO GPU и NPU — плагины Intel: варианты bench `ov-gpu*`, `ov-npu*`,
   `whisper-gpu` здесь всегда «не работает» и пайплайн откатывается на CPU.
   Это ожидаемое поведение, не баг и не повод править `backends.py`.
2. Основной путь (OpenVINO EP на CPU) полностью рабочий: OpenVINO оптимизирует
   AMD-процессоры по AVX2. Отсутствие VNNI ограничивает скорость int8.
3. `install.ps1` сносит `onnxruntime-directml` (взаимозаменяемые пакеты: модуль
   `onnxruntime` может стоять только один), поэтому бэкенд `dml` в установленной
   копии недоступен — а на AMD это единственный путь задействовать встроенную
   Radeon.
4. Whisper large-v3-turbo остаётся на CPU int8 (тяжело для 6 ядер); вариант
   `whisper-dml` в `bench.py` не добавлен, но технически возможен.
5. 16 ГБ ОЗУ: `max_heavy_jobs: 2` + Whisper int8 + pyannote — впритык; две
   параллельные задачи рискуют свопом.

## Варианты оптимизации

### А. Только настройки `config.json` (код не меняется)

- `max_heavy_jobs: 1`;
- прогон `bench.py --only torch-cpu,onnx-cpu,onnx-cpu-b8,onnx-cpu-b16,whisper-cpu` —
  тест сам выберет `asr_batch` (8 на 6 ядрах реалистичнее 16 из-за RAM);
- `torch_threads: 6` (физические ядра) для pyannote;
- `diar_embeddings: auto` (OpenVINO CPU) — оставить как есть.

### Б. Замена пакета ONNX Runtime (по согласию; меняет окружение установленной копии)

- поставить `onnxruntime-directml` вместо `onnxruntime-openvino`;
- прогнать bench с `dml-gpu`, сравнить с `onnx-cpu`;
- вернуть пакет по результату измерения. Риск: потеря OpenVINO EP, который на CPU
  обычно быстрее голого CPU EP — решение только по измерению.

### В. Доработка форка (отдельная задача, не сейчас)

- bench-вариант `whisper-dml` (DirectML для Whisper): маленький патч `bench.py`,
  защита в `backends.py` уже есть;
- исследование `faster-whisper` (CTranslate2 int8 CPU) или whisper.cpp с Vulkan
  (задействует Radeon) — замена третьей модели, с обязательной проверкой эталоном.

### Г. Вне кода

- план питания Windows «Максимальная производительность», контроль троттлинга.

## Шаги проверки (требуют разрешения)

1. Дёшево и без риска: в установленной копии
   `.\.venv\Scripts\python.exe -c "import backends as b; print(b.openvino_devices(), b.available_providers())"`
   — подтвердить, что OpenVINO видит только CPU.
2. Прогон bench с `--only` из пункта А (нужен `HF_TOKEN`; скачивание моделей,
   5–15 минут).
3. По отдельному согласию — эксперимент с `onnxruntime-directml` (пункт Б) и
   обратный возврат пакета.
4. Итог — запись выбора в `config.json` папки данных и краткий отчёт в этом файле.
