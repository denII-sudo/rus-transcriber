# Облачные и сетевые папки: что проверяет программа (БД-8а, БД-3а)

Правило для человека — в `README.md`, раздел «Папка данных» → «Не держите папку данных в облаке и на сетевом диске».
Здесь — как устроена проверка, для разработчиков.

## Политика

- Папка данных, папка резервов `db-backups` и новый файл резерва в облачной папке — **предупреждение, не отказ**
  (решение владельца 28.11.2026: «Предупреждать»). Работа не блокируется.
- Сетевой диск для базы и резервов по-прежнему отвергает `storage.check_local_path` (SQLite в режиме WAL работает
  только на одном компьютере); детектор лишь объясняет это заранее.
- Документы рядом с записью в облачной папке — отдельный шаг БД-8б (вопрос человеку один раз на папку, ответ
  хранится). В `documents.checked_root` проверки облака нет и не будет: иначе останавливалась бы каждая запись
  документов.

## Модуль `cloudpaths.py`

Только читает, ничего не меняет и не создаёт; файлы не открываются, заглушки «только в облаке» не скачиваются.
`classify(path)` возвращает `{"kind": "cloud" | "network" | "local" | "unknown", "client": …, "basis": …}` без
самого пути; результат кэшируется на процесс. `warning(path, what)` и `data_dir_warnings(data_dir)` дают текст
предупреждения по-русски, тоже без пути. Сбой любого признака не прерывает проверку, сбой всего детектора даёт
`unknown` без предупреждения: сервер обязан запуститься.

Признаки на Windows, от дешёвого к дорогому:

| Признак (`basis`) | Откуда | Что ловит |
|---|---|---|
| `unc`, `drive` | путь `\\сервер\ресурс`, `GetDriveTypeW` = 4 | сетевой диск |
| `tag` | `FindFirstFileW` по самому пути и каждому родителю: тег ссылки `0x9000_x01A` (Cloud Files) или флаги `RECALL_ON_DATA_ACCESS`, `RECALL_ON_OPEN`, `PINNED`, `UNPINNED` | OneDrive, новый Яндекс Диск и другие клиенты Cloud Files |
| `sync_root` | реестр `HKLM\…\Explorer\SyncRootManager\*\UserSyncRoots` | зарегистрированные корни синхронизации |
| `client_folder` | `%OneDrive%`, `%OneDriveConsumer%`, `%OneDriveCommercial%`; `HKCU\Software\Microsoft\OneDrive\Accounts\*\UserFolder`; `HKCU\Software\Yandex\Yandex.Disk(.2)\RootFolder`; `info.json` Dropbox в `<домашняя папка>\AppData\Roaming|Local\Dropbox` | папки клиентов, в том числе прежнего клиента Яндекс Диска без тега Cloud Files (находка О-8) |
| `cf_api` | `CfGetSyncRootInfoByPath` (`cldapi.dll`) для ближайшего существующего каталога — только если признаки выше ничего не нашли | корень синхронизации, не попавший в реестр |
| `name` | компонент пути начинается с имени папки клиента (OneDrive, Яндекс.Диск, Dropbox, Google Drive, Мой диск, iCloud Drive, Облако Mail.ru…) | классические клиенты; слабый признак, текст предупреждения говорит «по имени похожа» |

Классический клиент, который синхронизирует обычную папку без пометок, без записи в реестре и с другим именем,
не распознаётся — поэтому правило в README важнее детектора.

Вне Windows `classify` пока возвращает `unknown` (предупреждений нет). Ветка Linux — тип файловой системы из
`/proc/self/mountinfo` (`nfs*`, `cifs`, `smb3`, `fuse.*`), пути `gvfs`, папки клиентов из их настроек — будет
написана вместе с пилотом на Linux; интерфейс `classify` для неё уже подходит.

## Где показывается

- запуск сервера: строка в `instructions` для ИИ-агента и одна строка в stderr (журнал сервера) — без пути;
- `self_check`: раздел `storage` (`data_dir`, `warnings`) и короткая метка в `summary`; `ok` предупреждения не меняют.
  Папка данных проверяется, только если модуль `paths` уже загружен (сервер, `rt.py self-check`): `selfcheck.py`,
  запущенный отдельно (так его запускает установщик), `paths` не импортирует, чтобы не создавать каталоги в папке
  данных по умолчанию;
- `get_settings`: `data_dir_warnings`;
- локальный экран (`rt.py screen`): полоса вверху страницы;
- резерв базы (`backup_state`, `rt.py db-backup`, кнопка на экране): строка в окне подтверждения и первая строка
  `warning` в ответе.

Установщик (`install.ps1 -DataDir`) этой проверки пока не делает: это область владельца, отдельный шаг.

## Версия SQLite (БД-3а)

`self_check` показывает `storage.sqlite` (версия библиотеки, с которой работает Python программы) и
`storage.wal_reset_fixed`. Ошибка WAL-reset ([sqlite.org/wal.html](https://sqlite.org/wal.html), раздел 11) есть
в 3.7.0–3.51.2 и исправлена в 3.51.3; исправление перенесено в 3.50.7 и 3.44.6 (и последующие выпуски этих веток).
Без исправления — предупреждение, не отказ. Правило — `selfcheck.wal_reset_fixed`.

## Тесты

`tests/test_cloudpaths.py`: признаки с подменой системных вызовов (`FindFirstFileW`, `GetDriveTypeW`,
`CfGetSyncRootInfoByPath`, реестр, переменные среды, `info.json`), тексты предупреждений без пути, кэш, отказ любого
признака; положительный контроль на Windows — настоящая временная папка: «локальная», `CfGetSyncRootInfoByPath`
отвечает «не корень синхронизации». Настоящие облачные папки в тестах не проверяются.
