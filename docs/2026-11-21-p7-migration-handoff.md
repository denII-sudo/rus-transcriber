# П7: перенос старых записей в SQLite — выполнен на установке владельца

Дата: 20–21.11.2026. Компьютер владельца: Windows 11, Intel Core Ultra; программа установлена из
`main` (версия 2026.11.20.3 и последующие правки без смены версии). Документ — итог П7 для
разработчиков: что сделано, какие решения владельца отступают от плана, что проверено и что нет.
Личные пути, имена участников и названия групп здесь намеренно не указаны; подробный журнал —
в приватном служебном репозитории.

## Что сделано

Порядок соответствует `docs/legacy-migration.md`.

1. **Инвентаризация.** Найдены все результаты старого формата: 9 записей (аудио и видео),
   16 вариантов стенограмм, ответы разбора и конспекты. Тестовые записи владелец исключил;
   их файлы перенесены в отдельные папки «на удаление» с пофайловым отчётом и сверкой SHA-256,
   не удалены. Ноябрьские медиафайлы, которые программа не обрабатывала, не трогались.
2. **Резервная копия** папки данных и комплектов результатов с контрольными суммами (повторена
   перед каждым шагом с изменениями; последняя — 616 файлов, независимая сверка без расхождений).
3. **План переноса** (`plan.json`): основная версия каждой записи, дата и источник даты, кем
   подтверждены голоса группы.
4. **Старые подтверждения говорящего** (до переноса, т.к. обучение голосов по SQLite-записям не
   поддерживается): `legacy_speaker_review` собрал карточки по 32 местам трёх записей; владелец
   ответил на все и применил ответы. Затем профиль группы пересчитан по этим записям
   (`update_voice_profiles` с подтверждением человека, резервные копии профиля, карантина нет)
   и выполнен `import_legacy.py mark-voices`: фрагменты одной группы помечены «подтверждено
   человеком», другой — «автоматика программы».
5. **Проверка `check`** — 16 из 16 `ok`.
6. **Пробный перенос на копии** (отдельная папка данных из резервной копии) — 16 из 16,
   `verified_copy`; повтор — 16 `skipped`; старые файлы не изменились.
7. **Перенос на настоящих данных:** `initialize_recording_store`, затем
   `import_legacy.py apply` — 16 из 16 `imported`, `verified_copy` (`integrity_check` и
   `foreign_key_check`, `verify_files` по каждому корню, пробная резервная копия базы,
   совпадение содержания со старыми файлами). Независимая проверка только чтением: в базе
   16 записей; слова, реплики, сомнения, правки и имена совпадают со старыми файлами во всех 16;
   старые файлы результатов совпадают с резервной копией.
8. **Переключение:** `set_recording_backend sqlite` по отдельной команде владельца.

## Решения владельца, отступающие от плана П7

- Перенос пишет документы **сразу в рабочие папки** результатов (подпапка `v4`), без
  промежуточной staging-папки; страховка — резервная копия и пробный перенос на копии.
- **Ревизии в базе начинаются с 1**; прежний номер ревизии файла записан как исходная точка
  (`quality.migration.baseline`), ложных промежуточных версий нет.
- **Переносятся все варианты** стенограмм, каждый — отдельной записью с тем же аудио; основной
  вариант определён по истории обработки и помечен примечанием «вычислено по истории».
- **Даты записей:** из имени файла (с временем), где оно есть; иначе — указание владельца; для
  двух видеофайлов — из метаданных контейнера, где `creation_time` — время **окончания**
  записи: начало = окончание − 1 час (поправка по указанию владельца) − длительность. Источник
  каждого значения записан в `quality.migration.field_sources`.
- **Пометки голосов** хранятся в профиле отдельным шагом после подтверждений и переобучения.
- **Перенос старой раскладки данных при старте сервера отключён** (#25): только явной командой;
  запрет постоянный и закреплён `tests/test_no_auto_migrate.py`.
- В карточки подтверждения **не предлагаются места короче 0,8 с** (в отпечаток они не попадут),
  а **места с правкой только текста включены**.
- Устаревшие ссылки сомнений привязываются **по времени**, если место однозначно (см.
  `docs/legacy-migration.md`).
- Два вложенных друг в друга места подтверждения владелец отложил; в профиль они не вошли.

## Изменения кода в ходе П7

#23 (`legacy_speaker_review`, предупреждение о потере «человеческих» секунд), #24

занятый порт страницы карточек), #43 (занятый порт экрана П5).

## Известные ограничения и что не проверено

- Найденные при переносе недостатки исправлены (21.11.2026):
  - **свободный ответ в карточке подтверждения говорящего** («X говорит только …») раньше
    вставлялся в стенограмму как текст; теперь он применяется только как решение о говорящем
    («это Вера», «Вера: точные слова»), а пояснение уходит человеку «Проверить человеку» (#42).
    Защита действует для карточек, собранных после обновления. Испорченное место владелец
    исправил через карточку;
  - **вложенные места** в `legacy_speaker_places` объединяются в одну карточку (#42);
  - **страница карточек** при занятом порте берёт следующий, а не сообщает «открыта» (#42);
  - **запись настроек** сохраняет ключи, уже записанные в `config.json`, даже если они совпадают с
    умолчаниями (#41; перенос раскладки `save_overrides` не менялся). Значения, которые прежняя
    версия уже убрала из `config.json`, не восстанавливаются: сейчас они совпадают с умолчаниями.
- На момент итога П7 новая расшифровка и разбор на настоящих данных **после переключения на
  SQLite** ещё не выполнялись; возврат на `legacy_files` после новых правок в базе не проверялся.
  - Дополнение 22.11.2026: вечером 21.11.2026 в режиме `sqlite` одна запись (3 мин 30 с)
    расшифрована в трёх вариантах, два из них прошли через разбор карточек (версия 2026.11.21.3,
    `a18284d`). Найдены недостатки разбора и записи документов; отчёт — в приватном служебном
    репозитории. Конспект не заказывался, возврат на `legacy_files` по-прежнему не проверялся.
- Старые файлы и папки «на удаление» сохранены; их удаление — отдельное решение владельца.
- Это не оценка акустической точности распознавания.
