# П4: автономный исполнитель OpenCode / OpenAI

## Граница и передача данных

Исполнитель вызывает `opencode serve` на loopback с временной Basic Auth и
использует stateless `POST /api/experimental/generate/text` с закреплённой
моделью `openai/gpt-6-luna`. Это именно облачный OpenAI backend, не локальная
модель. OpenCode Generate API не запускает agent tools; приложению не нужен
универсальный shell-агент. Endpoint experimental в OpenCode V2; версия API
проверяется при старте, при несовместимой версии вызов прекращается.
Python-клиент обращается к loopback API напрямую, не пропуская локальный
Basic Auth и текст задания через системный HTTP proxy.

Передаются только слова, устойчивые ID, признаки сомнений, цель и ревизии
модельного задания. Не передаются аудио, исходный путь, биометрия, логи и
прочие поля полной записи. `allow_cloud_model=false` полностью запрещает
облачный вызов. С 18.11.2026 по решению владельца это значение по умолчанию:
облако включается только явным согласием — `allow_cloud_model=true` в MCP,
`rt.py workflow-start --cloud-model` или отметка «нужен конспект» на экране П5,
где заказ конспекта означает согласие (пояснение рядом с отметкой).

## Исполнение и ограничения

При заказанном конспекте worker после атомарного сохранения ASR самостоятельно
выполняет модельное задание без открытого чата. По 500 слов на запрос,
не более 10 000 слов / 20 частей на одно задание; превышение не обрезает
текст, а завершает только модельный шаг с ошибкой. Размер ответа каждого
блока также ограничен. Одна генерация ограничена timeout 300 секунд; это предел
одного HTTP-вызова, не общего времени workflow. Один невалидный ответ
получает ровно одну repair-попытку. Сохранённые блоки переживают сбой;
`workflow_execute_model(..., retry_failed=true)` продолжает только недостающие.
Автоматического повтора после rate limit, offline или неизвестного исхода нет.

Ответ разбирается локально, сверяется с контрактом П3 и проверками цитат,
записывается в SQLite только после полной проверки. Смысловая точность,
полнота вывода, авторство и человеческая проверка не предполагаются из
технически успешного ответа.

## Приёмка

Реальный синтетический worker-путь проверен: commit тестовой ASR-структуры →
OpenCode V2 → OpenAI GPT-6 Luna → валидированный конспект в SQLite и один
materialized conspect; request завершился `completed`, чат-клиент не передавал
модельный ответ. Отдельный smoke test подтвердил JSON-формат и применение
контрактного валидатора.

Проверки с подменённой сетью охватывают один repair, исчерпание repair,
rate-limit, offline, продолжение только недостающих блоков и запрет облака до
создания клиента. Предел 10 000 слов отклоняет, не обрезает превышение.

Полный изолированный набор — 560 тестов, OK, один пропуск; целевые П3/П4 —
39 тестов, OK. `tools/check_repo.py` — 0 нарушений; Python AST/UTF-8 проверен,
BOM установщика сохранён. Это синтетическая техническая приёмка, не оценка
акустического качества, смысловой точности на реальных записях или
пользовательской готовности.

### Последующая проверка timeout

- Один отдельно разрешённый sandbox workflow с текстом из записи завершился
  `offline` при исходном лимите 90 секунд. Диагностический вызов с тем же
  заданием ожидал 90,03 секунды; OpenCode API-клиент преобразовал transport
  timeout в `offline`.
- Контрольные запросы только с синтетическим текстом к тому же локальному
  Generate API и модели вернули HTTP 200, включая запрос сопоставимого размера.
  Одна повторная sandbox-попытка с временным per-request timeout 300 секунд
  завершилась за 144,66 секунды: результат прошёл локальную проверку, документ
  синхронизирован, deliverable `usable_with_limits`; человек его не проверял.
- После этого `REQUEST_TIMEOUT_SEC` в `llm_provider.py` увеличен до 300 секунд.
  Текущая проверка кода: `tests.test_p4_provider` — 11 тестов OK; полный набор —
  581 тест, один пропуск. Реальный облачный вызов повторно после изменения
  исходного файла не запускался; успешная e2e-попытка использовала то же значение,
  заданное только в sandbox-процессе.
- В workflow передаются текстовые слова/ID и цель, но не аудио и не путь к записи.
  Содержимое задания, ответа и идентификаторы записей не включены. Исход прошлых
  timeout-вызовов не позволяет установить, дошли ли они до модели.

Прогоны с реальными данными требуют отдельного разрешения; описанный выше
диагностический запуск был разрешён отдельно и не является общим разрешением.
Установка/обновление OpenCode и скачивание моделей не нужны.
