# rus-transcriber — памятка для Claude Code

Отвечай по-русски, простыми словами. Пользователь — не программист: перед действием коротко объясняй, что и зачем
делаешь; команды, которые меняют или удаляют что-то вне папки программы, — только после его «да».

## Что это
MCP-сервер для Claude Desktop: локальная расшифровка русской речи (в том числе детских разговоров) — pyannote
(кто говорит), GigaAM RNN-T/CTC и Whisper (голосование «два из трёх»), голоса по словам, голосовые профили групп,
разбор сомнительных мест человеком (карточки), конспекты с проверкой цитат.
Порядок старшинства правок: **человек > отпечаток голоса > распознавание > эвристики**.

## Где что лежит (Windows)
- Программа (она же рабочая копия, которую запускает Claude Desktop): `%LOCALAPPDATA%\rus-transcriber`,
  окружение `.venv`, кэши моделей `cache\`.
- Личные данные: `%APPDATA%\rus-transcriber-data` (или `RUS_TRANSCRIBER_DATA`): `config.json`, `groups\<группа>\`
  (`vocab.json`, `voices.json` — голосовые отпечатки, это биометрия), `jobs\`, `eval\`, `confirmations.log`.
- Настройки Claude Desktop (Store-версия): `%LOCALAPPDATA%\Claude-Data\claude_*\claude_desktop_config.json` —
  там `HF_TOKEN`. Токен никогда не выводить в ответ и не копировать в файлы.

## Устройство кода
- `core.py` — ядро без MCP (`CoreError`); `server.py` — тонкая MCP-обёртка (`INSTRUCTIONS`, `VERSION`);
  `rt.py` — то же из командной строки.
- `confirm.py` — подтверждение опасных действий человеком (окно Windows или `python rt.py approve`).
  Не обходить, не включать `confirm_mode: off` на живой машине, не нажимать за человека.
- `worker.py` — расшифровка (отдельный процесс); `backends.py` — распознавание; `voices.py` — профили;
  `words.py`, `vocab.py`, `gender.py` — слова, словарь, род глаголов.
- `transcript.py` — .json/.md стенограммы, журнал правок, `apply_review`, `apply_word_edits`, `edit_span`, `reopen`.
- `freeform.py` — свободные ответы человека в карточках (выравнивание, вставки, автоудаление, наложение речи).
- `review_pack.py`, `cards.html` — карточки разбора (локально и в облаке); `conspect.py`, `quotes.py` — конспекты.
- `paths.py` (папка данных, флаг `EXPLICIT`), `migrate.py`, `data_io.py` (выгрузка/загрузка групп), `settings.py`.
- `bench.py` — тест скорости: какое устройство лучше для RNN-T, CTC и Whisper; `diar_fast.py` — быстрые
  отпечатки голосов через OpenVINO; `jobslots.py` — не больше `max_heavy_jobs` тяжёлых задач одновременно.
- `tmpfiles.py` — временные папки (`emo_`, `bench_`, `gigaam_`, `vr_`) с очисткой; `selfcheck.py` — самопроверка.
- `tools/check_repo.py` — проверка файлов на личные данные; `tools/eval_quality.py` — WER и точность голосов.

## Настройки и устройства
- **Два слоя.** Общие умолчания — в `settings.py` (`DEFAULTS`) и уходят в Git. `config.json` в папке данных
  хранит только отличия этой машины; его заполняет тест скорости. Явный выбор (даже совпавший с умолчанием,
  например «процессор») сохраняется через `settings.update(explicit=...)` и не теряется при обновлении.
- **Чистая установка — всё на процессоре:** `asr_device`, `asr_third_device`, `diar_ov_device` = `CPU`.
  Видеокарту Arc включают вручную или через тест скорости.
- **У каждой группы своё устройство:** основной проход RNN-T (`asr_backend`/`asr_device`), второй проход
  CTC (`asr_second_backend`/`asr_second_device`/`asr_second_batch`), Whisper (`asr_third_*`), разделение
  по спикерам (`diar_ov_device`); эмоции всегда на процессоре. Пустые `asr_second_*` значат «как у основного».
- **NPU по умолчанию запрещён:** `asr_allow_npu=false`. На Meteor Lake (Core Ultra Series 1) NPU не
  поддерживает FP32 и считает GigaAM неверно, поэтому тест скорости его пропускает. Новый NPU с FP32
  тестируется и включается только при совпадении текста с эталоном.
- **Порог точности теста:** `bench_min_similarity` (по умолчанию 0.97) или ключ `--min-similarity`;
  выбранный порог сохраняется в `config.json`. Выше порог — строже к точности, можно в ущерб скорости.

## Правила (важно)
1. **Личные данные не попадают в код, тесты, документацию и коммиты**: имена участников, названия групп и
   термины из словарей, пути с именем пользователя. В тестах — только вымышленные (Анна, Борис, Вера, Глеб;
   `demo-group`). Перед коммитом: `.\.venv\Scripts\python.exe tools\check_repo.py` → `нарушений: 0`.
   Вывод `check_repo.py --list-words` не показывать в ответе — там настоящие имена.
2. **Тесты и скрипты не трогают настоящую папку данных.** Каждый модуль тестов задаёт временную
   `RUS_TRANSCRIBER_DATA` до первого импорта программы. Был инцидент: тест импортировал `server.py`, тот запустил
   миграцию и переименовал настоящую папку данных (исправлено флагом `paths.EXPLICIT`, есть тест-регрессия).
   Новые тесты делать так же; `server` в тестах импортировать только с заглушкой `migrate.run`.
3. Ничего не удалять в папке данных и в `%TEMP%` без прямого согласия человека.
4. Расшифровки и записи — речь детей: в разговор читать только то, что нужно для задачи.

## Проверка после изменений
- Тесты: `.\.venv\Scripts\python.exe -m unittest discover -s tests` (сейчас 166, около 10 с).
- Всё сразу: `.\.venv\Scripts\python.exe rt.py self-check` (тесты, check_repo, морфология) — или MCP-инструмент
  `self_check`.
- Сервер подхватывает новый код только после перезапуска Claude Desktop (полностью закрыть и открыть).
- `pip check` может закончиться с кодом 1 из-за формального замечания `gigaam 0.2.0 requires onnxruntime,
  which is not installed`: стоит `onnxruntime-openvino`, модуль `onnxruntime` (1.24.1) импортируется,
  ускорители OpenVINO и CPU на месте. Это не поломка, лечить не нужно.
- При изменении `server.py` поднимать `VERSION` (дата). Новые файлы программы — добавить в список копирования
  в `install.ps1` (шаг 4).

## Состояние и открытые задачи (на 11.11.2026)
- До этого разработка шла в облачной сессии Claude, правки выкладывались прямо в эту папку; облачная копия больше
  не ведётся — **эта папка и есть актуальный исходник**. Git настроен: публичный репозиторий
  `https://github.com/denII-sudo/rus-transcriber`, ветка `main`, первый коммит — исходник 2026.11.10.
- Перед коммитом работает хук `.git/hooks/pre-commit` (`tools/check_repo.py --staged`): личные данные в
  публичный репозиторий не попадают. В новом клоне хук ставится вручную: `copy tools\pre-commit .git\hooks\pre-commit`.
- С 11.11.2026 действует политика устройств: чистая установка — процессор, у RNN-T, CTC, Whisper и
  диаризации свои настройки, NPU Meteor Lake отключён (`asr_allow_npu=false`), тест скорости сохраняет
  выбор по каждой группе и порог точности `bench_min_similarity`.
- Задачи:
  1. Упорядочить работу с группами (сначала анализ): выбор словаря и группы (`worker.resolve_vocab`,
     `paths.pick_group`), `default_group` (сейчас оставлен как есть), профиль группы `"default"`, общий словарь
     без `group` (с 10.11 — без профилей), два места для словаря группы, как менять группу готовой расшифровки.
  2. Варианты для «пропущенной речи»: окно ±1 с на очищенном звуке (highpass ~120 Гц, шумоподавление,
     нормализация) — распознать и показать варианты в карточке; диаризацию — по исходнику. Проверять на звуке.
  3. `migrate_data` не нашёл старую папку данных после обновления (подозрение — виртуализация папок MSIX).
  4. Шифрование архивов `export_group` (в них голосовые отпечатки).
  5. `test_repo_clean` медленный (≈16 с): без git обходит всю папку вместе с `.venv`.
- Дополнительные служебные заметки с чувствительными данными (локальные пути, названия папок и проектов, ход
  работ) — в приватном репозитории `https://github.com/denII-sudo/rus-transcriber-ops` (доступ по приглашению).
  Там же `debug/` — снимок рабочей папки данных (журналы задач, настройки, профили голосов, отчёт по NPU) для

  Если доступа к нему нет — попроси человека открыть нужный документ и вставить его содержимое в переписку.
